Facts about `claude plugin test` and the 2.1.309 mod API, learned building spike 027 round 6 (2026-10-23).

- A Box's `hover` is kept beside `props` on the element as its parent's `children` lists it, not in `findAll` results: assert via the keyed parent's `children[i].hover`.
- A test's `turn.step` hook must answer the same `{ turnId, index }` it was called with, or the chain fails with "no implementation for turn.step".
- `$.clock.every` callbacks may still fire under test even with a `clock.every` stub: a poll that writes state (e.g. `$.agent.list()` refresh) shows up in pane assertions.
- No mod API sets a pane's place or order, minimises it, or adds a title-bar control (PaneOpenArgs: id, title, focus, closeOnEscape, holdToasts, rows, columns only). Esc-to-close is `closeOnEscape`; `Button role="dismiss"` is the close hint.
- `prompt.submit` `e.origin.kind` (`composer` / `bridge` / `sdk` = the person) tells a human prompt from a notification.

**How to apply:** check these before writing pane or event tests in a mod; see [[bash-heredoc-backslashes]] for writing multi-line scripts (use the Write tool, then run the file).

Since 2026-10-23 (AAW-20261023 step 1.2, lens avatars): `on(...)` after the test's first `$` call throws ("hooks beneath the plugins are registered before that"), so one seed per test: loop over cases with `for (...) test(...)`, never a seed inside a loop. A stub that throws falls through to the real file system (an absolute path like `/home/u/.claude.json` resolves to `E:/home/u/...`): match stub keys by tail. `mock.env(on, {HOME})` stubs `$.env.get`. `$.fs.stat(p, { resolve: true })` gives `realPath` (links followed, `..` folded): the trust check's basis. Headless tests cannot see a surface's Svg scrub: draw robots and images inline (no `<symbol>`/`<use>`/`<clipPath>`) and render a dumped Svg with headless Chrome (`chrome --headless=new --screenshot`) to eyeball it.

Since 2026-10-23 (step 1.3, keep-alive state): an inline test plugin (`test(name, { plugins: [{ name, register }] }, fn)`) has its `register` loaded on its own, so it can use nothing declared outside it (`x is not defined`). A test can capture another hook's `$.state.set` with `on('state.set', ...)` returning `{ value: { isSet: true, version } }`. A plugin's `types` contract declares only its own state (d.ts PluginState); a reader of another plugin's value keeps a local type outside PluginState and reads through `$: any` or checks fields at run time.

Since 2026-10-24 (AAW-20261023 step 1.5, lens view controls): a tree holding two `Image`s with one key is refused whole by the host ("Image ... is drawn twice; each takes its own key"): the pane draws nothing, terminal only, so prefix Image keys per chart. `on('session.surfaces', () => ({ value: ['terminal'] }))` stubs `$.session.surfaces()`; an `AbovePrompt` site mounts as `{ component: 'AbovePrompt', props: { hasSurvey, isWorking, maxRows, bodyColumns, scroll, view } }`, and the test's catch-all `ui.render` stub is its `next(e)` tree. A mount may carry `viewport: { columns, rows }`. `$.ui.close` of an id not open is left alone (d.ts:2538), so no `$.ui.panes()` check is needed before it. Pane mods can only ask a size (`rows` inline, `columns` docked, d.ts:7638-7660) — no placement, minimise or full screen; the AbovePrompt band (terminal, desktop only) is the one real "pinned above the prompt" place.

Since 2026-10-24 (step 1.6.1, lens anomaly detector): a hooks module cannot return a `systemMessage` (`ClassicResultFields` gives `Stop` only `additionalContext`), so a module alert is `$.ui.toast`. A test calling `$.classic.Stop` needs `on('classic.Stop', ...)` stubbed ("no implementation"), and registering it twice in one test fails the module load ("registered twice"). Two Buttons sharing a key cannot be told apart by a surface (ButtonProps.key): a list must give each entry its own key — the lens's background tasks broke on a subagent listed by both `$.agent.list()` and Stop `background_tasks`.

Since 2026-10-23 (FEAT ai-dlc-lens step 19.l1, code-review fixes): the module analyser also refuses `$.state` as a value (`const f = $ => $.state`): spell `$.state.get(ref as never)` at the call site and cast the result. `ui.mount` of a `ToolUse` row clones its props, so a getter in `input` throws inside the engine, never in the hook: a card's own throw cannot be injected headless (test the guard as a pure helper, `drawOr`); a Pane mount keeps a missing `props.scroll`, which makes a pane drawing throw. A mounted drawing redraws on `find` in the harness, so a stale module-global read (vs an atom read) cannot be shown headless. A `clock.every` stub returning a held promise counts live timers: the next period is asked on a later task (await `setTimeout(0)`, not microtasks), and a cancelled timer is not asked again. `session.end` with reason `clear` is followed by no `session.start` (SessionEndInput): never stop a mod's pollers there. With typed `$` (`EngineInterface`), `read($, atom)` is already typed from PluginState: `as T` casts on atom reads are redundant.

Since 2026-10-23 (FEAT ai-dlc-lens step 28.1, keep-alive keepWarmMs): the test body's `$` has no `state` either (`$.state.get` is undefined): to test a reader, give the test an inline plugin (`{ plugins: [reader] }`) that registers a probe `command.run` doing the `$.state.get`, stub `on('state.get')` to answer `{ value: { value, version } }`, and call the probe with `$.command.run`. Keep-alive's published `keepWarmMs` is re-read for non-running tracks at `turn.start`, `session.end` (session override left out) and after the command (`refreshKeep`), never in `stopTrack` (`arm` calls it); a session override deliberately survives `turn.start`.

Since 2026-10-23 (FEAT ai-dlc-lens step 29.1, run order): the workflow view orders runs by spawn time (`startedAt`, ms), so a test that asserts the run order must start each spawn in a later millisecond (`nextMs()` in `spawnInto`/`spawnReal`). Line endings differ per file in `plugins/claude/ai-dlc-lens/`: `tests/lens.test.tsx`, `MANUAL-CHECKS.md` and `hooks/anomaly.ts` are CRLF, the other hooks LF: a scripted replace must match each file's endings (write the script with the Write tool, build CRLF with `chr(13)+chr(10)`).
