## One band, active runs (step 44, R44.4 and R44.5; 2026-10-31)

- **Written here, no third-party code:** in `register.tsx`, the `AbovePrompt` hook draws the lens band only where every attached surface draws it (`bandEverywhere`, the rule `/ai-dlc:lens` already follows), so a VS Code session gets the pane alone; in `lens.ts`, `runListStatus` keeps a workflow whose run is `active` from reading `completed` in the run list and the band (it reads `waiting`), and `workflowInfo` uses it.
- **R44.4 widened (2026-10-31):** no change here; keep-alive (ai-dlc) follows the same surface rule, so a VS Code session draws no band below the tabbed pane.
- **R44.9, R44.10 (44.2.l1.3, 2026-10-31):** written here, no third-party code: `followSeat` in `register.tsx` closes the Run List tab when a lens pane is drawn inline, so a narrowing VS Code panel keeps one lens tab; VS Code itself moves the pane between above the prompt and the right pane. The probe (`p44`) used to find it is removed.
- **R44.12 (44.2.l1.4, 2026-10-31):** written here: `followSeat` also opens the Run List tab, without focus, when a VS Code lens pane is docked again after being inline. The comments that called AbovePrompt terminal and desktop only now say the probe saw VS Code raise it.
- **R44.14 to R44.16 (44.2.l1.5, 2026-10-31):** written here. The Run List tab opens only in tab mode, by `/ai-dlc:lens` and on widening (`openLens`, `seatChanged`). In VS Code the view's place follows the pane's seat (`followSeat`), and the mode button (`placePress`) switches between the pane (docked) and the band above the prompt (pinned, pane closed; `vscodeBandA`, `bandAllowed`), so R44.4's no-band rule now holds only while the pane is the view. The pinned note is not shown in VS Code.
- **R44.17, R44.18 (44.2.l1.6, 2026-10-31):** written here. The acts a render asks for (the seat follow, the band's hand-over, the band ping) run through `afterRender`, which tries a write again when the host refuses it as made during a later render's dispatch; the seat follow's refused write had left a widened pane in its narrow minimised list, without its flowchart.
- **R44.19, R44.20 (44.2.l1.7, 2026-10-31):** written here. On docking after inline, `seatChanged` lays out the workflow view in both panel types and opens the Run List tab in tab mode only. In VS Code a step's flowchart is drawn only in the docked pane; above the prompt a line says to widen the Claude panel (no host op can widen it), and the step's full-screen control is drawn dim while the panel is narrow.
- **R44.21, R44.22 and the G4 suggestion (44.2.l1.10, 2026-10-31):** written here, no third-party code. The `AbovePrompt` hook gates the lens band on its render's own surface first (`bandAllowed($, e.surface)`): a terminal or desktop render draws it whatever else is attached and with an unknown roster; a VS Code render keeps the R44.4 and R44.16 rules, and the commands keep the roster rule. Step chart headings (`stepLook`) use `runListStatus`, which now keeps any named run that is not `done` (active, empty or unknown) from `completed`. `afterRender` takes a `gaveUp` callback, so `followSeat` clears `bandGivingWay` only when the hand-over succeeds or is given up, not between retries.
- **R44.22 extended, R44.23 (44.2.l1.11, 2026-11-01):** written here, no third-party code. `stepLook` names a run with no readable run state with an empty status, so its finished steps read waiting, as the run list does. A new `ownSurface` (the first of `$.session.surfaces()`, `terminal` first under the REPL) gives `onBand` (and so `showView` and `/ai-dlc:lens`), `placePress` and `openLens`'s VS Code seat check the session's own surface: a terminal or desktop session draws the band and opens no pane whatever else is attached; a VS Code session keeps the R44.4 and R44.16 rules.
- **R44.23 amended (44.2.l1.12, 2026-11-01):** written here, no third-party code. `onBand` now reads a new `viewBandOnly`: a pinned view is the band alone in a terminal or desktop session (`ownSurface`) with no VS Code panel attached; with one attached, `/ai-dlc:lens` and `showView` open the pane for it (the terminal shows the pane too, since a pane is the session's) unless the lens was moved into the VS Code band (`vscodeBandA`). The mode button passes the press's surface to `placePress`: a press in VS Code takes the R44.16 path in any session, so an attached VS Code panel always keeps its pane or its band. `stepLook` (R44.22 extended) and `openLens`'s seat check by `ownSurface` are kept.
- **Q44-C, decision 9 (44.2.l1.13, 2026-11-01):** written here, no third-party code. `notePaneSeat` (the seat memory `paneSeat`) and `followSeat` (the seat memory `lastSeat`, the place, the band's hand-over and the Run List tab, through `seatChanged`) now act only on lens pane renders whose own surface (`e.surface`) is `vscode`. Decision 10 (manual closes are allowed exceptions) needs no code. `MANUAL-CHECKS.md` M34 gains the decision 9 case and the VS Code session with Desktop attached.
- **ITEM-104, decision 16 (44.2.l2.2, 2026-11-01):** written here, no third-party code. In `register.tsx`, `refreshList` shows a subagent stored `running` as halted (`failed`) once `$.agent.list()` has not listed it, and it has sent no event, for the new setting `droppedSubagentMinutes` (`settings.ts`, default 15, 0 to 1440, 0: never); `missingSince` holds the time and `heard` restarts it on any event of the agent. `session.start` clears `haltedByTurn` and `missingSince`; a non-answer `turn.complete` keeps an agent already stored as ended; a resumed agent's `endedAt` is reset. `MANUAL-CHECKS.md` M35 gains the converse case.
- **ITEM-104, review round 2 fixes (44.2.l2.3, 2026-11-02):** written here, no third-party code. In `register.tsx`, the `update` updater in `refreshList` no longer writes module state (the engine runs it again on a version miss): it collects the resumed ids, and a new pure helper, `haltDroppedSubagents`, returns which `missingSince` entries to start or clear and which agents to halt; `refreshList` applies both after `update` resolves. The timeout reads the time from `$.clock.now()`, once before the write, instead of `Date.now()` (the wall clock only where nothing answers `clock.now`, as in a test that mocks no clock). Timeout halts are kept in a new set, `haltedByTimeout`, apart from the list-confirmed `haltedByTurn`; `heard` (now async) brings such an agent back to `running` with `endedAt` null on any later `turn.start`, `turn.step`, `tool.call` or `turn.complete`, and a listed `running` still resumes it. `missingSince` is a `Map` cleared at `session.start` with both sets.
