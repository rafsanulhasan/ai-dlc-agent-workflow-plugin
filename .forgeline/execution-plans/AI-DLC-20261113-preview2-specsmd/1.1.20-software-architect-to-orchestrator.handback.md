# 5. ADR drafts (complete; to `memory-bank/product/decisions/`; written by `documentation-writer`)
Common header: **Status:** Proposed (G2) · **Date:** 2026-11-13 · **Deciders:** software-architect (1.1.14, 1.1.20), system-engineer (1.1.19), human at G2 (and D15–D25 for 0015).

### ADR-0011 — Hand-off records are the typed events
**Context.** FR-6 asks for five typed events checked against a schema, with no runtime (D3). Every run already writes handoff records and hand-backs; the hook and lens parse their names. A second stream would duplicate and drift.
**Decision.** One record file = one event, named by G-REC (`CODE-FROM-to-TO.TYPE.md`, optional `.h{round}`), `human` a valid party; flat front matter, common `event, step, run, from, to, date` + per-type fields with closed enums; `event`, `step`, `from`, `to` match the file name. Gate decisions `{code}-{human|orchestrator}-to-orchestrator.verdict.md`; approver `none` writes no verdict. Pairing handoff → handback; handoff to `human` → verdict; escalation → verdict. Reviewer verdicts stay hand-back fields. `.ai-dlc/event.schema.json` documents; `workflow.mjs` enforces from one table (drift test). Opt-in per run (`events: 1`); `workflow.mjs events` lists read-only.
**Consequences.** No duplicate store; history readable; lens and hook changes additive; orchestrator prepends front matter to verbatim hand-backs; old and migrated runs not validated; closed `command.action` needs a schema change to extend; three parsers share one grammar and one vector set.
**Alternatives rejected.** `events.jsonl` per run (second source of truth); JSON event files beside records (duplication); one file per reviewer verdict (more files, no new information).

### ADR-0012 — Bolt types are named, skippable stage subsets of existing lifecycles
**Context.** specsmd has bolt types with their own stages; the product owner prefers no new lifecycles (FR-4); our lifecycles carry owners, artifacts, loops, gates.
**Decision.** `boltTypes` maps lifecycles to stage subsets (or `"*"`), optional `after` override, optional `producesCode: false`. Stages outside the type are skipped like a false `when`; dependents proceed; order from `after` edges. Building stages marked `building: true`; `producesCode: false` types may not contain one. Defaults `construction-bolt`, `simple-bolt`, `spike-bolt` (ASDLC research + probe → architecture). New stages `unit-design`, `bolt-design`, `probe` (`software-engineer`, `.scratch/` only). `validate` checks ids, existence, duplicates, acyclic overrides, no-building rule.
**Consequences.** No new lifecycles or gates; projects add types; skip rule reuses `when`; `building` makes the docs-status building stage machine-readable; a type means something only in its listed lifecycles; `probe` widens ASDLC (human Q8).
**Alternatives rejected.** One lifecycle per type (PO rejected); specsmd DDD stages (paradigm-specific; folded into `lld`); ordered-subsequence rule (cannot express research before recommendation in ASDLC); `research-assistant` running the live spike (no Bash).

### ADR-0013 — One home per artifact type, one old-to-new map; the new path wins
**Context.** Knowledge moves from `docs/` to `memory-bank/product|project/` and runs to `execution-plans/` (D2, D3, D8); preview1 repos must work for one release (D9) with a warning and a migration.
**Decision.** `ARTIFACT_TYPES` gives each type one path and its legacy path, used by `validate`, `migrate`, resolver, tests. Layout preview2 when `artifacts.intents` set. A non-empty new root wins; a non-empty legacy root is ignored with a warning. Without `workflow.json`: non-empty `execution-plans/` wins, else non-empty `docs/handoffs/` with a warning. One warning line per invocation, roots aggregated, existing non-blocking channels, naming the channel's migrate entry. Legacy branches marked `fallback: remove in 1.0.0`. Order enforced in code: new tooling → `migrate` → template-key merge (`merge` skips `artifacts` while legacy).
**Consequences.** Preview1 works one release; bolt artifacts spread by type and linked from `bolt.md`; specs and LLDs share a folder with different suffixes; empty legacy folders never warn; 1.0.0 removal is a marker grep.
**Alternatives rejected.** Per-bolt co-location (violates AC-1.2); legacy wins (freezes migration); warning per file or per session (noise or silence); empty root counts as present (warns forever).

### ADR-0014 — `documentation-writer` is the single writer of `memory-bank/`
**Context.** D2: stage agents own content; one agent persists it. In preview1 each stage wrote its own artifacts; voice, markers and paths drifted.
**Decision.** Stage agents return content + *Docs update*; only `documentation-writer` writes under `memory-bank/`; `brutal-critique` gates; any other agent's bank write is a reviewer Blocker (C-10). Exempt: tool output with no content edits (`init` `.gitkeep`, `migrate` pure moves at 100% similarity via `git mv`) (1.1.17). `execution-plans/` is not documentation (orchestrator and teammates write records). Backlog in the bank: `product-manager` owns content, `documentation-writer` writes it (incl. ITEM-121's merge).
**Consequences.** One voice, consistent status; an extra hop per artifact; docs-status rule and template change (bolt 003); authorship checkable from the diff.
**Alternatives rejected.** Each stage writes its own artifacts (preview1); shared-writer convention without the Blocker (unenforceable).

### ADR-0015 — The plugin becomes `ai-dlc-engine`, the marketplace `ai-dlc-suite`; family names stay; one migrate skill
**Context.** After G1 the human renamed the plugin (D15) and marketplace (D17, D21) and moved the folders (D19), both in preview2 as one break (D23); lens commands move to the lens (D22) while keep-alive and auto-handoff stay in the engine (D24); migration is a shipped skill (D25). Research: no documented alias across a marketplace rename; removing a marketplace deletes stored plugin data; `ai-dlc` is taken; the memory-folder pattern is undocumented (1.1.15, 1.1.16).
**Decision.** Apply the rename map (2.10): `ai-dlc-engine:` prefixes, `plugins/*/ai-dlc-engine/`, marketplace `ai-dlc-suite`; lens commands `/ai-dlc-lens:show|configure|init|kit|gate`; lens keep-alive toggle → engine skill `/ai-dlc-engine:cache-keepalive-lens`. Family names kept (`.ai-dlc/`, `AI_DLC_*`, `ai-dlc-lens`, managed-block markers, state namespace unless the spike says otherwise). No alias. `/ai-dlc-engine:migrate` is the single entry point; it runs the plugin's own `workflow.mjs migrate` and rewrites the repository's `.claude/settings.json` and `.claude/settings.local.json` (user-level only as advice); `workflow upgrade` keeps the template-key merge. The lens accepts both worker prefixes for one release. Spike bolt 001 checks undocumented behaviour first.
**Consequences.** Every command, subagent type and memory folder name changes; engine and lens renames ship together; users remove the old marketplace, add the new one, reinstall, run migrate; the upgrade guide warns about stored-data loss and managed settings; a stale-names sweep guards it; one engine skill's text names a lens setting.
**Alternatives rejected.** Keep `ai-dlc` (D4 reversed by D15); marketplace `ai-dlc` (taken); two releases via `renames` (D23); rename `.ai-dlc/`/`AI_DLC_*` (D16); keep `plugins/claude/ai-dlc/` (D19); migration inside `workflow upgrade` (D25); merge the lens toggle into `cache-keepalive-configure` (engine writing a lens setting).

### ADR-0016 — Units are stable product slices with intent-scoped folders
**Context.** specsmd numbers units per intent (`{UUU}-{name}`); the human named two lasting units, `ai-dlc-engine` and `ai-dlc-lens` (D14), that every future intent touches.
**Decision.** Unit slugs from `memory-bank/product/units.md` (slug, purpose, owned code paths), no number. Each intent has a folder per touched unit: `intents/{intent}/units/{unit-slug}/` with `unit-brief.md`, `stories/`, `bolts/`. Bolt ids global (`{BBB}-{unit}-{slug}`).
**Consequences.** Same unit name across intents; history by slug; each intent holds only its own work; a new unit = a registry entry.
**Alternatives rejected.** specsmd per-intent numbered units (new name each intent); product-level `product/units/<unit>/` with every intent's work (mixes intents, unbounded).

# 6. Architecture narrative for G2
(Target `memory-bank/product/narratives/preview2-specsmd.md`, written by `documentation-writer`, then `brutal-critique`. Audience: the human and the product owner; no prior context.)

## Act 1 — The problem
The AI-DLC plugin runs a team of AI agents through lifecycles with human gates. Today everything they produce lands in `docs/`: specs, ADRs, plans, the backlog and hundreds of hand-off records. That mixes three things: what the product *is* (knowledge), how the team is *working* (run mechanics), and what readers need (user documentation). Nothing says which file is current, who may write it, or how a piece of work is sized.
specsmd, an open-source method, has a cleaner model: a **memory bank** holds knowledge, and work flows as **intents → units → bolts** (small, typed delivery slices). The owner wants it adapted natively, under our gates, with typed events for the hand-offs. The product also gets its real name: the plugin becomes **ai-dlc-engine**, the marketplace **ai-dlc-suite**, and the live view **ai-dlc-lens** owns its own commands.
People involved: the human owner, who approves at the gates; users who installed preview1 and must not be stranded; the agents, whose instructions encode every path and name.

## Act 2 — What made this hard
- **Constraints:** planning only in this run; zero-dependency Node tooling; Claude Code and GitHub Copilot, with the lens Claude-only; preview1 repos work for one release (D9); no deterministic runtime (D3); one documentation writer (D2).
- **Characteristics that matter:** *evolvability* (every path from one table); *recoverability* (event records stay plain files); *migratability* (one command with a dry run); *consistency* (one status vocabulary, one record that wins).
- **Unique challenges:** the rename touches every agent reference, memory folder and user setting; no alias for a renamed marketplace, and removing one deletes the plugin's stored data; lens commands answered by a module in one plugin while skills ship in another; undocumented platform behaviour (memory-folder naming, unknown default agent).
- **Trade-offs:** bolt types as new lifecycles (clearer, but doubles the catalogue and gates) → subsets of existing stages with a skip rule; a separate event stream (cleaner log, duplicates records) → records as events with front matter; per-bolt artifact folders (browsable, breaks one home per type) → type folders linked from `bolt.md`; renaming in two releases (softer, two breaks) → one clean break (owner's choice); units numbered per intent (new name each intent) → stable unit slugs.

## Act 3 — The design
```
memory-bank/
  product/  intents/{NNN}-{slug}/units/{unit}/{unit-brief.md, stories/, bolts/}
            units.md · specs/ (.spec.md, .lld.md) · decisions/ · narratives/ · glossary.md · briefs/
  project/  backlog.md · plans/ · research/ · quality/ · standards/
execution-plans/{LIFECYCLE}-{date}-{slug}/
  execution-plan.md · run.v*.md · 1.2-orchestrator-to-x.handoff.md · …handback.md · …verdict.md · …escalation.md · …command.md
docs/   README pages, guides, release notes (reader-facing only)
```
- **Two units:** ai-dlc-engine owns the contract (layout, event grammar, `workflow.json`, migration) and the team, including keep-alive and auto-handoff; ai-dlc-lens reads it and shows runs live; dependency one way.
- **Bolts** typed by naming a subset of an existing lifecycle's stages (`construction`, `simple`, `spike`); stages outside are skipped like a false condition.
- **Events** are the hand-off records with a type and front matter, checked by `validate` when a run opts in.
- **Preview1 repos** keep working one release: new path wins, old one read with one warning naming `/ai-dlc-engine:migrate`; migrate shows a dry run, refuses conflicts before writing, moves with `git mv`, rewrites the repo's settings and memory folders, flips the layout last.
- **Decisions:** ADR-0011 (records are events), 0012 (bolt types as skippable stage subsets), 0013 (one home per type; new path wins), 0014 (single writer), 0015 (rename and migrate skill), 0016 (stable units) — each traced to Act 2.
- **Delivery:** 13 bolts; a live spike first settles undocumented behaviour; content bolts; the rename (serialised); migration and the sweep; this repo's own migration and the release.

**Risks and mitigations:** 1 undocumented platform behaviour → spike 001 first, spec changes before the migration bolt; 2 users lose plugin data removing the old marketplace → upgrade-guide warning before step 1, migrate dry run; 3 rename churns every file → serialised with no other bolt open, stale-names sweep; 4 three parsers drift → one grammar, shared vectors, drift test; 5 settings rewrite misses a form → post-rewrite parse check, misses as advice; 6 fallback outlives its release → marker + 1.0.0 grep (ITEM-125); 7 `workflow.mjs` ~1,400 lines → split trigger ~1,500.
