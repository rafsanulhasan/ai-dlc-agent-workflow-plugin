# Research Findings: specsmd (specs.md) for preview2 integration

## Question
What is specsmd, who maintains it, under what licence, and what its AI-DLC flow looks like (phases, stages, memory-bank layout, intents, units, bolts, bolt types, state model, extension points), compared with AWS's AI-DLC. Scope is primary sources. Time-sensitive: state as of 2026-11-13.

- Fetched the specsmd repo's `README.md`, `LICENSE`, `package.json` (under `src/`), `CHANGELOG.md`, `src/flows/aidlc/README.md`, `src/flows/aidlc/memory-bank.yaml` and `src/flows/aidlc/agents/construction-agent.md` (raw GitHub).

## Findings

**1. What it is and who maintains it.** specsmd is an npm package, "Multi-agent orchestration system for AI-native software development", which "Delivers AI-DLC, Agile, and custom SDLC flows as markdown-based agent systems" [1][2]. The repo is `fabriqaai/specs.md` and is maintained by Fabriqa AI (the copyright holder) [1][3]. The package's `package.json` names author "specsmd team" [2]. Its CLI entry point is `bin/cli.js` [2]. Install is `npx specsmd@latest install`. The README warns "Do not install globally with npm" [1]. Hosts listed: Claude Code, Cursor, GitHub Copilot, Google Antigravity, Windsurf, Amazon Kiro, Gemini CLI, Cline, Roo Code, OpenAI Codex, OpenCode, and VS Code-based IDEs [1].

**2. Version and licence.** `src/package.json` on `main` gives version **0.1.74** and licence **MIT** [2]. `LICENSE` reads "MIT License", "Copyright (c) 2025 Fabriqa AI" [3]. Caveat: the 0.1.74 figure is the `main` branch, not a checked npm release.

**3. Flows.** Four: Ideation (Spark, Flame, Forge; no checkpoints), Simple (spec generation only; 3 phase gates), FIRE ("Fast Intent-Run Engineering"; 0 to 2 adaptive checkpoints), and AI-DLC (4 agents; comprehensive checkpoints) [1]. The `CHANGELOG.md` covers only dashboard and installer changes [4].

**4. AI-DLC phases, agents and stages.** Inception: "Capture intents, elaborate requirements, decompose into units". Construction: "Execute bolts: Model → Design → ADR → Implement → Test" (README) [1]; the flow's own docs name `domain-design`, `logical-design`, `code-generation`, `testing` [6]. Operations: "Deploy, verify, and monitor" [1]. Agents: master orchestrator, inception, construction, operations [6]. The construction agent asks the user which bolt to work on, never auto-selects, and refuses to create bolts: "Bolts must be planned during Inception" [7].

**5. Memory-bank layout.** README [1]:
```
memory-bank/
├── standards/
├── intents/{intent-name}/ (requirements.md, system-context.md, units/)
├── bolts/
└── operations/
```
`memory-bank.yaml` (described as authoritative) [6]:
- `intents/{NNN}-{intent-name}/`: `requirements.md`, `system-context.md`, `units.md`, `inception-log.md`.
- `units/{UUU}-{unit-name}/`: `unit-brief.md`, `stories/{SSS}-{title}.md`, `construction-log.md`.
- `bolts/{BBB}-{unit-name}/`: `bolt.md`, `ddd-01-domain-model.md`, `ddd-02-technical-design.md`, `ddd-03-test-report.md`.
- `standards/`: `tech-stack.md`, `coding-standards.md`, `system-architecture.md`, plus `decision-index.md`.
- Top level: `story-index.md` (single-file mode), `project.yaml` (`project_type`, `initialized_at`).
These two sources disagree.

**6. Intents, units, stories.** Intent "(feature/capability)"; unit "(independently deployable component)"; story "individual user story or task" [6]. Inception owns intents, units, stories and the initial bolt plan. Construction owns unit and bolt execution and replanning [6].

**7. Unit and bolt design, bolt types, states.** Bolt: "time-boxed execution session scoped to a Unit"; a unit "may require multiple Bolts" [6]. Only bolt type named: `ddd-construction-bolt` [7]. Bolt states not defined in fetched sources; a `bolt-status` skill is named [6][7]. `bolt-replan` skill ("append, split, reorder") [7].

**8. Execution-plan, event and state model.** None defined. Inception produces "Bolt Plans" ("Planned work sessions") [6]. Logs: `inception-log.md`, `construction-log.md`; timestamps `YYYY-MM-DDTHH:MM:SSZ` [6].

**9. Extension points.** README: "pluggable flows for every use case" only [1]. Flows under `src/flows/`; templates under `src/flows/aidlc/templates/` not read.

**10. AWS AI-DLC.** Blog 2025-07-31 (Raja SP): Inception ("Mob Elaboration"), Construction ("Mob Construction"), Operations; "Traditional 'sprints' are replaced by 'bolts'"; "Epics are replaced by Units of Work" [5]. `awslabs/aidlc-workflows`: MIT-0, "5 phases and 33 stages", 11 profiles, no unit/bolt terms [9][10] — a different project from specsmd.

**11. Disambiguation.** specsmd (fabriqaai, MIT) ≠ awslabs/aidlc-workflows (MIT-0) ≠ AWS blog (methodology). Product Hunt variant without bolts/units [11, unverified].

**12. Licence implications.** MIT: keep copyright + permission notice in copies/substantial portions [3]. MIT-0: no notice condition [9]. Follow existing LICENSE + ATTRIBUTION.md + THIRD_PARTY_NOTICES.md pattern. Ideas from the AWS blog alone carry no licence obligation [5].
