- Generator: `tools/build-standards.mjs`, beside `build-copilot.mjs` and `validate.mjs`, because it is a repo-local build tool like them (D53); `.claude/scripts/` holds scripts the plugin installs into consumer repositories (`sync-harness.mjs`), which this is not. It writes `.claude/rules/<n>.md` and `.github/instructions/<n>.instructions.md` with byte-identical bodies; the marker is a YAML comment on the first front-matter line naming the standard and a sha256 of the twin without that line. `sync-harness` compares only description, scope and body and keeps front-matter lines it does not sync (8.1.5 Q4; `sync-harness.mjs:87-98,169-182,331-335`), so it sees the twins in sync. A hand-edited twin is refused, never overwritten, unless `--force`; a marked twin with no standard is an orphan (exit 1), never deleted. `--check` exits 1 when anything is missing, stale, refused, orphaned or off-template; 2 on usage errors or an invalid standard.
- Template (C5): `docs-status` carries `template: plugins/claude/ai-dlc/skills/docs-rules/templates`. The generator renders the twins in the template's exact form and refuses the standard, writing nothing, when either twin without its marker line differs from its template byte for byte. So the repo copy equals the plugin template except the one marker comment, and a change to one without the other fails the Stop step and CI.
- First run: four twins adopted (bodies unchanged; diff = the marker line, and `alwaysApply: true` dropped from the plugin-development rule, a key Claude Code does not read).
