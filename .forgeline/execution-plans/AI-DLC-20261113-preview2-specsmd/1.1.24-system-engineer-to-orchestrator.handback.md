## 0. What I verified, and the decisions that change the 1.1.23 design

Verified at HEAD (so the plan rests on it): `workflow.mjs` is 988 lines and runs everything at import (argv parse, `ROOT`, and `LEVELS`/`ENV` which read `.claude/settings*.json` at lines ~715-737); it is installed as a two-file copy (`workflow.mjs` + `workflow.schema.json`) by the `workflow` skill (install and upgrade step 1), by `init` (step 91) and by the future `migrate` skill (step 6), and the Stop-hook gate `check-workflow.mjs` blocks finishing when `node .ai-dlc/workflow.mjs validate` fails; CI is `ubuntu-latest`, Node 22, `actions/checkout@v4` (shallow); `.gitattributes` forces LF; `merge` adds every key the project lacks at any depth (`workflow.mjs:848`); the hook test runner (`claude-code/testing`) loads code files only, and its precedent for shared fixtures is a plain `.mjs` module (`L/tests/fixtures/scrub-cases.mjs`, imported by `diagram.test.ts` and by `tests/lens-renderer/scrub.test.mjs`).

Decisions (each also appears under `refine:` in section 9):

- **S-1. Vector files are `.mjs` modules, not `.json`.** The hook and lens runners load code files only; the repository already solved this once (scrub-cases.mjs). Spec §4.2, §8, §9 and the 1.1.23 notes name `.json`.
- **S-2. No `lib/` split of `workflow.mjs` in preview2.** Keep one file, make it importable (export + main guard), organise it in fixed sections. Detail in section 3.
- **S-3. The `merge` guard moves from bolt 012 to bolt 002.** Bolt 002 turns the template's `artifacts` into the 13 preview2 keys; from then on `merge` on any legacy project (this repository included) adds `intents` and the rest and flips the layout before any files move. Until 012 nothing prevents that. The guard is about 12 lines plus one test.
- **S-4. A fourth vector file, `runs-root.mjs`.** The resolver table (spec §9.1, seven rows) is the largest behavioural surface duplicated in three code bases and has no vector file in 1.1.23; `fallback-warning` covers only the formatter.
- **S-5. G-FM is implemented once, in `workflow.mjs`.** The spec says three implementations, but no story carries an AC part for the hook or the lens parsing bank front matter (e005 is `[validate]`, e013 `[templates]`), and neither reads a bank file. The lens already has the lenient reader it needs for `decision:` in `.verdict.md`. I recommend narrowing the spec text to "one grammar; an implementation joins the vector set when it first reads a bank file". This drops two vector copies and one drift pair. If the architect keeps three, add two story parts to e016 and l001 and accept the edge-case risk (the lens lowercases keys; the hook accepts `[\w-]+`).
- **S-6. The AC-3.3 gate-equality test must not read git history.** 1.1.23 section 7 compares the preview1 template "(git)" with the new one; CI checks out one commit. Bolt 005 stores the expected gate set (ids, approvers) as a literal fixture, captured once from `47a3480`.
- **S-7. "Clear legacy paths as you touch a file."** Each bolt removes the legacy `docs/...` paths in the files it already edits (section 2 assigns all 37 non-test hits). This shrinks bolt 011's fix volume, which 1.1.23 says is unknown, to a short leftover list (assigned to 006).
- **S-8. Shared bank files change once per wave, not inside a bolt run.** Unit-brief *Bolts* sections, `units.md`, the tasks-plan status columns and the backlog are touched by one `documentation-writer` stage after the wave's merges. Each bolt's own `bolt.md` and stories stay inside its run. Otherwise every parallel bolt's docs stage edits the same files.

## 3. `workflow.mjs`: no `lib/` split, an importable single file

**Decision: keep one file through preview2.** Reasons:

1. The installed form is the unit. Three places copy exactly two files (the `workflow` skill's install and upgrade, `init`, and the `migrate` skill's step 6), each "diff first, write with consent". A `lib/` folder means a third copy set, partial installs, and a failure mode in the gate that matters most: `check-workflow.mjs` blocks the end of a session when `validate` fails, so an install that leaves `lib/` missing turns into a blocked session.
2. A split decided in 002 puts install-flow changes on the critical path (002 → 005 → 006 → 009 → 010 → 012).
3. The conflict argument for splitting is answered by sections and merge order (section 1). Size: my forecast is about 2,000-2,300 lines, not the 1,500 trigger in 1.1.19 §1.5: artifacts and layout +150, G-FM +55, bank checks +60, resolver, formatter and exit handler +85, `boltTypes` +95, G-REC and events +170, planning warning +20, `migrate` and detect +550, `merge` guards +30, refactor +40. The legacy branches are grouped (below) and about 250 lines of them go in 1.0.0.
4. Revisit at 1.0.0 (legacy code gone) or above 2,500 lines.

**What 002 does to make the file testable (this replaces the "one file, CLI-only" assumption).** The existing top-level code has import-time side effects. The change is local and every existing CLI test guards it:

- `IS_MAIN = process.argv[1] && path.resolve(process.argv[1]) === fileURLToPath(import.meta.url)`, the guard `auto-handoff.mjs` already uses (line 328); argv parsing, the help block and the command dispatch (lines 898-988) run only when `IS_MAIN`. When imported, `argv` is `[]` and `ROOT` is `process.cwd()` (no `git rev-parse` spawn).
- `LEVELS` and `ENV` (lines ~715-737) become a memoised `envLevels()` read on first use, so importing never reads settings files.
- Pure functions are exported: `parseFrontMatter`, `parseRecordName`, `RECORD_TYPES`, `resolveRunsRoot`, `formatFallbackWarning`, `ARTIFACT_TYPES`, `rootOf`, `EVENT_RULES`, later `planMigration`, `applyPlan`, `memoryFolderOf`, `rewriteSettings`, `mergeMemoryIndex`.

## 7. Migrate fixtures that run on Windows and Linux

CI is Linux only; the developer machine is Windows (`core.autocrlf=true` globally, `.gitattributes` forces LF in this repository only). Every fixture rule below targets a divergence that exists between those two.

- **Isolate git.** `spawnSync("git", [...], {cwd, env})` with an argument list, never a shell. `env`: `GIT_CONFIG_GLOBAL=<os.devNull>`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`; per repository `core.autocrlf=false`, `core.safecrlf=false`, `commit.gpgsign=false`, `user.name`, `user.email`. This keeps the developer's global autocrlf out of the fixture.
- **Real paths.** Build the repository under `fs.realpathSync.native(fs.mkdtempSync(...))` and always pass `--root`. On Windows `os.tmpdir()` can be an 8.3 short path, while `git rev-parse --show-toplevel` returns the long one; a mismatch breaks the "is this a tracked path" test.
- **Forward slashes everywhere in output.** `planMigration` and the dry-run print repository-relative paths with `/`; `path.join` results are normalised once, so expected `--dry-run --json` text is the same on both systems.
- **Unique content per file.** Each fixture file's body contains its own path. `git log --follow` (AC-11.3, AC-17.10(a)) pairs renames by similarity, and two short identical files can be paired wrongly.
- **Build once, copy per test.** One `before()` creates the base repository (init, add, commit); each test uses `fs.cpSync(base, work, { recursive: true })`. Git on Windows costs a few hundred milliseconds per init-plus-commit; a copy is cheap. Cleanup: `fs.rmSync(tmp, { recursive: true, force: true, maxRetries: 5, retryDelay: 50 })`, because Windows holds `.git` files briefly.
- **Byte-exact duplicates.** The "identical file" test (O-2, D39) compares bytes. A pair that differs only by CRLF against LF is a conflict, not a drop; one fixture covers it. This is the conservative failure (it stops and names both paths); the lld of 012 may relax it.
- **Fixture set, mapped to the ACs** (each a function in `helpers/repo.mjs` returning a file map):

| Fixture | Covers |
|---|---|
| F1 preview1 repository, all seven artifact types tracked and committed, default `artifacts` | AC-11.2, 11.3, 11.4, 11.8 |
| F2 same with custom `artifacts` paths | AC-11.6 |
| F3 both layouts present (`docs/handoffs/` plus a non-empty `execution-plans/`) | AC-11.7 |
| F4 target exists with different content | AC-11.5 (exit 1, `git status` clean, message names the path) |
| F5 folder against file | `kind-mismatch` |
| F6 no `workflow.json` | step 1 (legacy defaults, no `workflow.json` written) |
| F7 memory folders `ai-dlc-<id>/` incl. a project-local and a non-plugin `ai-dlc-*` folder, one pair of identical files, one pair with differing `MEMORY.md` | AC-17.10 (a) to (e) |
| F8 `.claude/settings.json` and `settings.local.json` as JSONC with comments, one LF, one CRLF-with-BOM | rewrite keeps comments, line endings and BOM; text parses after |
| F9 settings with a key for another marketplace (`ai-dlc@<other>`) and an `ai-dlc:<id>` in the same file | `advice:` lines only, prefix rules skipped for that file |
| F10 settings whose `repo` value ends `…/ai-dlc-agent-workflow-plugin` | stays untouched |
| F11 a settings file that does not parse before the rewrite | left untouched and reported, never half-written |
| F12 an already-migrated repository | "nothing to migrate", exit 0, second run clean |

- **Rewrite method** (the lld of 012 confirms): one scanner over the JSONC text finds string-token spans; whole-string and prefix rules apply to a token's content; replacements are applied from the end; the result is checked with the existing `stripComments` plus `JSON.parse`. That preserves comments, BOM and line endings by construction, and it is why F8 exists.
- **No case-only renames** exist in the old-to-new map, so `git mv` case behaviour on Windows and macOS is not exercised; no fixture claims it is.
- **Not covered by CI:** Windows. Section 9, clarify 4.
