## Design decisions (what I decided)

- **D33 pane ids.** `:` is not allowed in a pane id. The d.ts says a pane id is "1-64 of letters, digits, `_` and `-`" (register.tsx:29 and :202). So the final form is `lens-<view>`: `lens-kit`, `lens-edge`, `lens-agent`, `lens-chart`, `lens-runs`.
  - At load, the lens closes any pane still open under an old id (`LEGACY_PANE_IDS` = `ai-dlc-lens` plus the five `ai-dlc-lens-*`). This extends today's `closeOldCard` and carries the fallback marker.
  - `migrate` rewrites no layout file unless new spike item (i) finds that pane ids are persisted.
  - Pane titles ("AI-DLC Lens") stay as they are.
  - The human should still be told, in one line, that `lens:*` is written `lens-*`. It is not blocking.
- **New finding (Major, mine, not in the critique).** The lens's own state atoms use `{plugin:'ai-dlc-lens', …}` about 40 times (register.tsx:232-246…). Under D33's sweep pattern these become `{plugin:'lens'}` through one constant, `LENS_STATE_NS`, in bolt 010. The shared keep-alive namespace stays `'ai-dlc'` unless spike (e) says otherwise.
- **Major 1.** The settings rewrite touches only keys of marketplace `ai-dlc-agent-workflow`. For other marketplaces:
  - any key or value naming `ai-dlc` or `ai-dlc-lens` from another marketplace gets an `advice:` line instead;
  - while such a key is present in a file, the `ai-dlc:` prefix rules in that file also become advice only, because the prefix may name the other plugin's agents.
- **Major 4, ownership.**
  - The engine owns `tools/` (all of it), both marketplace files, `.github/workflows/validate.yml` and `tests/`, except `tests/lens-renderer/` and `tests/cache-reader/`. Those two are node:test suites of lens code (they import `plugins/claude/ai-dlc-lens/renderer/render.mjs` and `hooks/cache-reader.mjs`), so the lens owns them; they stay under `tests/`.
  - In five **shared registration files** the engine owns the file and the lens owns its own entries. Only a lens bolt (010) edits a lens entry. The files: `.claude-plugin/marketplace.json`, `tools/claude-only-plugins.json`, `tools/claude-only-skills.json`, `validate.yml`, `tests/helpers/paths.mjs`.
  - `tools/validate.mjs` hard-codes no lens path; it reads `tools/claude-only-plugins.json` (see its line 11). So it needs no lens edit, only a generic comment fix in 009.
- **Major 7.** The task plan is the schedule of record (waves and order). Spec §16 governs each bolt's scope, and both carry the same bolt rows. The backlog's wave table is marked superseded and replaced by an item → bolt map.
- **Major 8.** The old numbering "unit N" becomes "work item N"; "unit" means only `engine` or `lens`.
- **Major 9.** Two kinds of rewrite rule:
  - whole-string rules match one complete JSON string token, quotes included;
  - prefix rules match inside string content with `(?<![\w-])…(?![\w-])`, longest name first.
- **O-24.** The `interim-names` pattern is kept as written. Planning records are outside the AC-17.3 search scope, so it needs no allowlist entry. Closed.
- **O-8.** `verdict.decision` = `approved|rejected`. An escalation is answered by a verdict followed by a `command`. `pass|revise` is dropped. Closed.
- **O-11.** The work moves into the bolt scope text. Closed.
- **ADR-0011 vs SPEC:318.** The `events: 1` opt-in lives only in `execution-plan.md`, because run-state versions per session make "current run state" ambiguous.
- **Minor 7.** Bolt 012 also requires 010, because the lens command names it rewrites are final only after 010.
- **D35 spelling.** I used the human's spelling, `specmd`, verbatim. The upstream project is `specsmd`. **Ask the human before G2 freezes.**
