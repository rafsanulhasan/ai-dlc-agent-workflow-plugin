# LLD: Cache Lab in ai-dlc-lens (root 22)

Paths are under `plugins/claude/ai-dlc-lens/`. Code lines are as read on 2026-10-25. No code is written here. The lens plugin is Claude-only, so none of this reaches the Copilot build.

## 1. Design summary

| Principle | Decision |
|---|---|
| Extract in a child, compute in TypeScript | A plain-JS child script reads the transcripts and emits numbers only (ADR-0006). All classification, pricing and formatting are one pure TypeScript module, tested by fixtures without a UI. |
| One source for the extraction rules | The child script is the single place that knows the transcript format. The module sees only its envelope. |
| `$` stays in `register.tsx` | The host does not follow `$` across an import (auto-handoff `panel.tsx` precedent). `cache-lab.ts` and `transcripts.ts` take no `$`. |
| Reuse, not copy | Prices: the lens's own `lookupModel`, `factsOf`, `Costing`, the `costingPath` setting. A new `Prices`-shaped function type is the pure core's only price dependency. |
| Never a partial figure | Any reader failure is one reason line; a figure is shown whole or not at all. |

Why a `.mjs` and not TypeScript for the reader: it runs under plain `node` as a child, and a TypeScript file would need a build or a Node version that strips types, neither of which the plugin can assume. ## 3. The reader (`cache-reader.mjs`), ITEM-069

Run as `$.process.run(['node', `${$.plugin.root}/hooks/cache-reader.mjs`, <mode>, ...args])`. Stdout is one JSON object in the `{ data, error }` envelope (`error` is a one-line string or null). Never writes transcript text: only ids, timestamps, model ids and token counts.

### 3.1 Modes

- `list --folder <dir> [--since <ms>]`: walks `<dir>/*.jsonl` and `<dir>/<session>/subagents/agent-*.jsonl`. `data.files` = `[{ rel, size, mtimeMs }]`, those with `mtimeMs >= since` (all when `--since` is absent). A file whose mtime precedes the window start holds no call in the window (a call's row is written before the file's last write). About 100 bytes per file, 609 files here: far under the 4 MiB stdout cap.
- `read --folder <dir> --files <rel,rel,...>`: for each named file, streams it line by line (`readline` over a read stream; the 4 MiB `$.fs.read` cap does not apply). `data.files` = `[{ rel, size, mtimeMs, calls, skipped }]`. The lens sends batches of at most 80 names (about 40 characters each: the Windows argument limit stays under 8,191). The script stops adding files when the serialized output reaches 3.5 MiB and returns `data.next` = the index of the first file not done (the lens re-calls with the rest); a single file whose records alone pass 3.5 MiB returns `error: "<rel>: too many calls for one page"` and no data. `isStdoutTruncated` on the lens side is an error (section 4), never a partial figure.

### 3.2 Per file (`parseTranscript`)

1. Each line: `JSON.parse` in a try. Not JSON, or a truncated last line of a file being written: `skipped++`, continue (Q-CL6, below).
2. A row counts as a **call** when `type === 'assistant'`, `message.usage` is an object whose `output_tokens` is a number, and `timestamp` parses. Otherwise it is not a call: counted in `skipped` only when the line was not JSON; a usage-less or non-assistant row is silently not a call (a user row is normal, not damage). Rows whose `message.model` is `<synthetic>` are not calls.
3. Fields: `in = usage.input_tokens`, `out = usage.output_tokens`, `cr = usage.cache_read_input_tokens ?? 0`, `cc = usage.cache_creation_input_tokens ?? (cc5m + cc1h)`, `cc5m`/`cc1h` = `usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`, **present only when both are numbers** (as keep-alive's `creationSplit`); `model = message.model`; `at = Date.parse(timestamp)`; `session = row.sessionId` (else the file's top-level name); `stream = 'main'`, or `agent:<id>` for a file under `subagents/` (id from `agent-<id>.jsonl`) or a row with `isSidechain: true` (its `agentId` when it has one).
4. **Dedupe by `message.id`** inside the file (architect constraint 2; ADR-0006): one API response is several rows, one per content block, each repeating the usage. The **last** row of an id wins (its `output_tokens` is the final one; `in`, `cr`, `cc` are equal across the rows). A row with no `message.id` is kept as it is. `order` = the file position of the kept row, for ties.
5. **Turn fields, only for bust candidates** (`cc > 10000`, the threshold constant duplicated from `cache-lab.ts` and asserted equal by a test): `pid` = the `promptId` of the nearest ancestor user row, found by walking `parentUuid` (`uuid -> row` map for the file; at most 64 steps; a missing parent, a cycle or no user row with a `promptId` on the way gives `pid` absent). `turn` = the 1-based ordinal of that `promptId` among the distinct `promptId`s of the file's user rows in file order. Research 17.1.19: `promptId` sits only on `user` rows (97 of 97 and 311 of 311 in two files); the `parentUuid` chain from an assistant row to that user row is **not verified**, so the walk is a pure function with a fixture (section 8) and a failed walk degrades to absent, not to a wrong id. The join is in the reader because it holds the whole file; shipping every row's `uuid`/`parentUuid` would cost about 80 bytes a call over 50k calls.
6. `skipped` is the count of lines that were not JSON. The lens logs it once per read to the debug log; it never shows an error banner for it.

### 3.3 Errors (each one line, the envelope's `error`, `data` null)

No `node` on PATH (the lens, not the script: `$.process.run` rejects or exit code 127 on a shell; the lens maps it to `node not found`), a non-zero exit, `--folder` missing or unreadable, a file that cannot be opened (`<rel>: <code>`), too many calls for a page, stdout truncated. The lens shows the reason in the accordion (section 7) in place of the figures.

## 4. Lens side of the reader (`transcripts.ts`, pure)

```ts
export type Call = { id?: string; session: string; stream: string; at: number; model: string; in: number; out: number; cr: number; cc: number; cc5m?: number; cc1h?: number; pid?: string; turn?: number; order: number }
export type FileRecord = { rel: string; size: number; mtimeMs: number; calls: Call[]; skipped: number }
export type Envelope<T> = { data: T | null; error: string | null }

export function checkEnvelope<T>(stdout: string, isStdoutTruncated: boolean, exitCode: number): { ok: true; value: T } | { ok: false; reason: string }
export class FileCache { get(rel, size, mtimeMs): FileRecord | undefined; set(f: FileRecord): void; clear(): void }   // module memory, keyed (path, size, mtimeMs)
export function mergeCalls(files: readonly FileRecord[]): Call[]       // flatten; dedupe across files by id (a resumed session repeats its history); stable order
```

- `checkEnvelope`: truncated, non-zero exit, JSON that does not parse or does not have the envelope shape, or `error` set all return `{ ok: false, reason }` with a single line. Pure, so each case is a table test.
- `FileCache`: a changed `(size, mtimeMs)` replaces the entry; only new or changed files go to the reader. The cache does not survive a module restart (ADR-0006). A file still being written is re-read whenever it grows, which is what `size` in the key is for.
- `mergeCalls`: across-file dedupe by `id` keeps the first file in the order given (the list is sorted by `mtimeMs`, oldest first, so the session that wrote the call wins over the resumed copy).

## 5. The pure core (`cache-lab.ts`), ITEMS 069 to 072

```ts
export type Prices = { input: number | null; output: number | null; cacheRead: number | null; cacheWrite5m: number | null; cacheWrite1h: number | null }  // lens.ts:197
export type PriceOf = (model: string) => Prices | null          // null = model not in the file
export type Window = { from: number; to: number; sessions?: readonly string[] }   // inclusive; `sessions` filters by session id: the "This session" preset is every session of the automatic handoff chain (US-22.8), section 7.2

export const BUST_THRESHOLD = 10_000                             // strict: cc > 10_000
export const TTL_MS = { '5m': 300_000, '1h': 3_600_000 } as const

export type Classified = Call & { first: boolean; bust: boolean; base: 'first' | 'modelSwitch' | 'compaction' | 'unexplained'; attribution?: 'ttlLapse' | 'prefixChange' | 'unknown' }
export function classify(calls: readonly Call[]): Classified[]    // over the WHOLE stream, never the window (AC-22.1.2)
export function labOf(all: readonly Classified[], priceOf: PriceOf, w: Window): CacheLab
export const cacheLab = (calls: readonly Call[], priceOf: PriceOf, w: Window): CacheLab => labOf(classify(calls), priceOf, w)
```

`cacheLab` is the highest seam that observes every number: F1, F2, F3 go in, the `CacheLab` value comes out, no reader, no UI.

### 5.1 `classify` (ITEM-070 first/bust, ITEM-071 attribution)

1. Group by `session + '|' + stream`; sort each group by `(at, order)`.
2. For call `i` of a group, `cur = g[i]`, `prev = g[i-1]`, `bp = g[i-2]`:
   - `first = i === 0`.
   - `bust = !first && cur.cc > BUST_THRESHOLD`.
   - `base`: first match wins: `first`; `modelSwitch` if `cur.model !== prev.model`; `compaction` if `isCompaction(bp, prev)`; else `unexplained`.
   - `attribution` only for a bust, in this order (the stories' *Terms*, Miss attribution; CL M1): (1) `base === 'modelSwitch'` -> `unknown` (the cache is per model, so no gap explains it); (2) represented TTLs = `5m` when `cc5m > 0`, `1h` when `cc1h > 0`; none represented -> `unknown`; (3) gap = `cur.at - prev.at`; gap > every represented TTL's `TTL_MS` -> `ttlLapse`, **for base `compaction` and `unexplained` alike** (a compaction bust after a lapse is a lapse); (4) gap <= every represented TTL: base `compaction` -> `unknown` ("Unknown only within the TTL"), base `unexplained` -> `prefixChange`; (5) anything else (two represented TTLs with a gap between 5m and 1h) -> `unknown`. F4 (1m gap, ratio 0.6) stays Unknown through rule (4); the new AC-22.3.6 row of ra-fix3 (compaction, 8m gap, a 5m write) is `ttlLapse` through rule (3).
3. **`isCompaction(bp, prev)` (Q-CL2 answer, section 9):** `bp !== undefined && prev !== undefined && bp.cr > 0 && Math.max(0, (bp.cr - prev.cr) / bp.cr) > 0.5`. Accepted by the human (Q-CL2). It reads the cache-read of the **two calls before** the one classified, never the call itself and never the context size.

### 5.2 `labOf` (every metric)

Let `W` = classified calls of the window (`from <= at <= to`, and `session` in `sessions` when given). Prices per call: `p = priceOf(c.model)`.

| Metric | Computation | Notes |
|---|---|---|
| Saved by cache | `Σ c.cr × (p.input − p.cacheRead) / 1e6` over `c ∈ W` with `c.cr > 0` and `p.input`, `p.cacheRead` non-null | claude-lens formula (uncached cost minus actual; writes and output cancel). F1 (rev 2): 52,000 × 2.70 / 1e6 = 0.1404, shown `$0.14` (AC-22.2.2). |
| Write rate of a part | `5m` part: `cacheWrite5m`; `1h` part: `cacheWrite1h`; remainder `cc − cc5m − cc1h` (or all of `cc` with no split): `cacheWrite5m` (Q-CL1 default) | If the needed rate is null the call is unpriced for Lost. |
| Lost to busts | `Σ over busts b ∈ W: ( cc5m × max(w5 − p.cacheRead, 0) + cc1h × max(w1 − p.cacheRead, 0) + rest × max(w5 − p.cacheRead, 0) ) / 1e6` | claude-lens formula with per-TTL rates. F1 (rev 2): A3 20,600 × 3.45 + A4 15,700 × 3.45 + A5 12,000 × 5.70 = 193,635, `$0.19` (AC-22.2.3). |
| NET | `Saved − Lost` | Shown negative with a leading minus. |
| `unpricedCalls` | the count of calls in `W` that contributed to neither figure because a needed price (or the model) is missing | F3: 1. Q-CL3 default: priced calls summed, the note `N call(s) with no price` shown. |
| Cache Hit % | `Σcr / (Σcr + Σcc + Σin) × 100`, all of `W`, one decimal; zero denominator gives `null` | Ours, token-weighted. F1 (rev 2): 52,000 / (52,000 + 145,800 + 700) = 26.2% (AC-22.2.5). |
| Tokens Saved | `Σcr` over `W` | A count, not dollars. |
| Bust events | count of busts in `W` | F1: 3. |
| Median baseline | per session: its baseline call = the first call of its `main` stream (sorted) with `cc > 0`; take the baselines whose call is in `W`; the true median of their `cc` (even count: mean of the two middle values); none -> `null` | Ours. F1: 20,000 / 10,000 / 60,000 -> 20k. B0 (sidechain) is not B's baseline. |
| Miss attribution | counts of `ttlLapse`, `prefixChange`, `unknown` over busts in `W` | Sum equals Bust events. |
| TTL mix | `m5 = Σcc5m`; `h1 = Σcc1h`; `unknown = Σ (hasSplit ? max(0, cc − cc5m − cc1h) : cc)`; `hasSplit` = `cc5m` or `cc1h` defined | `m5 + h1 + unknown = Σcc`. Percent = part / Σcc, one decimal, none when Σcc is 0. F1: 130,800 / 12,000 / 3,000. |
| Gallery | busts in `W`, newest first (Q-CL4), the first 50: rows `{ at, model, session, stream, attribution, cacheWrite: cc, lossUsd: number \| null, pid?, turn? }`; `total` = busts in `W`; `truncated = total > 50` | `lossUsd` is one bust's Lost term, `null` when unpriced. |

export type CacheLab = {

## 6. Prices and data access, ITEM-069 (Q-CL9)

- **File:** the `costingPath` setting (default `.ai-dlc/model-metadata.json`), loaded by the lens's existing `loadCosting` (`register.tsx:659`) into a `Costing`. No new path logic.
- **`priceOf`** is built in `register.tsx` from that `Costing`: `parseCosting` once per load, then `(model) => { const f = lookupModel(json, model); return f ? { input: f.input, output: f.output, cacheRead: f.cacheRead, cacheWrite5m: f.cacheWrite5m, cacheWrite1h: f.cacheWrite1h } : null }`. `lookupModel` (`lens.ts:279`) matches by lower case with `[1m]` and a trailing `-YYYYMMDD` dropped, against `id` and `aliases`: unchanged, so Cache Lab and the existing cost figures agree on which model is which. `lens.ts:197` already has the `Prices` type; `cache-lab.ts` re-exports it rather than redefining.
- **Long-context tiers:** not applied (Q-CL8 default). `factsOf`'s `long` pricing is ignored here; the accordion notes `base prices` under the figures.
- **Transcript folder (architect constraint 4, ADR-0006):** `register.tsx` registers `classic.SessionStart` (first), `classic.Stop` and `classic.UserPromptSubmit` observers that call `noteTranscript(e.transcript_path)`, which stores `folder = path.slice(0, lastSeparator)` in module memory (both `\` and `/` separators). Each handler only calls `next(e)` after. Until a path is seen the accordion shows `transcripts not located yet`. Sidechains are at `<folder>/<session>/subagents/agent-<id>.jsonl` (the reader walks that shape; the build confirms it on a real folder).

## 7. The accordion (ITEMS 070 to 072), and the load

### 7.1 Load (the only I/O), `loadLab($)` in `register.tsx`

1. Only when the Cache Lab accordion is **open** (the figures are never computed while it is collapsed; the header carries no number). Key: `lens:cachelab` through the existing `section`/`isOpen`/`toggleOpen` helpers.
2. `list` (with `--since` = the window start, none for `All`), then batches of `read` for the files `FileCache` lacks (by `(rel, size, mtimeMs)`), following `data.next`. Order of reading: newest first.
3. `mergeCalls` over the cached records of the listed files; `classify` memoised on the merged-call version; `labOf` on `(version, window, price file text)`.
4. State goes to an atom (`cacheLabA`: `{ status: 'idle' | 'loading' | 'ready' | 'error', lab?, reason?, skipped }`), set by `loadLab`; the pane renders from the atom, so a long read shows `reading transcripts...` and never blocks a draw. `loadLab` runs once per open and per window change, and again when a Stop/turn arrives (new files) only while the accordion is open; a running load is not started twice.
5. Skipped lines: one debug log line `cachelab: skipped N lines in M files`. No banner (AC-22.1.4).

### 7.2 Window (L7 / Q-CL11, accepted 2026-10-25)

`WINDOWS = ['session', 'today', '7d', '30d', 'all']`, default `7d`, held per the persistence switch below. A row of Buttons in the accordion header (`This session`, `Today`, `7d`, `30d`, `All`; the active one marked), each `onPress` setting the atom and calling `loadLab`. The presets read **This session / Today / 7d / 30d / All**, default `7d`; the choice is kept for the session (module memory by default, `$.store` when the switch is on, below) and never written to a file (the new AC-22.2.12, ids by the analyst, is its test: five presets exist, `7d` is the default, a press recomputes, a later open of the accordion in the same session keeps the choice). `windowOf(preset, now, chainSessions)` (pure, in `cache-lab.ts`): `session` -> `{ from: 0, to: Infinity, sessions: chainSessions }` (the sessions of the chain, below); `today` -> local midnight; `7d`, `30d` -> `now − n days`; `all` -> `{ from: 0, to: Infinity }`. The pure function takes any `Window`, so AC-22.2.9 (10:05 to 11:30) is a function-level test; the UI offers the presets only.

**Persistence switch (Q-CL19, human 2026-10-25; architect 17.1.26 form).** The setting `cacheLabKeepWindowOnReload` (bool, default `false`; env `AI_DLC_LENS_CACHE_LAB_KEEP_WINDOW_ON_RELOAD`) is a normal `SPEC` entry of `hooks/settings.ts`, resolved by the lens's existing loader and precedence (settings files and `env`), so `register.tsx` reads it as `settings.cacheLabKeepWindowOnReload` and never touches `process.env`. It is read where `loadLab` runs and handed to a `WindowStore`, a two-function seam (`get(chainId): Window preset`, `set(chainId, preset)`) with two implementations. **Off (the default, the production behaviour): `memoryWindowStore`**, a module-level variable reset by `/reload-plugins`; `$.store` is not read or written, and any stale entry from an earlier run with the setting on is ignored. **On: `storeWindowStore($.store)`**: key `lens:cachelab:window` holding a list of `[chainId, preset]` pairs (rev 4: keyed by the chain, US-22.8, so an automatic handoff keeps the choice and a session started by hand does not) (the shape of keepalive's `sessionOverrides`), bounded by the constant `WINDOW_SESSIONS_MAX = 20` (keepalive's `sessionOverridesMax` default; the lens cannot import that setting, so it is a lens constant, oldest dropped first with `.slice(-WINDOW_SESSIONS_MAX)`). Each preset press writes `[chainId, preset]`; module start (and each `loadLab` after a reload) restores the entry for the current chain id. An absent entry, a new chain (a session started by hand) or a value not in `WINDOWS` gives `7d`. **The chain choice survives an automatic handoff whatever the switch says** (AC-22.8.2): the memory store is keyed by the chain id too and is not reset by a handoff (only `/reload-plugins` resets it), so the switch still governs only a reload. The setting is the only place the choice is made. Tests: pure over `windowOf` as before; the two stores over an in-memory `$.store` stub (a handoff keeps the choice under the same chain id and a hand-started chain reads `7d`, AC-22.8.2 and 8.3; set, then a fresh store instance reads it back: kept with the store, lost with memory; a stale entry ignored when off; the bound drops the oldest; an invalid value reads `7d`); the settings entry parses `true`/`false` and rejects other text through the loader's existing bool rules, and the README table pin in `lens.test.tsx` (it pins `SPEC` keys) gains the row. AC-22.2.13 (analyst, 17.1.25) is the behaviour test: setting off, `/reload-plugins` resets the window to `7d`; setting on, the window survives a reload; a new session starts at `7d` either way. Which of the two sources is first at module start (a first publish happens at the first keep-alive event with a session id) is build-verified; the design is right either way. **The race (CL m8): a press made before the published chain arrives.** The press saves its preset under the id `chainNow()` gave at that moment (the transcript session id) and marks the store entry `pressed`. When the id then changes to the published chain's id, `restoreWindow` runs, and **the press wins**: if `pressed` is set, the pressed preset is re-saved under the new chain id and shown, and the new id's stored value is not read; if not, the new id's stored value is restored. No press is lost; a value stored earlier under the chain id is overwritten by the press, which is the later intent. Test: press, then the chain publishes with a stored value for the new id: the pressed preset shows and is stored under the new id.
- *`This session` window.* `windowOf('session', now, chainNow().sessions)`. The reader needs no new mode: its `list` already returns every transcript of the folder and the lens filters calls by `session` in `sessions` (a chain's sessions share the project folder; a session in another folder is a limit, listed in section 13). A failed lineage read makes the chain the session itself (keepalive LLD 19.1; AC-22.8.3), with one debug line from `chainIdOf`.
- *Test seams.* `windowOf` with a chain of two sessions (pure); `chainNow` over the three states (published, transcript only, unknown); render test of AC-22.8.1 (F6 and F6h), AC-22.8.2 (`WindowStore` keyed by chain id across two session ids), AC-22.8.3 (hand-started; failed read).

## 8. AC-22.4.6 (the turn link) designed to the fallback

## 9. Answers to the open questions

## 13. Risks

- The transcript fields are undocumented (ADR-0006): `message.id`, `message.usage`, `cache_creation.*`, `isSidechain`, `subagents/` layout. Reader tests pin today's shape; a change shows as zero calls and a reason, not as wrong figures.
- First open over every transcript (about 750 MB here) takes seconds; the pane shows `reading transcripts...`. Window default `7d` and the mtime skip bound it.
- `$.process.run` argument length on Windows: batches of 80 names; a test builds the longest batch.
- Dedupe by `message.id` across files assumes a resumed session copies rows with the same id; a different cause of cross-file repeats would be dropped silently. The reader test covers the assumed case only.
- F1's attribution changed under the exact compaction rule (section 9); the stories carry the revision (done in rev 2 and 3), the build reads them.
- A chain whose sessions live in different project folders (a `cwd` change between sessions) is not read by `This session`: the reader lists one folder (section 6). Accepted; the chain's own folder is the normal case.
- The `chain` published state field is a cross-plugin contract kept by two copies of one type (the lens keeps its own, as for the other fields); a test on each side pins the shape.
