## Terms (added)

- **Off line**: a track line whose keep-alive part starts with `off` (any reason of `stories.md` US-17.2, `off (disabled)` and `off in overage` included).
- **Keep-warm text** (rev 4.3, decision 9): the clause `keep warm <d> (<source>)`, on every line that has a keep-warm clause, running lines and off lines alike. `<d>` is the keep-warm time in force (published `keepWarmMs`), written as today. `<source>` is the **source note**, the level that gave `<d>`, exactly one of: `session` (a `/ai-dlc:cache-keepalive --session` override for that track, set in this session or carried along its automatic handoff chain), `machine` (a `/ai-dlc:cache-keepalive --machine` override), `settings` (a settings file: `.ai-dlc/cache-keepalive.json`, or an `AI_DLC_KEEPALIVE_*` variable in the `env` of `.claude/settings.json` or `.claude/settings.local.json`), `default` (no level sets it). The published track entry carries the same label as `keepWarmFrom`. The `/ai-dlc:cache-keepalive` report keeps its longer source text. The note is shown by default and turned off by the setting `sourceNote` / `AI_DLC_KEEPALIVE_SOURCE_NOTE` (boolean, default `true`, not trust-gated): with `false` the clause is `keep warm <d>` with no ` (<source>)` on any line, `keepWarmFrom` is still published and the report is unchanged (follow-up 17.1.30.l1.1; AC-17.6.35).
- **Nothing allowed** (rev 4.3): neither track is enabled for this session (below), so neither may arm.
- **Chain id** (rev 4.3, decision 10): the session id of the first session of an automatic handoff chain (auto-handoff's `lineage:<session id>` record in `$.store`, field `chain`, written before the seed prompt). A session started by hand, or whose lineage record cannot be read, is its own chain (chain id = its own session id). "This session" in the terms below means this chain when `handoff.carryOver` is on (the default), and this session alone when it is off (US-17.7).
- **Running track**: a track with a ping scheduled (published `running: true`): armed, or pinging. Every other track is **not running** (off lines and stopped lines).
- **Button** (rev 4.2, Q-SL8): `[off]` beside a track that is **allowed** to arm, that is, enabled for this session (below; the spec's D5 check), running or not; `[on]` beside a track that is not allowed (its line reads `off (disabled)`). Whether the track is running never changes its button.
- **Session switch** (per track): a per-track value, `on`, `off` or unset, that lasts for this session only and is above every settings level for the track's `enabled`, as the `/ai-dlc:cache-keepalive --session` override is for the keep-warm time. Unset at session start. Set by the track's button; set to `on` for both tracks by the master `[on]`; cleared for both tracks by the master `[off]`.
- **Master switch**: one value for keep-alive as a whole, `on`, `off` or unset, this session only, above every settings level for the master `enabled` (settings files and `AI_DLC_KEEPALIVE_*` variables). Unset at session start. Set by the master button.
- **Master in force**: the master switch when set, else the master `enabled` the settings give (default `true`).
- **Track enabled for this session**, decided in this order, first match wins:
  1. the track's session switch is `on` → enabled (it overrides a master that is off, by the master switch or by the settings' `enabled: false`, and the track's own `<track>.enabled: false`);
  2. the track's session switch is `off` → disabled;
  3. the master in force is off → disabled;
  4. else as the settings give the track's `<track>.enabled`.
  An enabled track arms only as rev 3 D5 says (Q-SL1); a disabled track never arms, and its line reads `off (disabled)`.
- **Master button**: on the title row; `[off]` when the master in force is on, `[on]` when it is off. It depends on the master alone, never on the tracks.
- **Band**: the AbovePrompt band (Terminal, Desktop). **Pane**: the keep-alive Pane (VS Code).
- **Full text** (rev 4.4): the track lines (1h, then 5m) and, while it shows, the `keepalive seed: …` line, exactly as the E-strings and rev 3 give them (off-line suffix and source note included). The published `line` of each track is its full line; the band and Pane rows show the full lines; the status line shows the full text, joined with a newline, only in *full mode*.
- **Summary** (rev 4.4): one line, no newline, `keepalive <1h token> | <5m token>[ | <seed token>]`, built from the same track state as the full text, with the tokens of AC-17.6.37 and the length rule of AC-17.6.38. `<H:MM>` is a clock time written as the full line writes its clock times. Display only: nothing new is published.
- **Status mode** (rev 4.4): which text the status line shows, `full` or `summary`, decided by `statusText` (AC-17.6.41): `full` → full mode; `summary` → summary mode; `auto` (default) → the surface rule (AC-17.6.39).
- **Surface roster** (rev 4.4): the surfaces the session is drawn on, as the host lists them (`$.session.surfaces()`; spec delta D13).

### US-17.7 An automatic handoff chain is one keep-alive session (ITEM-076, T17.7; rev 4.3)

As a developer whose session is handed off automatically when its context runs out, I want keep-alive to carry on as if it were the same session — my switches, my keep-warm overrides, and the cache prefix untouched — and to come back on if it was off, so that the handoff does not undo what I set or lose the cache.

*The human, 2026-10-25 (decision 10). Settings (spec; keys in `.ai-dlc/cache-keepalive.json`, variables in a settings file's `env`, listed by `/ai-dlc:cache-keepalive-configure`):*

| Key | Variable | Default | Trust-gated | What it does |
|---|---|---|---|---|
| `handoff.carryOver` | `AI_DLC_KEEPALIVE_HANDOFF_CARRY_OVER` | `true` | no | `true`: the master switch, both track switches and the `--session` keep-warm overrides are kept per chain id, so a session seeded by an automatic handoff sees them as they were. `false`: they are kept per session id, so a seeded session starts clean, like one started by hand. |
