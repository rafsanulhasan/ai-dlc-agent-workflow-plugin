The `warm until` time is the local-clock expiry of the cache, assumed to be 1 hour after the last successful ping (or after arming), and `keep warm 8h` is a separate stop threshold for the ping loop that measures from arming, with no effect on the cache itself.

Findings (paths relative to `plugins/claude-mods/cache-keepalive/`):

- **Source of the status line:** the `armed` line is emitted in `classic.Stop` when background tasks exist: `hooks/register.ts:215-228`. `N task(s)` is `e.background_tasks.length` at that moment (`:228`), a snapshot. Nothing updates it, and the mod never observes task completion. A task finishing wakes the session, and that new turn's `turn.start` calls `stop()` (`:208-210`).
- **`armed`:** the Stop hook has set the stop-timer (`arm`, `:229`) and no ping has run yet. The status is set at `:228` and is replaced by `warm until ...` after the first successful ping (`:172`).
- **TTL and "warm until" at arming:** `TTL_MS = 60 * 60_000` (1 hour) at `:10`, and at arming `warmUntil = armedTime + TTL_MS` (`:224-226`). So at arming the displayed time is 1 hour from Stop, not 5 minutes.
- **Rolling update on each ping:** after a ping returns a hit, `warmUntil = now + TTL_MS` (`:169`), and the status is re-rendered with that time (`:172`). The time is therefore last successful ping + 1 hour. Formatting is `getHours():getMinutes()` on the local clock (`:66-68`).
- **Ping cadence:** `PING_EVERY_MS = 50 * 60_000` (`:9`), so each ping lands 10 minutes before the assumed 1-hour expiry. Pings are armed by `arm()` (`:150-187`), and the timer re-arms itself after every successful ping (`:173`).
- **`keep warm 8h` source:** `keepWarm()` resolves the value in this order: this session's `/keepalive` override, then the machine-wide override, then the `/config` value (`:47-54`). The `/config` default is `8h` (`plugin.json:15-19`) and the fallback constant is `DEFAULT_KEEP_WARM = '8h'` (`duration.ts:7-8`). The setting is `keepWarmFor` and the `/keepalive` command sets it (`register.ts:245-252`).
- **What `keep warm 8h` means:** a wall-clock budget counted from arming, not from the last ping. Each timer tick compares `now - armedTime` against `keep.ms` (`:163`). If the budget is spent, the timer stops with `keepalive: kept warm 8h, stopped, warm until ...` (or `no ping needed for` when no ping ran; `:163`). It stops the pinging only and does not extend or shorten `warmUntil`.
- **Loop as a whole:** tick every 50 minutes (`:153`) → if the cache is already expired, stop (`:159`) → if the keep budget is spent, stop without pinging (`:163`) → ping with a forked one-line request (`:165`) → on a miss, stop (`:168`) → on a hit, extend `warmUntil` (`:169`) → if the token budget is spent, stop, or compact if `compactOnCap` and it pays (`:171-180`) → otherwise re-arm (`:173`).
- **Arithmetic for 8h:** ticks at 50, 100, …, 450 minutes ping (9 pings). The tick at 500 minutes sees `500 >= 480` and stops (`:163`). The last ping at 450 minutes leaves the cache warm until 510. This matches the "about nine pings" note at `README.md:48`.
- **Token budget (separate from time):** `budget = 2 × context tokens` set at arming (`:223`), and each ping adds to `spent` (`:102`, `:171`). It can stop the loop before the 8h budget does; `README.md:48` notes this too.
- **Duration rules:** `parseDuration` accepts `<n>m|h|d`, at least 1 minute, with fractions allowed (`duration.ts:13-19`). Durations of 50 minutes or less send no ping, because the first tick at 50 minutes already passes the budget (`register.ts:163`, `README.md:29`).
- **1h vs 5m caveat (code):** the mod assumes the 1-hour TTL and says so (`register.ts:7-8`). It cannot read the TTL, so it infers 5 minutes only through overage (`:218-219`). A 5-minute cache would make the 50-minute ping miss; the hit check is `hit > 0.9` (`:101-105`), so the miss stops the loop (`:168`), but only after one full re-cache has been paid.
- **1h vs 5m caveat (docs):** agent-team teammates use the 5-minute cache unless `subagentPromptCacheTtl` is `1h`, so their first ping misses and the pings stop (`README.md:50`). The mod cannot detect that bucket in advance.
- **Refresh-on-read assumption:** the claim that a cache read restarts the 1-hour lifetime is an inference by the mod's author, not a documented guarantee (`README.md:48`). The `warm until` display depends on it.
- **Sleep caveat:** a timer that fires late after machine sleep checks `now >= warmUntil` and stops rather than re-writing an expired cache (`register.ts:157-159`).
- **Mid-wait changes:** `keepWarm()` is re-read at each tick (`:160`, `:163`), so a `/keepalive` change takes effect at the next ping (`README.md:46`).
