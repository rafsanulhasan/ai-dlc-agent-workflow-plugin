Only the shared prefix (tools, system prompt, and CLAUDE.md/memory/git-snapshot project context) can hit on the seeded session's first request, and only if it is byte-identical to what the old session cached and a cache breakpoint sits at its boundary; the old conversation can never hit, and the handoff gap is too short for keep-alive pings to matter.

Findings:
- Exact prefix match, order tools → system → messages, up to the block with `cache_control`: https://platform.claude.com/docs/en/build-with-claude/prompt-caching ("Cache prefix order", "Exact matching").
- Cache writes happen only at breakpoints. The lookback is 20 blocks before a breakpoint, and it can only find entries earlier requests already wrote: same URL, "Lookback window".
- Changes at a level invalidate that level and everything after it, so a changed git snapshot, CLAUDE.md or memory invalidates everything behind it: https://code.claude.com/docs/en/prompt-caching ("How the cache is organized", "Cache scope").
- Old conversation is never reusable: /clear removes it, and the seed's messages are new (register.tsx:1019-1022, :1055-1057).
- Sequential sessions share the prefix only if the startup git status snapshot matches; the old session's edits or commits change the new snapshot (https://code.claude.com/docs/en/prompt-caching, "Cache scope").
- The brief is a plain `$.model.complete({model:'haiku'})` with its own system prompt, so it does not touch the old session's prefix (register.tsx:527-533). Gap = that call (60s timeout) + /clear + SessionStart, typically seconds, well inside 5m.
- Keep-alive pings are `$.model.fork` calls (register.ts:96). Forks inherit the parent's prefix, but they fall in the 5m "everything else" bucket (https://code.claude.com/docs/en/prompt-caching, "Which TTL each request gets"). The 1h assumption at register.ts:7-8 is therefore unverified for pings. Keep-alive arms only on Stop with background tasks (register.ts:215-216), so it is off in a seeded session.
- TTL: 5m default, refreshed on each hit at no cost; lifetime counts from request start; 1h writes cost 2x base input vs 1.25x for 5m; 1h entries must precede 5m entries in a prompt (https://platform.claude.com/docs/en/build-with-claude/prompt-caching, "Pricing", "Mixed TTLs").
- Main conversation gets 1h by default on a subscription within plan usage, else 5m; `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL` set it (https://code.claude.com/docs/en/prompt-caching, "Choose the TTL yourself").
- Verification fields: `usage.cache_read_input_tokens`, `cache_creation_input_tokens`, `input_tokens`, and `cache_creation.ephemeral_1h/5m_input_tokens` (platform prompt-caching page, "Usage fields"). The module already reads the seed turn's usage to set the floor (register.tsx:928-930), so the cache split can be logged there with no new call.
- Compaction keeps the system and project-context layers cached and rebuilds only the conversation layer (https://code.claude.com/docs/en/prompt-caching, "Compacting the conversation"). This is an alternative to /clear, not a tweak to it.
- Confidence: High on the API rules (exact prefix, breakpoint-only writes, lookback, TTL refresh and pricing). Medium on whether Claude Code places a breakpoint at the project-context boundary; the docs imply sequential sessions share it, but do not state the placement. Low on whether a 5m fork read shortens a 1h entry.

Recommended design (for planning; no edits made):
- Do not fold keep-alive into the handoff path. The handoff gap is seconds; pings only help long idle gaps, and the old-session timers survive /clear (prior research, register.ts:18), so they would ping the wrong session.
- Keep the model and effort identical across the clear; a model switch means zero hits (https://code.claude.com/docs/en/prompt-caching, "Switching models").
- Put only the seed and session-handoff text in messages, never in CLAUDE.md, memory or the system prompt, so the stable prefix is unchanged.
- Before /clear, avoid touching CLAUDE.md, memory or tracked files if the cache matters; the git snapshot will differ otherwise.
- At the seed turn, log `input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` and the 1h/5m split next to the existing floor line (register.tsx:930). A zero read with a fresh write means the prefix missed.
- If you want per-request TTL evidence, run `claude -p "hello" --output-format json` on the target setup and read `usage.cache_creation` (https://code.claude.com/docs/en/prompt-caching, "Choose the TTL yourself").
- Set expectations: the gain is capped at system + tools + project context, which is small next to the thresholded context the handoff discards. Do not promise the old conversation is reused.
