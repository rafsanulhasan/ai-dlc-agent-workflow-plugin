# Brief: temporary status-line probe

Goal: capture what Claude Code sends to the status-line command, to read `context_window.context_window_size` (and `used_percentage`, `total_input_tokens`, `exceeds_200k_tokens`, `model`) for a live session. Docs: https://code.claude.com/docs/en/statusline.

Constraints:
- The user's status line is claudemeter (configured at user level, likely `~/.claude/settings.json` `statusLine`). The probe must keep it working: read stdin, save it, then pipe the same stdin to the existing status-line command and pass its stdout through. Read the existing command; do not modify `~/.claude/settings.json`.
- Put the probe in the gitignored `.claude/settings.local.json` (`statusLine`, which overrides user settings) — never in `.claude/settings.json` (it has the user's uncommitted changes). Merge with existing content of settings.local.json; keep everything else.
- Script at `.scratch/window-probe/statusline-probe.mjs` (Node, no deps). Writes the latest payload to `.scratch/window-probe/latest.json` and appends one compact line per refresh to `.scratch/window-probe/history.jsonl` (keep at most ~200 lines). Never fails the status line: any error falls through to the original command.
- Write `.scratch/window-probe/README.md`: what it does and exactly how to remove it (the settings.local.json key to delete or restore).
- Test it locally by piping a sample JSON into the script and showing the output and the saved file.
