- Interval: PING_EVERY_MS = 50 min (register.ts:7). TTL_MS = 60 min (:8). Comment at :5-6 says the mod assumes the 1h TTL and infers 5m only from overage.

2. Duration and limits (register.ts)
- No maximum idle time and no ping count. The chain continues while each ping hits and the budget is not spent.
- Budget: set at each classic.Stop as WRITE_MULT * context tokens (:166-167), i.e. 2x the context in token-equivalents. spent resets to 0 there (:166).
- Cost per ping: readMult * cache_read + input + 2 * cache_creation + 5 * output (:50-53, accumulated at :62).
- Stop conditions:
  - budget spent, unless compactOnCap and compaction pays (:126-131);
  - ping misses, where ok = hit > 0.9 (:64-65, :124). Note: 0.9 is already a hit-rate threshold;
  - warm window expired before the timer fires (:119);
  - rate-limit window at 100% (:161-163, and session.measure at :176-179);
  - new turn starts (:152-154).
- No cost cap beyond the 2x-context budget. No duration of background tasks is read (open question).

4. Prompt-cache TTL (Anthropic docs)
- Source: https://platform.claude.com/docs/en/build-with-claude/prompt-caching (fetched this session).
- Default TTL is 5 minutes. A 1-hour TTL is an option via cache_control "ttl": "1h". The doc does not give an extra TTL-selection field beyond that.
- Write prices: 5m write = 1.25x base input; 1h write = 2x base input. Matches WRITE_MULT = 2 in the code, which assumes 1h.
- Cache read = 0.1x base input, with per-model exceptions: 0.025x for Fable 5.1 and Mythos 5.1; 0.05x for Opus 5.5 and Sonnet 5.5. readMult (register.ts:32-35) matches these.
- Refresh: the doc says the cache "is refreshed for no additional cost each time the cached content is used", and that the lifetime is measured from the start of the request that writes or reads the entry. The doc states this in the default-TTL paragraph. It does not restate it for the 1h TTL separately. A WebSearch returned only third-party sources, which were inconclusive for 1h refresh.
