**Q1. Can a teammate be handed off to a fresh context?**
- Only by lead-driven steps. Documented: a teammate is shut down by asking the lead ("Ask the researcher teammate to shut down"), and a stuck teammate is replaced with "Spawn a replacement teammate to continue the work" (https://code.claude.com/docs/en/agent-teams, sections "Shut down teammates", "Agents stopping early"). A replacement gets the lead's spawn prompt only; "The lead's conversation history does not carry over" (agent-teams, "Context and communication").
- No documented mod or hook API ends a teammate. `$.agent` exposes `register`, `spawn`, `list` only; `list()` returns each teammate's `status` (https://code.claude.com/docs/en/plugins/mods/reference, "Mods API methods"). `$.agent.spawn` is documented and an `agent.spawn` hook sees `e.isTeammate` (reference, "Subagents"), but the docs do not say that `spawn` creates a teammate rather than a subagent.
- `/clear`, `/compact`, `/rewind` typed in a teammate view act on the lead's conversation (agent-teams, "Talk to teammates directly"). So the existing /clear mechanism cannot reset a teammate.
- In-process teammates can get automatic compaction via a subagent definition's `autoCompactWindow` (100000 to 1000000), v2.1.296+ (agent-teams, "Use subagent definitions for teammates"). Split-pane ignores it.
- Verdict: a teammate can be replaced by a lead-issued shutdown plus a new spawn with a brief. No automated handoff path is documented for one. Only the lead or main session can be handed off automatically.
