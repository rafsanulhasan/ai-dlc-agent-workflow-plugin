## Design (decided by the human on 2026-10-22; binding; replaces round 1's design)
1. **Both properties live on the step's loop.** Every stage `loop` has `maxRounds` (integer ≥ 1) and `maxFailures` (integer ≥ 0), next to `to` and `on`. The template sets both explicitly on **every** loop, as in the human's example:
   ```json
   "loop": { "to": "change", "on": "…", "maxRounds": 1, "maxFailures": 0 }
   ```
   `clarify` gets the same pair: `"clarify": { "maxRounds": 2, "maxFailures": 1, "matrix": … }` (the human's values).
2. **Remove** round 1's `review.maxRounds` and `AI_DLC_REVIEW_ROUNDS` everywhere: schema, `workflow.mjs`, template, docs and tests. `review` goes back to `axes` only.
3. **Defaults when a loop omits a property** (hand-written or old files): `maxRounds` 1, `maxFailures` 0. Old files with only `maxRounds` stay valid.
4. **Meaning.**
   - `maxRounds`: the most review passes the step may run.
   - `maxFailures`: how many failing verdicts **that reviewer** may return before the loop stops and escalates, even if rounds are left.
   - Failing verdicts by reviewer:
     - brutal-critique: REVISE, or Majors on a PASS
     - sqa-engineer: a test that fails because the code is wrong
     - code-reviewer: a Blocker or Warning
     - any other loop: its `on` condition
   - **Rule:** `maxFailures < maxRounds`. With `maxRounds` 1, `maxFailures` must be 0. A file value that breaks the rule is a `validate` **error**.
5. **The human always decides on open Blockers.** When a loop stops (its failures used up, or its rounds spent) with findings open, the orchestrator asks the human, once, whether to fix them (one more round) or stop / accept. Blockers never pass to real work without that decision. State this in `aaw-review.md` and `SKILL.md`. The orchestrator's own wording is WI-2, so just make the rule clear here.
6. **AAW "all three must be equal" rule: drop it.** Each reviewer step has its own pair now. Update the schema, `workflow.mjs`, `aaw-review.md`, `edit-recipes.md` and the tests. This also resolves the spec-axis Warning (3/1/1 split): per-reviewer limits are now intended.
7. **Environment variables: exactly three explicit pairs**, one per reviewer kind, matched by the loop stage's `agent`:

   | Reviewer (stage agent) | Rounds | Failures |
   |---|---|---|
   | `brutal-critique` | `AI_DLC_CRITIQUE_MAX_ROUNDS` | `AI_DLC_CRITIQUE_MAX_FAILURES` |
   | `sqa-engineer` | `AI_DLC_TEST_MAX_ROUNDS` | `AI_DLC_TEST_MAX_FAILURES` |
   | `code-reviewer` | `AI_DLC_CODE_REVIEW_MAX_ROUNDS` | `AI_DLC_CODE_REVIEW_MAX_FAILURES` |

   - Each env value overrides that property on **every** loop whose stage agent is that reviewer, in every lifecycle (AAW, FDLC, BFLC, RLC, TLC, CRLC …).
   - Loops owned by other agents (product-owner accept, software-architect architecture-review) and `clarify` are file-only.
   - **Precedence per property:** valid env → the loop's value → default.
   - **Validity:** ROUNDS must be a whole number ≥ 1; FAILURES a whole number ≥ 0. Use one stated rule, e.g. `^\s*(0|[1-9][0-9]*)\s*$` within the safe-integer range, so `007`, `00`, `+2`, `1e3`, `0x2` are rejected. Document the rule in `SKILL.md`, and pin `007` in a test.
   - Unset or blank means not set, with no warning.
   - Invalid → ignored, one stderr warning naming the variable, JSON value used. Never an error, exit code unchanged (the human's rule from round 1, still binding).
   - **Combined check after env:** if the effective `maxFailures` ≥ the effective `maxRounds`, the env value(s) that caused it are ignored with a warning, and the loop's file values are used.
8. **`rounds [--json]`** reports per loop: lifecycle/stage, agent, to, `maxRounds` + source, `maxFailures` + source (`env` / `loop` / `default`), plus a `clarify` row. `show` prints both per loop (e.g. `x1 f0`).
9. **Upgrade (Mode: upgrade):**
   - add `maxFailures` (0, or `maxRounds`−1 when that is lower) next to each existing `maxRounds`
   - add `maxRounds` 1 / `maxFailures` 0 to loops that have none, and say plainly that these loops were unbounded before and are now capped
   - say that kept explicit values (e.g. old AAW `3`s) keep their rounds
   - remove `review.maxRounds` if present
