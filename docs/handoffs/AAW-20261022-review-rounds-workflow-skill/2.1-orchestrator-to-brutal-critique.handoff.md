# 2.1 orchestrator → brutal-critique: critique the docs of the configurable-review-rounds change

## Goal
AAW used to run up to 3 review rounds, and every other review loop had no limit. Review rounds are now a project setting with a default of 1. Critique the **docs** paths of this change against that intent, and return PASS or REVISE.

## Request (the human's words)
"I found that there is always 3 rounds of review and bc critique which in token consuming. keep it as configurable as the plugin can read how many reviews would take place from an environment variable or through ai-dlc:init."

## Intent (decided with the human; binding)
- **Setting:** `review.maxRounds` in `workflow.json`. It is optional, an integer ≥ 1, and the default is 1.
- **Precedence for each loop's limit:** env `AI_DLC_REVIEW_ROUNDS` → `loop.maxRounds` → `review.maxRounds` → 1.
- **Env var:** it counts only when it is a whole number > 0. Unset or empty means not set. Any other value is ignored with a one-line warning, never an error, and the JSON value is used.
- **Scope:** all review loops. `clarify.maxRounds` is not covered.
- **Meaning of N:** 1 review + up to N−1 fix passes; then the human decides.
- **AAW:** the three review loops share one budget. Explicit values there must be equal, but they are no longer required.
- **New command:** `rounds [--json]` prints each loop's effective limit and its source.
- This item covers only the `workflow` skill. Init, orchestrator, ai-dlc and README wording are WI-2 (out of scope here).
