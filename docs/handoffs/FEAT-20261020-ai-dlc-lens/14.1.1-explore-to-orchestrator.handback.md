**4. Cache**
- Usage section (register.tsx:1790-1803) shows:
  - Input = in + cr + cw (1793)
  - Cache read `sum.cr` (1795), Cache write `sum.cw` (1796), Uncached `sum.in` (1797)
  - Cost from `costOfAgent` (lens.ts:406, called at register.tsx:1773), using `priceAt` (lens.ts:311) and the `cacheWriteRate` setting.
- There are no cache hit or miss counts anywhere in the lens. The only hit/miss text is ai-dlc's seed line (`keepalive seed: cache hit/miss`, keepalive README:29).
- Saved: `savingsOfAgent` (lens.ts:1753) computes cr × (input price − cache-read price). `sessionSavings` is at lens.ts:1778. The cache-write premium is not subtracted (lens.ts:1751).
- Keep-alive section: `keepaliveSection` (register.tsx:1716) and `keepaliveFigures` (register.tsx:1208). `keptWarm` (lens.ts:1712) lists the 5m track first, then 1h (`KEEPALIVE_TRACKS` at lens.ts:1659).
- Reading keep-alive state:
  - `KEEPALIVE = { plugin:'ai-dlc', key:'keepalive' }` at register.tsx:1140, read via `$.state.get` at register.tsx:1152 and 1175.
  - Armings are captured into the lens's own `kaCyclesA` atom (register.tsx:246) by `captureKeepalive` (register.tsx:1190) and `noteKeepalive` (lens.ts:1673).
  - The pane line comes from `keepaliveLine` (lens.ts:1640), which returns null unless `enabled` is true and at least one track has `running:true`.
- The status line is ai-dlc's, not the lens's. It is rendered by `render()` at plugins/claude/ai-dlc/hooks/keepalive/keepalive.ts:181-184 through `$.ui.status`, and the state is published at keepalive.ts:170-176.
- Why the 5m track shows "off". Every track starts as `keepalive 5m: off` (keepalive.ts:52), and each new turn resets it to that (keepalive.ts:635). It only arms in `classic.Stop` (keepalive.ts:654-697), and only if all of these hold:
  - the Stop has background tasks; otherwise it returns early (keepalive.ts:658)
  - the track is enabled (688)
  - a cache split is known (689)
  - `split['5m'] > 0`; otherwise it sets plain `off` (690)
- The split is the 1h/5m `cache_creation` breakdown of the last cache write: `creationSplit` at plugins/claude/ai-dlc/hooks/auto-handoff/config.ts:385. It is fed only by main-loop responses (`noteUsage`, plugins/claude/ai-dlc/hooks/auto-handoff/register.tsx:881-883, `!e.agentId`) or by the transcript.
- So if the main conversation's cache writes are all 1h, or a turn ends without background tasks, the 5m track stays "off". Separately, `status:false` hides the lines (keepalive.ts:183). The README confirms the rule at plugins/claude/ai-dlc/hooks/keepalive/README.md:18 and 36.
