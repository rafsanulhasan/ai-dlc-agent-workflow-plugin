**Can a command know the session's own surface (R44.23)?** Yes, through the session's surface list:
- **The command event carries no surface.** `command.run`'s input (CommandRunInput, d.ts:1828-1857) has only `command`, `args`, `origin` and `presentation`. `presentation` (d.ts:1797-1811) holds only the terminal layout and its width.
- **`$.session.surfaces()` (d.ts:2864-2875)** returns "`terminal` under the REPL first, then the remote ones in the order they attached". `session.start`'s `surface` (d.ts:12309-12312) is the same first entry, null for `-p` or the SDK.
- **So the session's own surface is the first entry of that list.** For a terminal session this is documented.
- **Desktop and VS Code are an inference:** a Desktop or VS Code session's own client is assumed to be the first remote surface to attach. d.ts states only the order, not that the host client attaches first. M34 asks for a live check of the Desktop case.
- **Other options, if you prefer:**
  - Store `session.start`'s `surface`. It covers only the terminal case; it is null for Desktop and VS Code.
  - Use the button press's `e.surface` (UiPressArgument, d.ts:15167-15171) for the mode button. That is the surface the press came from, not the session's own, so I did not use it.
