That is your build-done, reviews-pending case, and the rule answers it two opposite ways:
   - Lines 26 and 37 say "the stage that built it is `done`" means no marker.
   - Line 49 says a backlog status of Review means *in progress*.
   - Line 37 also requires the backlog item to be Done.
   - Line 51 says the run state wins when the two disagree, so a done build stage with backlog Review gives "done", and the backlog Review clause is dead.
   - In default FDLC the documentation-writer stage runs in parallel with sqa-engineer, after the build stage and before code-reviewer (`documentation-writer.md:128`). Under the literal rule it always writes "shipped, no marker" before any review passes. That is exactly the lens-run misread, and the rule institutionalises it.

Either adopt agent-manager's reading (in progress until the last review or gate stage of the run is done, e.g. until G4 or run close), or state that no marker applies once the build stage is done and drop the backlog Review clause. Add one worked example: build `done`, review `pending`. Replace "and its backlog item is Done" with a precedence statement that does not contradict line 51. Mirror the change in `documentation-writer.md:35`, `write-documentation/SKILL.md:30,85,98` and both templates.
