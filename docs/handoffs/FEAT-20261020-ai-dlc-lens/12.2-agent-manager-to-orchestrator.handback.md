The defect is still there as it describes: `t.keep` is set only at arming and at each ping (keepalive.ts, the Stop loop and the arm tick), and `turn.start` and `session.end` never reset it.

## Root cause and fix
- **Root cause.** `trackStates()` (plugins/claude/ai-dlc/hooks/keepalive/keepalive.ts:145) publishes `t.keep ?? setting`, and `t.keep` was refreshed only by an arming or a ping. Three moments published a stale value:
  - after `/ai-dlc:cache-keepalive clear`, a stopped track kept the old override's `keepWarmMs` and the `cap` it had raised;
  - after `session.end`, the ended session's own override was still published;
  - a track that was never armed published its setting even while an override was set.
- **Fix.** A new function, `refreshKeep` (keepalive.ts:259), re-reads the keep-warm time of every track that is **not running**: the time its next arming would take. It is called at:
  - `turn.start` (:481);
  - `session.end` (:558), with `{ session: false }`;
  - the command, after a set or clear (:577), followed by `publish($)`.
- **What it does not touch.**
  - `stopTrack` (:116) is unchanged, since `arm()` calls it before every arming (the 19.l1 trap).
  - Running tracks are skipped. Their tick reads the time again before each ping, and the README says a change made while pings run "takes effect at the next ping", so the time they armed with stays in force until then.
  - If a track is armed while `refreshKeep` waits on the store, its generation has moved on and it is left alone.
  - If the store cannot be read, the setting is published and the failure goes to the debug log. `refreshKeep` never throws.
- **`keepWarm` (:233)** has a new option, `{ session: false }`. It leaves this session's override out and warns about nothing. That gives the time an ended session leaves in force: the machine override, else the setting.
- **Why it re-reads instead of clearing.** Setting `t.keep = undefined` would publish the setting while an override still stands, which is just as wrong. Re-reading the override chain publishes the time actually in force.

## Decision on `turn.start`
A session override **survives** `turn.start`. It is stored per session in the plugin store (`keepalive:keepWarmFor:sessions:<track>`), and the README and the `cache-keepalive` skill promise "Sets it for this session only" (meaning the session, not one turn). The next Stop already arms with it. So after `turn.start` the published value is still that override. It is dropped only when the session ends or when it is cleared.
