**Behaviour changes the reviewers should weigh**
1. A track now arms only from a warm main entry, warm until that entry's time instead of the Stop time + TTL. So a usage seen earlier gives an earlier `warm until`, and a cache that has already expired no longer arms.
2. A transcript row with a `timestamp` older than the TTL no longer seeds. If neither TTL is seeded, the line reads the existing noSplit text, which is slightly inaccurate here. T17.2's reasons cover it.
3. Risk for sa/se (LLD 3.8 and OQ2): the next Stop re-arms the 1h track from the ledger's 1h entry. After landed 1h pings that wrote no 1h tokens, that entry is stale (+60 rather than the ping time + 60), so the re-armed track can end `expired, stopped` at its first tick. Whether real fork pings carry a 1h write is unconfirmed live. I did not change the design.
