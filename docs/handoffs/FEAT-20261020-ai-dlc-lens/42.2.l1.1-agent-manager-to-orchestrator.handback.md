- 2.1.316: `Box(part ai-dlc){ Text "LENS BAND BENEATH" (part test), keep-alive Box }`. The part beneath is drawn in place.
- 2.1.323: `Box{ Box(part ai-dlc){ {type:"engine",ref:1}, keep-alive Box }, Text "LENS BAND BENEATH" (part test) }`. `next(e)`'s answer is an engine node, and the test's part comes after ours as a separate child of an unmarked root, so the flattened text reads keep-alive first and the lens second.

The 2.1.323 types document the node: `{ type: 'engine'; ref: number }`, "the number core answered from `next(e)`". A new `keepsBeneath()` was also added to the mounted drawing. The product code is correct: `below` sits between the panel and keep-alive's band.

**`no implementation for ui.status` is a red herring.** It is only the engine's report that keep-alive's one-time `clearOldStatus` call (`keepalive.ts:437`) was dropped, and it is printed with any failure. When I stubbed `ui.status` in `engine()`, the 5 tests still failed with the same order assertions. It also broke 8 other tests that stub `ui.status` themselves (`on("ui.status") registered twice`).
