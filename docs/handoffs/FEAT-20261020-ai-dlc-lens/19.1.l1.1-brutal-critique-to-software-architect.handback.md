## 1. docs/specs/aaw-variants.spec.md: REVISE

### Blocker
1. D3 last bullet (:71) with D4 (:72-77) — the code-review guarantee ("code is always tested and reviewed") rests on a prediction that nothing re-checks. The variant is chosen from the change set the request is *expected* to touch. AAWH has no `sqa-engineer` or `code-reviewer` stage. If the `change` stage of an AAWH run ends up changing a script, a hook registration or a CI file (the real change set differs from the expected one, which is normal), no stage tests or reviews it, and G5 does not apply to AAWH. Today `aaw-review.md` classifies the **actual** change set after `agent-manager` hands back and sends code to `sqa-engineer` → `code-reviewer`. The spec drops that and gives nothing in its place. This is the guarantee ADR-0002 says "moves to the rule". → Add a rule: after the `change` stage of every AAWH run the orchestrator runs `variant` on the paths `agent-manager` reports as changed. If the result is `plugin` (or `ask`), the run does not close: the orchestrator stops and asks the human to restart as AAWP (or, if the human agrees, continues under AAWP). State where it is written (`aaw-review.md`, *Rounds*, and the orchestrator hard rule, D8) and add a test row (an AAWH run whose reported change set contains a `.mjs` file). Also state in ADR-0002 that the guarantee rests on this second check.
