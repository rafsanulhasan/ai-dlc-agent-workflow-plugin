## Changes (plugins/claude/ai-dlc-lens/hooks/register.tsx)
- **W-A (pure updater).** Engine types, `.tsc/claude-code.d.ts:15541-15552` (`UpdateFunction`): `update` "reads the value, applies `fn` here in the plugin's environment, writes with `ifVersion`, and tries again on a miss". So on a conflict the updater runs again on the new value, and it "resolves what it wrote".
  - In `refreshList` the `update($, agentsA, …)` updater (:1132-1165) no longer writes module state. It resets `resumed` (:1130) on each run and pushes the resumed ids into it (`resume` at :1147).
  - The timeout loop moved into a new pure helper, `haltDroppedSubagents(out, listed, t, limitMs)` (:1193-1215, type `DropPlan` at :1179) (S-A). It only reads `missingSince` and returns `{start, clear, halt}`. `limitMs === 0` is checked once, before the loop.
  - After `update` resolves, `refreshList` applies the results (:1166-1174): resumed ids leave `haltedByTurn` and `haltedByTimeout`; `missingSince` entries are cleared or started (only if still absent); halted ids are marked in `haltedByTimeout`.
  - `turn.complete` already wrote `haltedByTurn` outside `patchAgent`'s updater, so it was left as it was. The new `heard` also writes module state before its `patchAgent`, never inside it.
- **W-B (clock).** `refreshList` reads `t = await $.clock.now()` once, before `update` (:1117-1125), and the updater gets it from the closure. That `t` is used for the `missingSince` start, the `t - since >= limitMs` comparison and the halted row's `endedAt`. Other uses of `nowMs` (the bg `stampTasks` stamp and so on) are unchanged.
  - Deviation, for review: there is a fallback to `nowMs()` when `$.clock.now()` rejects. The first run without it gave **761 pass / 124 fail**. The test kit rejects an unmocked event (`ai-dlc-lens's ui.press hook was skipped: ai-dlc-lens: no implementation for clock.now`), and most lens tests mock no clock. The fallback keeps those tests on the wall clock, as before. In a real host `clock.now` always answers. The alternative is to drop the fallback and have sqa-engineer add a `clock.now` stub to every `boot` helper.
- **W1 (timeout halt is temporary).**
  - New set `haltedByTimeout` (:362-368). Timeout halts no longer go into `haltedByTurn`, whose comment (:354-361) now says it holds turn-end halts the list confirmed.
  - `heard` is now `async heard($, key)` (:377-386). It deletes the `missingSince` entry, and if the key was in `haltedByTimeout` it removes it and patches the agent to `running` with `endedAt: null`, but only if the agent is still `failed`.
  - It is awaited in `turn.start` (:4465), `turn.step` (:4502-4506, in try/`lensFail`), `tool.call` (:4573-4577, in try/`lensFail`) and `turn.complete` (:4589-4591, before the agents are read). So a turn end is processed as one of a running agent: `answer` gives `completed`; a non-answer is kept `running` unless the list says it ended, in which case it becomes `failed` + `haltedByTurn`.
  - A listed `running` resumes an agent in either set (:1147).
  - `session.start` clears both sets and `missingSince` (:4129-4131).
  - A list-confirmed `failed`/`killed` is unchanged: it is never in `haltedByTimeout`.
- **S-B.** `missingSince` is now `const missingSince = new Map<string, number>()` (:376), cleared with `.clear()` like `haltedByTurn`.
- **Known narrow race, not fixed:** an agent event that lands between the updater's write and the apply step (:1166-1174) can see the agent not yet in `haltedByTimeout`. That agent then stays halted until its next event. The pre-fix code had the same window for `missingSince`.

## Notes for sqa-engineer (driving the clock)

- Without either, the lens falls back to `Date.now()` and today's tests are unchanged.
