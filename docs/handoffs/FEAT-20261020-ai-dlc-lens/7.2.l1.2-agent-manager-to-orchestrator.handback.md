Round 2 therefore treated every spawned agent as a respawn: `loop: true` for both agents in the run, so every arrow was drawn two-way.
- Round 2's `ensureAgent` decided "absent" from a read made before its write. If a `turn.start` read came before `agent.spawn`'s write and its own write landed after it, the spawned agent was replaced by a blank record with no type and no call id.   - it was named from the call's type: `sqa-engineer` title-cased to "Sqa Engineer", hence "SE";

- The headless run did not hit this overwrite: it is a timing race. What the run proved is the event order and the false `loop`. Test `C2b` reproduces that order, and the `ensureIn` unit test shows the overwrite.
- The fix:
  - the existence check now runs inside the write (`ensureIn`);
  - a two-way arrow needs an earlier spawn under another call (`isRespawn`);
  - a separate call→agent map (`callAgent`) is filled by `agent.spawn` and by the Agent call's result;
  - placeholders are steady grey and get their own Buttons and prompt;
  - a `$.agent.list()` that still says `running` no longer undoes a `turn.complete`;
  - a `tool.call` that arrives before its tool chunk is folded into its message's batch.
