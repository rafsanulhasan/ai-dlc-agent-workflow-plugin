## Root cause (for the human)

From Claude Code **2.1.323**, `claude plugin validate` type-checks every `.ts` / `.tsx` file of a plugin's hooks module, tests included. It reports each TypeScript error as a warning, and `--strict` turns any warning into exit 1. Up to 2.1.322 it did not type-check.

It uses the engine's own compiler options: `strict`, `noUncheckedIndexedAccess`, no `allowImportingTsExtensions`. The plugin's `tsconfig.json` has no effect. The 2.1.323 `plugin-authoring` reference says an installed plugin is "type-checked with the header's `tsconfig.json`, kept outside the mod folder", and `claude-code.d.ts:70-80` shows that header tsconfig without `allowImportingTsExtensions`.

Evidence (clean worktree of HEAD `47a3480`, 2.1.323):

| Experiment | `validate --strict ./plugins/claude/ai-dlc` |
|---|---|
| HEAD as is | exit 1: 43 TS5097, 8 TS2345, 4 TS18048 |
| `extends` removed from `hooks/*/tsconfig.json`, `allowImportingTsExtensions: true` kept | exit 1, the same 55 |
| A root `plugins/claude/ai-dlc/tsconfig.json` with `allowImportingTsExtensions: true` | exit 1, the same 55 |
| HEAD, on **2.1.322** | exit 0, `✔ Validation passed` |

`ai-dlc-lens` at HEAD on 2.1.323: exit 1, 109 errors (95 TS18046, 4 TS2552, 2 TS2322, 2 TS2345, 2 TS7006, 1 TS2304, 1 TS7016). They match one for one what `tsc -p plugins/claude/ai-dlc-lens/.tsc` gives with the 2.1.323 `claude-code.d.ts`. The two TS2322 errors are also new in 2.1.323's types: a Pane's `placement` may now be `'widget'`.

**Not in CI configuration:** the only CI-side fix would be dropping `--strict`, which the brief rules out. The fix belongs in the sources.

## Fix

**ai-dlc, TS5097 (43): import paths without an extension.**
- Every relative `import` / `export ... from` in `plugins/claude/ai-dlc/hooks/**` drops `.ts` / `.tsx`: 64 specifiers in 18 files, nothing else on those lines. This is ai-dlc-lens's convention, which already loads live.
- `plugin test` loads them on both hosts (below).
- Node needs extensions, so three Node test suites that import `config.ts` / `settings.ts` now import `tests/support/resolve-ts-extensionless.mjs` first: `auto-handoff-agreement`, `cache-keepalive-cli`, `keepalive-settings`.
- That new helper is a `module.registerHooks` resolve hook. Only for a relative specifier with no extension that Node could not find, it tries `.ts`, then `.tsx`. On a Node without `registerHooks` it does nothing; those suites already skip below Node 22.18.
- `tests/build-copilot-hooks-module.test.mjs`: the pin on register.tsx's import is now `/from '\.\.\/keepalive\/keepalive'/`. It still asserts that register.tsx imports keep-alive.

**ai-dlc, 12 strict errors in `keepalive/tests/keepalive.test.ts`** (committed lines). No assertion is weakened:
- `const split = ... [1_000, 0] as [number, number]`: the tuple `Opts.split` already names.

- `text?.startsWith(...)` `.toBe(true)`, `t?.includes(...)` and `r.text?.includes(...)` in two filters: an undefined text still fails each assertion.
