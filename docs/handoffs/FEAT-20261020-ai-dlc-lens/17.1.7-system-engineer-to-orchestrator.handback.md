**Rule (LLD rev 5)**
- Mark, don't read per response. On a main response (no `agentId`) with `cache_creation_input_tokens > 0` and no split (`creationSplit` undefined, or both fields 0), `observe` and `observePing` record no entry and set `ledger.pendingMain = { at }` (the later `at` wins). A ping reply is the same case. A read-only response, or a write with a split, sets nothing.
- Why not read the transcript at the response: the response's own row may not be flushed when `turn.step` returns. At Stop it is. `noteUsage` also has no transcript path.
- Resolve at the next Stop. Placement is unchanged (before the no-tasks branch, or right after `load` when tasks > 0). The guard widens from `!hasMain` to `needsMainSeed(l)` = `!hasMain(l) || pendingMain !== undefined`.
- `seedMain` merges `max(existing.warmUntil, writtenAt + life)` for each TTL with tokens > 0, only when that is after `now`. It never lowers a live entry and clears `pendingMain`.
- Clock: `writtenAt` is the transcript row's own timestamp. If the row has none, it is `pendingMain.at` (the response time), else `now` as before. It is never the Stop time while a pending write exists, because that would overstate warmth.
- Cost: one transcript read (whole file via `readRaw`, else a 2 MB tail) per Stop that has a pending write, and none otherwise. Pending writes are the rare case, since most responses carry the split. A flag for the build: that read is now recurrent, not once per session, so prefer tail-first if the whole-file read is large. I did not mandate it.
- No split in the transcript either (missing, unreadable, or no row with a split): `dropPending`, nothing recorded, one debug line `keepalive: main write without split, transcript has none`. The track shows `expired` or `no write seen` as before, which is honest because the TTL is unknown. The next Stop does not re-read.
