# 43.2 design: lens view modes, opening sources, status fixes

R = `plugins/claude/ai-dlc-lens/hooks/register.tsx`, L = `hooks/lens.ts`, T = `types/index.d.ts`, K = `plugins/claude/ai-dlc/hooks/keepalive/`. Line numbers are at base 1302cd4.

## 1. View state (T:98, L:1800-1870)

`LensView` gains two optional fields; `prev` stays sizes only.

| Field | Values | Meaning |
|---|---|---|
| `bandMode` | `list` (default) \| `workflow` | what the band shows at normal size: the run list, or `selected`'s flow |
| `paneMode` | `list` (default) \| `workflow` | what the pane (the right panel, beside the band or docked) shows: the run list only, or one run's flow (`pane` beside the band, `selected` docked) |

- The wide "list + selected run's charts side by side" layout is retired. Every site draws **list mode** (the runs, each one row, the list only) or **workflow mode** (one run, layout of section 4).
- Band, wide (`layoutOf(bodyColumns) === 'wide'`): list mode only; `bandMode` is never `workflow` there (drawn as list if it is). Band, narrow: either mode.
- Full screen (one big step chart) stays for the **docked** pane only. The pane beside the band has no ⤢ (B3b: already the right panel).
- Pure helpers go in L next to `viewResize` / `viewRestore` (for example `bandModeOf(v, layout)`, `bandRestore(v)`, `paneFromBand(v, layout)`, `bandFromPane(v)`), so the rules are unit-testable without the engine.

"Band closed" (human's answer to B4b): dismissed with `×` (`bandClosedA`), or not on screen: no `AbovePrompt` render of the lens band within the last 5 s (a module timestamp set by the band render, R:3813). ## 6. Status fixes (C1; L:749-860, 1531-1538; R:816-1003, 1773-1788, 2830-2835, 3286-3292)

1. **Latest attempt wins.** A failed or killed agent is ignored for status when a later agent of the same workflow carries the same handoff record step code (a restart). Applied in one helper in L used by both `workflowInfo` and `stepLook`.
2. **The run state decides done.** A run state `status: done` makes the run `completed`; a *Stages* row `done` makes that step's pending placeholders (`call:`) and no-hand-back records (`OPEN`) count as completed. `blocked` still halts.
3. **Listed completed applies.** `refreshList` applies a `completed` status from `$.agent.list()` (R:998).
4. **One input.** The step accordion's status takes the same run statuses and stage status as the band (`workflowStatus(..., runStatuses)`), so band and accordion agree.
5. **Other sessions.** The 2 s poll stats the current run-state file of each known run folder and calls `refreshRuns` when a mtime or the highest `run.v<…>.md` changed (cheap: stat only, no read otherwise); `recordCache` entries are dropped when their file's mtime changes.
