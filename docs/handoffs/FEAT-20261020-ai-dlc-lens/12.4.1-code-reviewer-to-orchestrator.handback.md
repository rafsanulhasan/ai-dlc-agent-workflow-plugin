Findings (severity, path:line, problem, fix):
- Warning, hooks/keepalive/keepalive.ts:220-229 (cachedRead): a file that stats but whose read fails (a transient lock or EBUSY while an editor saves, on Windows too) comes back from readRaw (io.ts:52) as `undefined`. The cache stores it as `{sig, text: undefined}`. settingsEnv and repoConfig treat undefined as absent, so this raises no failure and the "keep the last good values" path is skipped. Every setting from that file silently falls back to the next level or the default, and stays there until the file's size or mtime changes. Fix: when `sig !== 'missing'` and the read returns undefined, do not cache it. Return undefined for this turn, or better, count it as a failure so atTurn keeps the last values. Add a test with a fake that stats fine but throws on read.
- Warning, hooks/keepalive/keepalive.ts:249-251 (turnTrust): the same issue for ~/.claude.json. A failed read of a file that stats gives the fail-closed answer, which is cached against that sig. Gated settings from the committed sources then drop to their defaults, with no failure and no warning, until the file changes. This fails closed, so it is safe, but it is the same defect. Fix: do not cache the answer when the read returned undefined.
- Warning, hooks/keepalive/keepalive.ts:594-633 and 455-459: a track that stops without turn.start or session.end never has its `keep` re-read. These are `end()` (expired, missed, ping limit, error), the overage stop, `spendLimit`, the Stop "work done" stop and `stopForHandoff`. `refreshKeep` skips running tracks (line 353), so an override set or cleared while the track ran is not picked up when it ends. The expired branch (line 478) ends the track before `keepWarm` runs in the tick (line 479). Until the next turn the state publishes a `keepWarmMs` and `cap` that are no longer in force, which is the 28.1 defect again for these paths. Fix: re-read after the stop (a `refreshKeep` call in a stop path such as `end` made async, or one helper that stops and refreshes), and add a test where the override is cleared while the track runs and the track then expires or misses.
- Warning, hooks/keepalive/keepalive.ts:597-630, 687-689 and 556-559: `load($)` (a full read) can change `settings` (`keepWarmFor`, `minDuration`, `maxPings`). Tracks that do not arm in a Stop, or in a Stop with keep-alive turned off, keep the `t.keep` from turn.start. The 'ping' command and `showSeedCache` call `load` without `refreshKeep` or `publish`. So an edit made mid-turn is published with the old time and cap until the next turn. Fix: call `refreshKeep` after `load` in the Stop (before the `!settings.enabled` branch and the per-track `continue`s), and in the other two callers.
- Suggestion, hooks/keepalive/keepalive.ts:470 vs 156 and 451: `arm` captures `cfg = settings[t.key]` once. `trackStates` and `pingsOf` read `settings[key]` live. When the command's `load` changes `pingEvery` or `maxPings` while a track runs, the published `pingEvery` and `cap` disagree with the cap the tick uses (line 498). Fix: read both from one source (a per-arm snapshot kept on the track, or re-read each tick).
- Suggestion, hooks/keepalive/keepalive.ts:163-171: if `$.ui.log` throws inside the `.catch`, `publishing` stays rejected and every later publish is skipped, so publishing stops for good. Fix: end the chain with a second `.catch(() => {})`, or keep `publishing` as the already-caught promise.
- Suggestion, hooks/keepalive/keepalive.ts:235: `turnCache.root ??= await repoRoot($)` takes the object before the await. If a concurrent full read runs `forgetGit` or `turnRoot` replaces `turnCache`, the root is written to the dead object. This is harmless (it just reads again), but the write is lost. Fix: assign to a local first, then write.
- Suggestion, hooks/keepalive/keepalive.ts:254-257: `trustGate` does `cache.result ??= folderTrust($)`. The getter always returns a promise, so folderTrust is never called and the cached answer wins. This works but is non-obvious. Fix: add a comment saying so at the getter, and a test that fails if trustGate stops using the cache.
