## 1. docs/specs/taxonomy.spec.md: REVISE

### Blocker
1. D8 (:109-110) names a format that does not exist: "A task section in a `tasks.md` file (`## ITEM-NNN …`) gains a `- Run: <run id>` line". The real tasks files are **tables** with a leading `ITEM` column of bare numbers (`| 037 | 18.1 | … |`, `docs/product/active/multi-agent-workflow-foundations/sprint-1/taxonomy/tasks.md:20-31`), not `## ITEM-NNN` sections. A run state's `tasks: [ITEM-NNN]` also does not match the `037` cell. As written AC-18.9.2 (the run ↔ task cross-check) cannot be built or tested. → Choose the real format: a `Run` column in the tasks table, or a `Run` cell per row, and say how `validate` matches `ITEM-037` to the row `037`. Name which `tasks.md` shapes `validate` parses (table rows, and the `product-planning` task format if it differs) and add a fixture row to the test seam.

### Major
1. D5 (:98) says the chain id "is the `chain` value auto-handoff already stores in each `lineage:` record and brief header" and is "the short id of the chain's first session". It is not: `handoff` stores `chain = own?.chain ?? sessionId` with the **full** session id (`register.tsx:439`), and only `short()` shortens it. → Say that the cell and the `Chain:` line write `short(chain)`, 8 characters, and that two chains whose first sessions share their first 8 characters are not told apart (negligible; say so). Note also that after a failed lineage read (root 16, D3) the chain id restarts, so a chain can be split in the cell. Say that is accepted.
2. D2 (:83) and the narrative's Risks claim the Stop gate (`check-workflow.mjs`) runs `validate`, "so a wrong tag blocks the session". It runs only when `.ai-dlc/` has uncommitted changes (`.claude/hooks/check-workflow.mjs:39-43`). A wrong tag in a story, run state or backlog item does not change `.ai-dlc/`, so it does not block. And when `.ai-dlc/` is dirty for any reason (this repository's model-metadata hook rewrites `.ai-dlc/model-metadata.json`), a tag error somewhere else blocks an unrelated change. → State the real trigger. Either accept it ("the gate catches tag errors only when `.ai-dlc/` changed; CI or `validate` run by hand catches the rest"), or put a change of the gate's trigger into scope with its own item. Remove the claim from the narrative.
3. D2 (:71-74) scanning `### ITEM-NNN` sections of the backlog: `docs/backlog/backlog.md:7` is the template item `### ITEM-001: <Title>` with the status `Backlog | In Progress | …`. If it sits outside a code fence the scan flags it (open, no tags). → Say that code fences are skipped, and add a test row (an item inside a fence is ignored).
4. D7 (:107) adds a setting `runModule`. A new auto-handoff setting also needs its `SETTINGS` row (`config.ts`), the README table, the `configure-auto-handoff` SKILL and the alignment tests (`tests/auto-handoff/auto-handoff-agreement.test.mjs`, `settings-levels-aligned.test.mjs`). → List them in the boundaries table (the LLD fixes details).
