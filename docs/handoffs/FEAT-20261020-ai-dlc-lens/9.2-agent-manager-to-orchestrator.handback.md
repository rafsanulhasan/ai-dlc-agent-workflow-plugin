## What changed
The orchestrator now does only two things itself. It gathers the run's context: handoff records, hand-backs, run state, the workflow file, and `git status` / `git log` / `git diff`. And it checks whether the agents it spawned, parallel subagents or an agent team, did their work correctly. It never runs builds, tests, mutation runs, validations or plugin tests. Tests go to sqa-engineer and every other check goes to the agent that owns it. That agent quotes the command and its real output in its hand-back. If that evidence is missing or paraphrased, the check fails and the work goes back to the agent; the orchestrator never runs the command to fill the gap.

**Decision on `workflow.mjs validate`:** at run start it stays with the orchestrator, together with `show`, and so does `rounds --json` at run start and before each loop. These commands read the configuration the run follows, and an invalid file means there is no workflow to run. They do not build, test or validate the project's work. This is written down as the one exception in orchestrator.md (*Delegate the work; check the agents' work*) and in the `handoff` skill's *Rules*. `validate` of a **changed** workflow file is different: it is now agent-manager's check, quoted in its hand-back.
