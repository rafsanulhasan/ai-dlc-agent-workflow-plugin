# 20.5.l1.1 addendum: which design-reference upstreams ITEM-056 credits, and why

AC-20.7.1a (`docs/product/active/ai-dlc-lens/sprint-1/diagramming/stories.md:112`) and spec D8 (`docs/specs/diagramming.spec.md:157-162`) require ITEM-056's hand-back to record whether claude-code-figures is reused, with the reason. The step-38 hand-back did not. This addendum records it, with the mermaid-inline decision, so the tester's exact list is: beautiful-mermaid, elkjs, entities, `@resvg/resvg-wasm`, Inter, mermaid-inline (six), and no claude-code-figures.

| Upstream | Reused? | Entry in `THIRD_PARTY_NOTICES.md` | Reason |
|---|---|---|---|
| mermaid-inline (`github.com/dazebug/mermaid-inline`, MIT, "Copyright (c) 2026 dazebug") | **Yes, the approach only.** No code copied. | Yes: heading, link, MIT text, copyright holder | The human decided on 2026-11-13 to add it (20.5.l1.1 brief, decision B1), as AC-20.7.1a and D8 require. The lens takes mermaid-inline's split-render approach: a `ui.render` hook on `AssistantMessage` splits a reply on its closed mermaid fences and draws each picture right after its fence, from a local beautiful-mermaid layout rasterised by resvg. Its code is not copied: `hooks/diagram.ts`, `registerDiagram` in `hooks/register.tsx` and `renderer/` were written in this repository (a check of function names on 2026-11-13 found only the generic `render` and `pushText` in both, with different bodies). The step-38 notice said "No mermaid-inline ... code is used", which is true of code, and `hooks/ATTRIBUTION.md` said "Not used", which was wrong for the approach; both now say the approach is taken. Licence read from its `LICENSE` at commit 95fe13c4ed4eb9c6163d1abf09fd8212281c5bd0 (main, 2026-10-09). |
| claude-code-figures (`github.com/natsukium/claude-code-figures-plugin`, Apache-2.0) | **No.** Neither code nor idea. | No | It renders by calling local programs (mmdr or mmdc, dot, d2, with resvg) and writing PNG files to a temporary folder, for kitty and Ghostty terminals (research 14.1.15). The lens renders in-process from its vendored `renderer/vendor/` files and draws a PNG `Image` or an `Svg` per surface; the split-render idea it uses is credited to mermaid-inline. Its repository (default branch at commit f9e1cd2bfbc6c5e43b397369ff4928330dce4418, read 2026-11-13) has a `LICENSE` and no NOTICE file at its top level; no entry is needed. |
