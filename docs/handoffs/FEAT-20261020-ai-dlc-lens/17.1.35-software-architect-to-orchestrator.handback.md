**Summary format**
- Shape: `keepalive <1h> | <5m>[ | seed hit <k>|seed miss]`. It is at most 72 characters, so it fits an 80-column terminal with the host's prefix.
- If it is longer, drop the seed token first, then each `warm H:MM` clause.
- Tokens:
  - running: `warm H:MM, ping n/cap`, or `warm H:MM, first ping H:MM` before the first ping lands
  - stopped: `stopped: done|ping limit|spend limit|missed|error|expired|handoff[, warm H:MM]`
  - off: `off`, `expired`, `off (overage)`, or `idle (no tasks|no write|no write yet|turn|subagents|ended)`
- The summary drops the cache part, keep-warm and its source note, `stop by` and the off-line cap.
- Examples (lengths checked with node):
  - `keepalive 1h warm 6:38, ping 1/9 | 5m idle (no write) | seed hit 31k` (68)
  - `keepalive 1h stopped: spend limit | 5m stopped: spend limit` (59, after the drop)

**VS Code**
- The mod cannot tell which surface a given status string is drawn on. `ui.status` takes one string per plugin and has no surface argument (claude-code.d.ts 2.1.310 :2503-2513; its hook event is `{text}` only, :7170-7172).
- The mod does know which surfaces are attached: `$.session.surfaces()` (:2862-2875), plus the `session.attach` and `session.detach` events (:4523-4541).
- Rule: when every attached surface is `vscode`, the status line gets the full text joined with `\n`. Otherwise it gets the summary.
- Unverified: that a VS Code session lists exactly `vscode`. If it doesn't, VS Code falls back to the summary, which is safe.
