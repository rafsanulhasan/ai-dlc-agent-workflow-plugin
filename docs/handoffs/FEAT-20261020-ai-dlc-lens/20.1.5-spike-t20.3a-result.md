Mermaid to PNG: magic `89504e47`, 9.4 KB to 21 KB. Timings (this machine, Windows 11): load bundles + wasm 414 ms, Mermaid SVG 345 ms (first call, ELK), rasterise 181 ms.
- **Finding A (decides LLD 3.3):** beautiful-mermaid SVG uses CSS `var()` and `color-mix()`. resvg draws it with all shapes black (seen in the PNG). A flattening step, resolving custom properties and `color-mix(in srgb, ...)` before rasterising, fixes it: prototype `.scratch/t20.3a/renderer/flat.mjs` (about 20 lines); result PNG shows correct boxes, arrows, labels in Inter. Pass explicit `bg, fg, line, accent, muted, surface, border` to `renderMermaidSVG` so the mixes are fixed.
- **Finding B (offline, AC-20.5):** every beautiful-mermaid SVG carries `@import url('https://fonts.googleapis.com/css2?family=Inter...')` in its `<style>`. `scrubSvg` must remove it for all surfaces; the flatten step above drops the whole style block and replaces it with a local font-family rule. Other URL strings in `mermaid.mjs` are ELK/EMF namespace identifiers and `http://www.w3.org/2000/svg`, not fetches.
- `@resvg/resvg-js` fallback (npm 2.6.2, MPL-2.0) not needed.
