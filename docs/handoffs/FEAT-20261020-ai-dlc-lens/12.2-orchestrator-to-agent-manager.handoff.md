# 28.1 — keep-alive: the published keep-warm time when a track stops

Work item 28 (human, 2026-10-23: "yes", its own work item). Numbered under the new rule: one top-level step per item, its hand-offs as sub-steps.

## The defect
From code review 21.1 (`21.1-code-reviewer-to-orchestrator.handback.md`, suggestion on `plugins/claude/ai-dlc/hooks/keepalive/keepalive.ts:143`): `t.keep` (a `/ai-dlc:cache-keepalive` override's keep-warm time) is never cleared when a track is stopped or reset (`turn.start`, `session.end`). A stopped track goes on publishing the last override's `keepWarmMs`, while the published contract (`plugins/claude/ai-dlc/types/index.d.ts`, `keepWarmMs`) says it is the time "in force". Step 19.l1 declined resetting it in `stopTrack`: `arm()` calls `stopTrack` before every arming, so a just-armed track would publish the default until its first ping. Its note: "A correct fix (in `stopAll` and `end`) needs its own change in the ai-dlc keep-alive."

## Do
- Find where a track really stops or resets (not where it is re-armed) and clear the override there, so the published `keepWarmMs` is the time in force at every moment: after an arm, while running, after a stop, after `turn.start` and `session.end`. Decide whether an override for the session should survive `turn.start` (re-read `hooks/keepalive/README.md` and the `cache-keepalive` skill for what an override promises), and say what you decided and why.
- Tests in `plugins/claude/ai-dlc/hooks/keepalive/tests/keepalive.test.ts` for each moment above, including re-arming (the case 19.l1 found) and the lens reading the published state. If the code review's other keep-alive suggestion (`settle()` spinning 2000 ticks) blocks a clean test, fix that too and say so.
- Record the change in `plugins/claude/ai-dlc/hooks/keepalive/ATTRIBUTION.md`, as the repository requires for that folder.
- Don't touch the lens plugin (sqa-engineer is testing it now), the handoff / task-triage / orchestrator texts (another agent-manager is on them), READMEs, `docs/`, `docs/handoffs/**`. A behaviour change readers need goes in a *Docs update* request. Commit nothing.
