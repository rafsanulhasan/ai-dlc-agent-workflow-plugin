## Definitions for AC-1.5.1 and AC-1.5.2 (human, 2026-10-24, binding)
- **New run:** a new feature, enhancement or bug fix — i.e. a new unit of work. In the handoff layout that is a run folder (`docs/handoffs/{LIFECYCLE}-{YYYYMMDD}-{slug}/`) the lens has not seen before; its `run.md` names the work item (`work-item:` / title).
- **Old (ongoing) run:** a feature, bug fix or enhancement that is ongoing or pending — a run folder whose `run.md` `status` is `active` or `blocked` (or not yet `done`), including one the lens already shows.
- So the workflow's identity is the work item / run folder, never the timing or the spawner: every spawn whose brief names a record in run X joins run X's workflow (old or new); a different work item is always its own workflow (AC-1.5.2), and showing it never hides the others (AC-1.5.1). When no run can be read from a brief, fall back to the request text (same request = same work item) and say so in the report. A finished (`done`) run stays listed (dimmed / completed dot) and is not reused for a new work item.
- Tests for each definition: new folder → new workflow; spawn into an `active` run listed earlier → joins it; spawn into a `done` run → joins that run's workflow (still its own), never a newer one; two concurrent `active` runs → two workflows.
