# Critique: related-request rule (steps 26, 26.l1, 26.l2)

Verdict: REVISE

Overall: the rule does what the human asked. It has three parts. A related request joins the parent run as the next top-level steps, in the parent's folder and flowchart. An unrelated request gets its own run. The `parent:` field is optional. I found no case where two records get the same code, because numbers only grow. But the numbering is not fully determinate, the rule is not stated once, and this run's own records contradict it.
