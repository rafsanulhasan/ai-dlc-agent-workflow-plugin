**`/ai-dlc:lens-keepalive`**
- **The command:** it writes the new setting `keepaliveSection` (default `true`, env `AI_DLC_LENS_KEEPALIVE_SECTION`, normal lens precedence) to `.ai-dlc/lens.json`. Bare, it flips the value; `on` or `off` sets it. If a settings env holds the key, the reply names that level as the winner. It then reports the figures.
- **The section:** "Cache keep-alive (5m 11m 00s · 1h 0s · saved $0.69)" sits after Usage in every agent pane, in the separate pane and in drill-in. It starts collapsed like every section.
- **Measured** (from the state `ai-dlc` keep-alive publishes): each track's `armedAt`, `warmUntil`, `pings`, `running` and `enabled`. Also each agent's cache-read tokens, from `turn.step` usage.
- **Derived:**
  - Kept warm per track (5m, 1h) = the sum over armings of `min(warmUntil, next arming, now) − armedAt`, with the pings and number of armings. This includes the cache's own TTL after the turn, not only the extra time the pings bought (open question 1).
  - The lens keeps each arming in its own state (`keepaliveCycles`), captured at `turn.start`, before and after Stop, and on the 2 s poll, so earlier armings still count after a re-arm.
  - Savings = cache-read tokens × (input price − cache-read price), priced only from the metadata file. Long-context models are priced per request with the same rule as the cost. A missing price shows `—`; nothing is estimated, and the cache-write premium is not subtracted. The session figure is the sum over agents, `—` if any agent is unpriced.
- **Not shown:** cache-write usage per TTL. `ModelUsage` has no TTL split (d.ts:6605-6627). The Agent tool result's `usage.cache_creation.ephemeral_5m/1h_input_tokens` (d.ts:17864-17867) has one, but I have not confirmed what that figure covers, so I did not use it.
- **Probes:** they stay behind a new setting, `probes` (default off). Its logging covers E1, E2, E4 (the poll), E5, E7 and E9. I removed the command-only parts: E3 with its 16 probe panes, E6, E8 and the on-demand E4.
