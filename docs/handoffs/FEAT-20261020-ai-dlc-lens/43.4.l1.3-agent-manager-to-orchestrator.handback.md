## Point 6: not built, clashes for the human
1. **Two meanings of "scope".** `scope` (`AI_DLC_KEEPALIVE_SCOPE`, `session` or `machine`) and the flags `--session` / `--machine` already decide where a keep-warm override lives: the module's memory, or `$.store` for this machine. A new `--scope just-me|team|global` would choose a settings file. The two would share one word in the CLI, the schema and the skills. Choice: rename the new flag (for example `--for just-me|team|global`), or rename the old key (a breaking change for files already written).
2. **What `--scope` applies to.** The spec names `on` and `off`. Should a keep-warm time (`2h --scope team`) also be written to a settings file? Today a time goes only to the session or machine override. And may `--session` (module memory) be combined with `--scope`, or is one of them refused?
3. **"global" is a new precedence level.** Today keep-alive reads, highest first, the `env` of `.claude/settings.local.json`, the `env` of `.claude/settings.json`, `.ai-dlc/cache-keepalive.json`, then the default. It never reads `~/.claude/settings.json`. Where does global go? Claude Code's own order would put it after the team file: local > team > global > repo file > default. Is it trust-gated? It is not a repository file, so I would say no.
4. **"Every scope also writes to `.ai-dlc/cache-keepalive.json`, one section per scope".** That file is committed. A just-me or global value written there would be shared with the whole team, which contradicts "just me". This is also a schema change: today the file holds flat keys, every key present and never `null`; sections `justMe`, `team` and `global` would hold partial values. Two decisions are needed:
   - (a) Are the sections read? If so, where in the precedence order, and do they win over the `env` of the same scope?
   - (b) Are they only a record, never read? Is it acceptable that just-me and global values are committed?
5. **Trust gate.** A team value written to `.claude/settings.json` from a folder Claude Code does not trust is ignored for the 17 gated keys, `enabled` among them. Should the command warn, or refuse?

My proposal, if the human agrees:
- The new flag is `--for just-me|team|global`; `scope` and `--session` / `--machine` keep their meaning.
- `on` and `off` only.
- Precedence: local > team > global > repo file > default; global is not gated.
- The file sections are a record only, under `"overrides": { "team": {...} }`. just-me and global values are not written to the committed file.
- A warning when a team write lands in an untrusted folder.
