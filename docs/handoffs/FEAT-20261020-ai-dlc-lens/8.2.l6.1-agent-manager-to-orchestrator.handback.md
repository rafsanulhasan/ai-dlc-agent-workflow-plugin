**1. Blocked steps**
- **New check:** `stepBlocked`, with its own switch `anomalyStepBlocked` (default on) and its own colour `anomalyStepBlockedColor` (`#c62828`, red, the same rank as a blocked run).
  - Why separate: someone who only cares about whole runs can turn steps off without losing blocked runs, and the reverse.
- **What counts:** a row of the run's *Stages* table whose status cell starts with `blocked` (leading `**` or `_` allowed), whatever the run's status.
  - The table is found under a *Stages* heading, or by a `Stage` column. Columns are found by header name. A table with no `Status` column, and a row with no step code, are skipped. A step listed twice counts once.
  - Toast example: `Step blocked (run R, step 18, 18-…handoff.md): docs: waiting on G2`.
  - When the row changes, the anomaly clears.
- **No duplicate (my choice):** `applySettings` drops a step anomaly whenever the same run's `runBlocked` anomaly is shown. Instead, the run's anomaly now names its steps (`Run blocked (…): blocked step 18`).
  - If `anomalyRunBlocked` is off, the steps are reported on their own.
  - `applySettings` also keeps only one anomaly per key.
- **Done and abandoned runs** still report nothing.

**A5. Steps of one run split across charts**
- **Root cause:** three gaps in how a run's identity was compared.
  1. The run key was the exact path string. The same folder named as a relative path, `./…`, an absolute Windows path or a worktree path counted as different runs. An earlier session's briefs do use absolute `E:\…\.worktrees\…` paths.
  2. A resumed agent's spawn has a brief that names no record. It got a request key, so it started a new workflow.
  3. A split already in the stored state was never repaired: `joinWorkflow` only sent new calls to the oldest workflow.
- **Caveat on the live case:** the 1.6.1 and 1.6.1.l1 briefs both use the same relative path. With no probe log I could not tell which of causes 2 or 3 produced the human's split. The fix covers both, and it repairs the stored state on every read, so the human's current split is drawn as one chart.
- **Fix in `lens.ts`:**
  - `runIdOf`: the identity is the run folder's name, lower case.
  - `callRunIds`: a call with no run key takes the run of the agent it spawned or resumed.
  - `unifyRuns`: merges a split run into its oldest workflow, and gives calls of another run back to that run's workflow.
  - `joinWorkflow` matches runs by identity and returns the unified state.
  - `register.tsx`: `readWorkflows` unifies before every drawing (view, band, chat card, notices). A resumed spawn keeps its agent's run key.
- **Tests:**
  - Pure: one run across two batches and two sessions, with keys lost, an absolute path and a resume, gives one workflow; a second run stays separate; a split state is repaired; a mixed workflow is separated again.
  - In the lens: batch 1, then after `/clear` an absolute-path brief, then run B: two charts, and run A's chart holds both of its agents.

**A7. Full screen**
- **Root cause, from `claude-code.d.ts`:** full screen only reopened the pane with `PaneOpenArgs` `rows` and `columns` (d.ts:7638-7658).
  - `rows` applies only to a pane seated inline above the prompt, and the dock ignores it.
  - `columns` applies only to the terminal's dock, at most 45%.
  - The VS Code panel is sized by VS Code itself, so in the extension nothing visible changed.
  - On the terminal while pinned, `showView` drew full screen in the band, which only gets `maxRows`.
  - No host API lets a plugin take the whole window.
- **Fix:**
  - Full screen now always opens the pane and asks for focus (`focus: true`), which raises it, while still asking for rows and columns. The band steps aside, and restoring a pinned view goes back to the band.
  - The lens draws full screen itself, on every host: the first row, a note saying what this host does, a `Runs:` row to switch runs, and the selected run's title and chart drawn 1.5 times larger (within each setting's maximum), filling the body's rows.
  - The run list, notices, keep-alive line and Anomalies section are hidden until `⤡` restores the view.
  - The note in VS Code: "Full screen: this run only, filling the pane. This surface sizes the pane itself: maximise or widen its panel for more room. ⤡ restores."
  - The note in the terminal: "…at the height the terminal gives the pane (docked beside the transcript it is at most 45% wide)…"
- **Tests:** VS Code (focus; rows and columns asked; the run list gone; the larger chart, with its width compared; restore) and terminal pinned (the pane opens raised, the band steps aside, restore returns to the band).
