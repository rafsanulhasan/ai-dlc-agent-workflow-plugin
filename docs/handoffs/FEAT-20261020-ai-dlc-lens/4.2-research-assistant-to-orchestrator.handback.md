Q1 Svg, colours, blink
- Svg is a leaf element: no children, and only `source`, `alt` (required), `width`, `height` (CSS px) and `isInteractive` props; `source` is the SVG document string — DTS SvgProps/Svg doc (~chars 300000–400000), REF Elements table (2026-10-22)
- Svg is capped at 131,072 characters of markup; drawn on Desktop and VS Code only, not the terminal (a pane returning only an Svg opens empty there) — REF Elements; GAL "Svg" (2026-10-22)
- Hex colours work inside Svg markup: the official sample uses `fill="#2e7d32"` on `<rect>` — GAL "Svg" (2026-10-22)
- Default Svg draws as an image. `isInteractive: true` draws it in a script-less sandboxed frame, "so hover, CSS `:hover`, SMIL animation and `<title>` tooltips work". This answers the R2 question: SMIL `<animate>` and CSS `:hover` are supported only when `isInteractive` is true — DTS SvgProps.isInteractive (2026-10-22)
- Scripts and event-handler attributes are always stripped ("the frame has no allow-scripts and the scrub strips them"), and "the surface never lets the markup reach the page". Arrowhead markers, text and plain `<style>` are not mentioned either way, and neither is `<image>` or `href="data:..."`. Test them in a real panel — DTS SvgProps (2026-10-22)
- No Svg-click API: "presses that other plugins should observe go on an enclosing element", so make it clickable by wrapping it in a Box/Button — DTS SvgProps.isInteractive (2026-10-22)
- Blinking: with `isInteractive` the blink can be SMIL, otherwise a `$.clock.every` plus `$.ui.invalidate('ui.render')` toggle is the fallback. Redraws are throttled to 10 per second (30 in the terminal for the visible pane) — REF Limits (2026-10-22)
- Text `color` is "a theme key or a raw color" and BoxProps `backgroundColor`/`borderColor` are plain `string` with no doc comment. Nothing defines a raw colour or confirms `#rrggbb`. The only documented values are `'red'`/`'blue'` named colours — DTS TextProps; GAL "Text" (2026-10-22)
- Safe design: use Svg with hex fills for the green blinking dot and avatars, and theme or named colours for Text/Box — inference from the two lines above
- Raster (terminal only) takes 24-bit `0xRRGGBB` and rounds to a smaller palette (`0x2e7d32` draws as `#337733`) — GAL "Raster" (2026-10-22)

Q2 Width and resize
- `e.props.bodyColumns` means "Cells across the body, inside the frame" for a Pane and "the terminal's width, or the transcript column's while a Pane is docked" for AbovePrompt, so the unit is terminal cells — DTS PaneRenderProps/AbovePrompt docs; REF Render sites (2026-10-22)
- `placement` is `'dock'` or `'inline'`, and "where a surface seated it is that surface's to say". In VS Code a panel of 800 px or more docks (`placement` 'dock', `viewport.isFullscreen` true), and a narrower one is inline with 12 rows before scrolling — DTS UiPane; INT "Draw in the VS Code extension" (2026-10-22)
- Claude Code re-runs `ui.render` when "the site's props change or the terminal's width changes" and not on a timer. A dock to inline switch changes `placement` and `bodyColumns`, which are props, so a re-run is the documented trigger. The docs say "the terminal's width", so a VS Code panel resize is still unverified — INT "When Claude Code redraws without being asked" (2026-10-22)
- VS Code sizes the pane itself and ignores `$.ui.open` `rows` and `columns` — INT "Open a pane at the right time" (2026-10-22)
- `e.viewport` (`columns`, `rows`, `isFullscreen`) is always present in VS Code. In the terminal and Desktop it is absent until measured — REF Render sites (2026-10-22)
- Recommended design: derive compact vs flowchart from `bodyColumns` (and `placement`), not from `viewport`, plus a user toggle in `$.state` — inference from the two lines above

Q3 Transcript cards
- ToolUse props: `tool_use_id`, `tool` (e.g. `Agent`, `SendMessage`), `input` (the call input as the model sent it), `isRunning`, `isErrored`, `isInterrupted`, `output` (undefined while running). ToolResult props: `tool_use_id`, `tool`, `output` (the tool's own result object), `isErrored` — DTS ToolUse/ToolResult (~chars 300000–400000) (2026-10-22)
- ToolUse and ToolResult are two independent render sites, each keyed by `requestId` = tool call id. A mod can replace the ToolUse row with a tree and return `next(e)` at the ToolResult site, so the subagent's response row stays — REF Render sites; INT "Change what Claude Code already draws" (2026-10-22)
- At "replace" sites a returned tree is drawn in the site's place and `next(e)` returns `{ type: 'engine', ref }`. That engine reference can be nested inside a Box beside your own elements, e.g. a card above the native row — INT "Replace the drawing", "Leave it alone" (2026-10-22)
- No Agent-specific props: ToolUse has no agent field. `input` of an `Agent` call should hold description and subagent type; the exact keys are not documented. Correlate by `tool_use_id` with `agent.spawn` (`e.tool_use_id`, per 3.2) and `$.agent.list()` — DTS ToolUse (2026-10-22)
- Collapse and expand: there is no Collapsible element. The documented primitive is ToolGroup: `isExpanded` is "whether each call draws as its own ToolUse row (true under --verbose and in ctrl+o) or the group draws one line", and "a hook that sets `isExpanded` unfolds the group where it is". Build a manual `[+]` from a Button plus `$.state`/module state, and keep the native row via `next(e)` — DTS ToolGroup; REF Elements (2026-10-22)
- ToolResult rewrites: "a rewrite of `output` is checked against the tool's output schema", and an invalid rewrite draws the original. The docs do not say what a returned tree at ToolResult does, so do not hide or replace results there — DTS ToolResult (2026-10-22)
- Tool-call sites work in the terminal, Desktop and VS Code — INT "Change what Claude Code already draws"; REF Render sites table (2026-10-22)
- Teammate messages: `session.receive` origin kinds include `peer-send-message` ("another session's SendMessage"), also `peer`, `task-notification`, `scheduled-trigger`, `coordinator` and others — DTS SessionReceiveOrigin/PromptOrigin (2026-10-22)
- In the transcript, a delivered message is a UserMessage row with `origin`, `text`, `isExpanded`, and `from` ("another agent of this session, a teammate, another session, a channel") or `task` (for a notification). When `isExpanded` is false it "is one dim line naming its sender" — DTS UserMessage (~chars 300000–400000) (2026-10-22)
- A UserMessage card is therefore feasible: draw a compact header from `from` and `origin`, and nest `next(e)` for the full text so nothing is hidden. This applies in all three surfaces — REF Render sites table (UserMessage: Terminal, Desktop, VS Code); inference for the nesting design
- Outbound `SendMessage` calls are ordinary ToolUse/ToolResult rows with `tool: 'SendMessage'` (resumes a subagent and does not re-run `agent.spawn`) — REF Subagents section (2026-10-22)
- A `session.append` hook can rewrite a stored row's text blocks, but that changes history, so avoid it — REF Events/Session (2026-10-22)

Q4 Clicks
- Button is supported on all three surfaces (`onPress`, `key`, `label`). In VS Code `hotkey`, `plain`, `autoFocus` and `action` are ignored, so "the user presses a button there with a click, or with Enter once it has focus" — REF Elements; INT "Keyboard focus and hotkeys" (2026-10-22)
- Button state toggle is documented: the `onPress` callback changes a variable, `$.state` or `$.store`, then calls `$.ui.invalidate('ui.render')`. Writing a `$.state` value read by the hook redraws automatically — INT "Build a pane with tabs", "Keep state" (2026-10-22)
- The docs give no limit on Buttons at transcript render sites, and no example of one there. Tool-call sites are listed for VS Code, so a Button in a ToolUse or UserMessage tree should work, but it is unproven. Needs a spike in VS Code — REF Render sites (2026-10-22)
- `$.state` needs a `PluginState` type declaration and a `types` entry in `plugin.json`, survives module reload but is reset by `/clear`, `/resume` and `/branch`. `$.store` is machine-wide and persists across sessions — INT "Keep state" (2026-10-22)
- Link `href` renders as a link in Desktop and VS Code only if https or http://localhost, with no `@` — INT "Link in the Desktop app and VS Code" (2026-10-22)
- VS Code frames mod-drawn or rewritten content with a label such as "From the X plugin" or "Edited by the X plugin" — INT "Draw in the VS Code extension" (2026-10-22). Not stated whether this label also appears on transcript-row rewrites.
