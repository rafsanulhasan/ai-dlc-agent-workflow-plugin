## Invalidation decision
- **Repository root and trust target (git).** Dropped when the session's working directory changes (read through `$.session.cwd()` at each turn, which runs no process), at `session.end`, and at every full read.
  - Why not "never within a session": a `git init`, a clone or a moved worktree can change the root mid-session. Each full read runs git itself, so dropping the cached answer there means a turn's answer is never older than the last full read. The cost is one extra `rev-parse` at the turn after each Stop with background work, or after each command.
  - Why not watch the root itself: no signal is cheaper than the `rev-parse` it would replace. Statting `.git` in every ancestor folder costs more calls.
- **Trust answer.** Kept with the trust target and the size and modified time of `~/.claude.json`. That file is stat-ed at each turn that needs trust and read again when it changed.
  - Why: trust fails closed and gates the committed sources, so a trust withdrawn in `~/.claude.json` must count at the next turn.
  - Claude Code rewrites that file often, so the saving there is smaller than for the settings files.
- **Known limit.** Two edits in one modified-time tick that leave the size unchanged go unseen until the next full read. The human's rule (size or time) accepts this, and a test pins it down.
