**(a) Replace one fence, keep the rest: YES (Medium-High).**
- d.ts:10320 types `AssistantMessage` as one reply block: `text` (markdown), `isFirstOfReply`, `isSummary?`, `onScreen?`. It is raised on every attached surface. d.ts:10311-10316 says "A rewrite changes the drawing and leaves the stored message alone". `ui.render` returns a `RenderElement` tree (d.ts:10902), so a hook can return a Box of `Markdown` + `Image`/`Svg` + `Markdown`.
- `Markdown` (d.ts:5878) is a leaf that every surface carries. Limits: 100000 chars per drawing, and links that are not https/http/file draw as text.
- mermaid-inline (github.com/dazebug/mermaid-inline) does exactly this. Its `ui.render` hook on assistant messages redraws a reply holding a Mermaid block, passes the surrounding text back, and leaves the stored message unchanged.
- Rendering there runs in a separate `node bin/render.mjs` process, because the hooks module cannot load npm packages. The pipeline is beautiful-mermaid, then resvg to PNG, cached locally. Terminals without kitty graphics get Unicode box drawing.
- Implication: split `text` on the fence and emit text, picture, text. This must be one block per `AssistantMessage`; a fence split across blocks cannot be handled. Put the renderer in a child process. `onScreen` can drive lazy rendering.
- Not verified: how the hook handles streaming or unclosed fences.
- claude-latex: web search found no such project. mermaid-inline credits "LaTeX Inline" (copied `hooks/tex.ts`) as its math source. Treat LaTeX Inline, not "claude-latex", as the reference and read its repo before design.

**(b) Surfaces: YES (High, from the types).**
- d.ts:3919-3995 lists the elements per surface:
  - `terminal`: Box, Text, Button, Input, Select, Link, Code, Markdown, Client, Raster, Image. No `Svg`.
  - `desktop`: same set, with `Svg` and no Raster/Image.
  - `vscode`: `Svg` and no `Client`.
  - `mobile`: `Svg`, no Input/Select.
- `Svg` (d.ts:13065): `source` up to 131072 chars, `alt` required, optional `width`/`height`, and `isInteractive` for a script-less sandboxed frame. Desktop and VS Code draw it as an image. Mobile draws it in a web view.
- `Image` (d.ts:5470, 5513) is terminal-only. `source` is `{png}` or `{rgba,width,height}` base64 up to 2 MiB decoded, or a `{file}` / `{shm}` name. `columns` and `rows` are 1-255, and `alt` is required. Pixels show only in kitty or Ghostty, or iTerm2 3.5+ under fullscreen rendering (png/rgba only). Elsewhere the dim `alt` is drawn.
- Implication: emit SVG on desktop, vscode and mobile, and PNG (resvg) on the terminal. Read `e.surface` per render. Keep SVG under 131072 chars and PNG under 2 MiB, with a text fallback (Unicode art or the source fence) in the `alt`.
