# Research Findings: claude-lens cache-TTL handling and Anthropic prompt-cache usage fields

## Question
Does `@foyzulkarim/claude-lens` read `usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` from `~/.claude/projects/**.jsonl`, what does it derive from them, and what do Anthropic's docs say about those fields, cache reads and TTL refresh? Time-sensitive: current package and docs.

## Findings
1. **Reading the fields.** Not confirmed in source. The architecture doc names both fields as "exact field names, verified 2026-07-06 against real transcripts" and says they "drive the Cache Lab TTL mix panel" [1, §4]. `parse-premium.ts` reads capture sidecars (`*.cost.jsonl`, `*.turn-boundaries.jsonl`, `cost-log.jsonl`), not transcript JSONL, and maps only aggregate `cache_read_tokens` / `cache_write_tokens` [2]. I found no fallback logic for a missing `cache_creation` object. The code that reads transcripts is likely in the minified `dist/` bundle [3], which I could not read.
2. **Derivations.** I found no cost multipliers, expiry or "warm until" computation in any fetched file. Costs are labelled `computed` (tokens × pricing table) [1, §2]. Read tokens are not attributed to a TTL [1, §4; 2].
3. **Pricing table.** Stored in `~/.claude-lens/config.json` [1, §10]. Per-model rates were not retrieved.

Anthropic docs [4]:
- Write multipliers: 5m = 1.25× base input; 1h = 2× base input. Reads = 0.1× (0.025× for Fable 5.1 / Mythos 5.1; 0.05× for Opus 5.5 / Sonnet 5.5).
- `cache_creation_input_tokens` equals the sum of the `cache_creation` object's values. No standalone definition of the two ephemeral fields appears on the page; they appear only in an example.
- No TTL breakdown for `cache_read_input_tokens`.
- Default lifetime 5 min; `ttl: "1h"` in `cache_control` selects 1h. Refresh: "The cache is refreshed for no additional cost each time the cached content is used" (stated for the default cache). Lifetime is measured from the start of the request that reads or writes it.
- Not stated: whether a read resets a 1h entry's TTL.
- Ordering rule: 1h entries must precede 5m entries in a request.
