## Findings
1. Rendering model: a `ui.render` hook returns a tree built from `$.ui.resolve(e)`. Elements are Box (flex), Text, Button, Link, Code, Markdown, Input, Select, Svg, Client, Raster, Image. Every element is a function with props and `children`. JSX is allowed in `.tsx`. [R1 reference "Elements"] [R2 interface "Build a tree"]
   - Svg (≤131,072 chars) draws in Desktop and VS Code only. Image (PNG or RGBA ≤2 MiB, or a file path) and Raster draw in the terminal only. No `img`, no data-URI support is documented. [R1]
   - No CSS animation or SMIL is documented. Blink must be done by toggling a prop from a timer. [R2 "Redraw on a timer"]
   - Text `color` takes a theme key or a name such as `'red'`. The docs do not say that hex works for Text or Box `backgroundColor`. Hex is documented only for Raster. [R1]
   - Timers: `$.clock.every(ms, fn)` and `$.clock.after`. `$.ui.invalidate('ui.render')` is throttled to 10 per second, or 30 in the terminal for the visible pane. [R2, R1 Limits]
2. Width: the mod gets no resize event and no breakpoint API. Two signals are available:
   - `e.props.bodyColumns` (width available to the tree) and `e.props.placement` (`'dock'` or `'inline'`). [R1 render sites; R2]
   - `e.viewport` (`columns`, `rows`, `isFullscreen`). In the terminal it is absent until measured, and its `rows` is the window height. In VS Code it is always present. [R1]
   - `ui.render` runs again when props or terminal width change. The docs say "the terminal's width", and VS Code is not named; this is an inference for VS Code. [R2 "When Claude Code redraws without being asked"]
   - Fallback: branch on `bodyColumns` or `placement` in the hook. A compact or expanded mode can also be a user toggle stored in `$.store` or `$.state`, read in `ui.render`.
   - In VS Code, a panel 800 px or wider docks the pane beside the conversation, and a narrower panel draws inline with 12 rows before scrolling. This matches the compact-list case. [R2 "Draw in the VS Code extension"]
3. VS Code surfaces:
   - Pane (`Pane` site, `dock` or `inline`), status line and toast in one stack above the prompt, and transcript lines (`$.ui.log`). Band (`AbovePrompt`) is listed for Terminal and Desktop only. [R1 render sites; R2 "Draw in the VS Code extension"]
   - Version gates: 2.1.299 for rendering. 2.1.304 is needed when the session does not fetch feature flags, such as Bedrock, Foundry or Agent Platform. [R1]
   - Limits: status line cut at 200 chars or 2 rows; toast 500 chars; redraw 10 per second; `Link` href rules differ; `Text` ignores `size`, `mono`, `tabular`; `Box` ignores `position` and `hover`. [R2; R1]
   - Mods that draw are inside the VS Code chat panel only. It is not documented that they draw in the VS Code status bar.
4. Events and data:
   - Subagent spawn: `agent.spawn` (fires before the spawn). Input fields: `tool_use_id`, `prompt`, `description`, `subagentType`, `model`, `parentAgentId`, `name`, `background`, `fork`. This gives type and parent. [R3 d.ts `AgentSpawnInput`]
   - Subagent state: `$.agent.list()` returns `id`, `description`, `type` (`teammate` for in-process teammates), `status` (`pending`, `running`, `waiting`, `idle`, `completed`, `failed`, `killed`), `parentId`, `spawnedBy`, `name`. `waiting` and `idle` need 2.1.289. [R3, R1 `$.agent`]
   - Subagent completion: no dedicated stop event was confirmed. The usable signals are `turn.complete` with `e.agentId` set (subagent turns fire it too, per register.tsx:787) and `$.agent.list()` status. `classic.SubagentStop` is a settings-hook event name not checked here. [R2 "Follow a turn"; repo register.tsx:787]
   - Per-turn tokens: `turn.complete` has `e.usage` (turn totals). `turn.step` gives `result.usage` per request, with `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `model`. [R2 "Follow a turn"]
   - Context size: `$.session.usage()` returns `{ startedAt, context: { tokens, window, percent }, rateLimits, cost }`. [R1 `$.session`]
   - Agent-team messages: `session.receive` with `e.origin.kind` (`peer-send-message` for another session or agent; `task-notification`; `scheduled-trigger`) and `e.text`. Outbound: `session.send` with `e.to`, `e.text`, `e.origin.kind` (`model` or `plugin`). [R2 "Send and receive messages"; R1 events]
