## 3. Team mode versus subagent mode

**Subagent mode (today):** the orchestrator writes each handoff before spawn (`handoff/SKILL.md:133`), stores the hand-back, and verifies (`orchestrator.md` step 9).

**Team mode adds:**
- Teammates write the handoffs they send and the hand-backs they return (`handoff:135`). The lead keeps only the run state, from the names teammates report.
- brutal-critique reviews every handoff. No AAW step or loop does this yet. It needs its own loop and limits, not the shared critique budget (`aaw-review.md:48`).
- Verification conflicts with the current rule: "the receiver verifies a handoff; the writer never verifies its own record" (`handoff:129`). The human's rule has the previous agent verifying. See Q3.

**Claude Code constraints** (cited by `request-routing:152` to the agent-teams docs; not re-fetched this session):
- `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` is required.
- Teams do not run under `-p`, headless or Agent SDK sessions, which fall back to subagents.
- One team per session, with a fixed lead. Teams do not nest.
- Teammates lose frontmatter `skills`, so briefs must name them (`handoff:222`).
- `/resume` does not restore teammates (`handoff:293`).
- With agent-manager as main agent and no orchestrator, there is no lead (`handoff:134`).

**Copilot:** no teams and no documented nested spawning (`orchestrator.md` runtime section; `handoff:136`). Subagent mode only. Per-handoff critique still works as a subagent spawn.

**Decision rule:** no AAW rule exists. `request-routing` decides team vs subagent per stage (:143, :147-150), and no AAW stage fits its Refine/Align pattern. The rule the human wants (orchestrator decides per request, asks when unsure) must be written.
