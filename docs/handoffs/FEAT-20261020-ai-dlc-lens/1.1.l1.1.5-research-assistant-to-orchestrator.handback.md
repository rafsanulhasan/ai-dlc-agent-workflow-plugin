## Findings

### 1. How agent-flow presents subagent work
- Adds a side pane, not a transcript edit: "Shows a live tree: Interactive visual tree of the active session's subagents (opened via /flow, beside the transcript)". [1]
- Row fields: status, type, name, description, elapsed time, current activity, call count, tokens once finished. [1]
- Highlights: agents waiting for approval; a tool call over 30 s; a running agent silent for two minutes. [1]
- Agents the engine never listed go under a collapsed "unlisted loops" group. Narrow inline mode shows only rows needing attention. [1]
- Pane draws only via `ui.render` for `{component:'Pane'}`; it returns `next(e)` unless `e.requestId` is its pane id, else `Views.paneView(...)`. [3]
- Also a `ui.render` on `PromptHint` that returns `next(e)` and only records viewport columns. [3]
- Animation/colour/blink: not described in any fetched source. The "blinking green active, steady green done" effect is not confirmed for agent-flow. [1][2][3]

### 2. What it hides and how to see it
- Hides nothing from the transcript per the sources: no `session.append` handler, no ToolUse/ToolResult/ToolGroup/AssistantMessage/UserMessage `ui.render`, and `tool.call` returns `next(e)` unchanged. [3]
- Its `turn.step` reads streamed text into its state and "yields every chunk unchanged". [3]
- Detail hidden in the pane: each row's `[+]` expands to model, prompt excerpt, last lines written, recent tool calls, tokens. [1]
- Text-mode access: `/flow text` prints the tree as text; also used where no pane can be drawn (e.g. `-p` runs). [1]

### 5. Official docs support
- Hiding or replacing a tool's row is supported: `ui.render` sites `ToolUse`, `ToolResult`, `ToolGroup` (terminal, Desktop, VS Code), plus `AssistantMessage` and `UserMessage` (all three). Returning a tree without `next` replaces the drawing. [9][10]
- Rewriting stored rows: `session.append` fires "once for each row the conversation keeps ... before it's stored", and `next({...e, message})` can change text blocks or a `tool_result` `content`. Docs do not say whether this affects what the model later reads; treat as a risk to verify. [9]
- Animation sources: `Client` elements (terminal and Desktop only) and `Raster` and `Image` (terminal only) are not in VS Code. `Svg` is Desktop and VS Code, not terminal. [10]
- Redraw limit: `ui.render` redraws throttled to 10 a second, or 30 in the terminal for the visible pane. A VS Code blink must stay within 10 a second. [9]
- VS Code draw support: rendering needs extension 2.1.299+ (2.1.304+ without feature-flag fetching). The panel frames mod output and labels it "From the <plugin> plugin". Buttons have no hotkeys; `Text` ignores `size`, `mono`, `tabular`; `Box` ignores `position`, `hover`. [11]
- `Pane` renders in VS Code: docked when panel is 800 px or wider, inline (12 rows) when narrower. [11]
- Official docs do not say how the VS Code extension treats `session.append` rewrites, nor whether Desktop and VS Code honour all `ToolUse` replacements the same way. Not stated.
