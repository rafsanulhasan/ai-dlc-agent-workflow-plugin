## Acceptance criteria covered
| AC | Expectation |
|---|---|
| AC-1 | With an active run claimed by the chain, handoffs continue past `maxConsecutiveHandoffs` (4 or more in a row with no typed prompt). |
| AC-2 | When that run's `run.md` turns `done`, `blocked` or `abandoned`, the next handoff does not fire; a typed prompt resumes. |
| AC-3 | With no active run, the old guard still stops at `maxConsecutiveHandoffs` (default 2). `chainWhileRunActive: false` restores it with a run. |
| AC-4 | `pickRun` finds the run across a chain of 3+ sessions (lineage) and never takes another session's run or one of several unclaimed runs. |
| AC-5 | The session handoff lists `run.md`, the session note, and only records of stages not `done` / `skipped`; `last-record` and its pair first when open; missing files marked `(missing)`. |
| AC-6 | Names: original → `[ai-dlc:auto-handoff]: <base> (Session 1)` via `/rename`, only when `command.list` has `rename`; seeded → `(Session N)` via `sessionTitle`; base never nested; a failed or missing rename never blocks the handoff. |
| AC-7 | The capabilities file records whether `rename` exists; the CLI `capabilities` / init's rename check reads it. |
| AC-8 | Precedence per key: settings.local.json env > settings.json env > process env > `.ai-dlc/auto-handoff.json` > userConfig > default; an invalid value falls through and is logged; env keys `AI_DLC_AUTO_HANDOFF_*`; old `AUTO_HANDOFF_*` ignored; `DISABLE_AUTO_COMPACT` honoured. |
| AC-9 | CLI `merge` on an existing file adds new keys, removes unknown keys and keeps set values; `validate` rejects bad values. |
