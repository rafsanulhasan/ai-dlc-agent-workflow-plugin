AC-4 (restated; U1 + O1). herdr behaviour is active only when all of these hold: the setting `mode` is not `off`; `herdr` is on PATH; the herdr server is running; and this session's pane is identified. That means either `HERDR_ENV=1` or, when `HERDR_ENV` is missing or not `1`, exactly one pane of `herdr pane list` is this session's (a working `claude` pane whose cwd is this repository, not a pane the skill opened). No match, or more than one, means inactive, never a guess. `mode` `off` wins over every other condition, `HERDR_ENV=1` included. When inactive, behaviour is exactly as before: no pane is created, nothing is printed, no error or warning. Detection makes only read-only herdr calls (`--version`, `status server`, `pane list`).

AC-5 (restated; O1). The setting `mode` chooses `watch`, `run-in-pane` or `off`, default `watch`; it is documented in the skill. Its storage and layering are AC-16 to AC-20.

AC-10 (rewritten). In run-in-pane mode each subagent runs as its own `claude -p --agent ai-dlc:<id>` process in a herdr pane. The orchestrator gets its final result through two retrieval paths, a main and a fallback. Which of the result file (design D4) and the pane read (`pane read` / `pane wait-output`) is the main is decided by design (1.1.6.l2) from evidence, not fixed here. Whichever is main:
1. both paths are implemented;
2. the fallback is used only when the main path yields no usable result (for example no result or exit record, or an unreadable result); a usable main result is never replaced by the fallback;
3. the result stored as the hand-back is the agent's final text, verbatim, from whichever path produced it;
4. a result neither path can produce, or that is unusable or unverifiable, is a failed hand-back, never success (AC-11);
5. the run records which path produced each result (Assumption: one line in the run state; the design may choose where).

AC-11 (clarified, same intent). A result whose line 1 is not `handoff <file>: passed|failed — …` (for example a Stop-hook-rewritten result) is stored as a failed hand-back and the step is re-spawned with the `Agent` tool. "Text copied" is never treated as "step succeeded". This is not a loop round.

AC-16. `mode` accepts exactly `watch`, `run-in-pane`, `off`; default `watch`; variable `AI_DLC_HERDR_MODE`, key `mode` in `.ai-dlc/herdr.json`. Testable: each value reads back via `show`; any other value is invalid (AC-21).

AC-17. `runTimeoutMinutes` is the minutes a run-in-pane agent may take before the script stops it and the step falls back to the `Agent` tool. It must be above 0 and at most 720; default 60; variable `AI_DLC_HERDR_RUN_TIMEOUT_MINUTES`, key `runTimeoutMinutes`. Testable: 0, a negative, above 720 or non-numeric is invalid (AC-21); an elapsed valid timeout stops the child and gives a `stage:"run"` failure that falls back to the `Agent` tool.

AC-18. Each setting is read from the first of five levels that sets it to a valid value: (1) `env` of `.claude/settings.local.json`, (2) `env` of `.claude/settings.json`, (3) the process environment, (4) `.ai-dlc/herdr.json`, (5) the default. `null` in the file means not set there. Testable: a higher level wins over every lower one, for each key.

AC-19. `show` prints each key with its effective value and its source level; `show --json` prints the same as one JSON document. `show` never writes a file.

AC-20. `set <key>=<value>...` writes `.ai-dlc/herdr.json` after validating every assignment, and leaves the file unchanged when any is invalid (exit 1, no partial write). With no assignment it is a usage error (exit 2). `set --dry-run` and `merge --dry-run` write nothing. `merge` creates `.ai-dlc/herdr.json` (all keys `null`), copies the schema `herdr.schema.json`, and does not overwrite a value already set. (Assumption: exit codes and output format follow `auto-handoff.mjs`, as the LLD states.)

AC-21. `validate` exits 0 when the file and every settings level are valid, and exits 1 with one message per invalid value otherwise. An invalid value at a level is a `warning:` in `show`, an error in `set` and `validate`, and the next level applies. Reading the settings never throws and never blocks a run.

AC-22. The skill documents the keys, values, defaults, the five levels and the four commands (`show`, `merge`, `set`, `validate`). It says where a personal choice belongs (`env` of `.claude/settings.local.json`, uncommitted) versus the team's (`.ai-dlc/herdr.json`).
