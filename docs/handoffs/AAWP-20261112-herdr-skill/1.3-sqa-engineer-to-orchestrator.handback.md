## Gap and findings (no production code touched)
1. **GAP, AC-11 (the known Stop-hook risk): `herdr.mjs run` cannot detect it.** `usableResult` only requires exit 0, `subtype:"success"`, not `is_error`, and a non-blank string. A child whose final text was rewritten by the Stop hook, so that line 1 is not `handoff <file>: passed|failed — <why>`, comes back as `{"ok":true,...}` with the text copied verbatim. I pinned the current behaviour in a characterisation test (`run` returns `ok:true` and copies the text). I added a `todo` test, "a result whose line 1 is not … is not reported as a plain success", which fails today and does not fail the suite. It will pass once `run` returns `ok:false` or a flag for such a result. The only guard today is the orchestrator's own line-1 check ("a missing line counts as a failed verification"), so the effect is safe, but the script does not raise it. Severity medium. Route to agent-manager (code) if AC-11 is meant to hold in the script; otherwise accept the gap, document it as a known limit in SKILL.md and drop the todo.
2. **Minor, defect-free inefficiency (`herdr.mjs:381-387` and `:447-449`).** When `pane run` fails during a `run`, the pane is closed twice (`openPane` closes it, then `runCommand` closes it again). The second close is harmless (pane_not_found is success), but it is redundant. My test asserts "closed at least once, only the new pane".
3. **Observation, not a defect (`herdr.mjs:216-219`).** `safeArg` allows a space. A hand-made job file with `agent: "a b"` therefore reaches claude as one quoted argument (`ai-dlc:a b`). It is not an injection, and the CLI's own regex rejects such an id earlier.
4. Deviation 4 (a record with no `## Your task` shows the first 6 body lines after the frontmatter) is tested and matches the implementation.
