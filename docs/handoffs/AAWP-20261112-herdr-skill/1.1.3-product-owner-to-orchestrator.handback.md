# Intent: herdr skill and herdr panes for spawned agents
Source: the human's request and clarified answers in run.v1.md (binding); research 1.1.1, 1.1.2. Anything else is marked Assumption.

## Outcome
Inside herdr (herdr.dev) the AI-DLC team becomes visible there: a Claude-Code-only skill teaches agents the herdr CLI, and the orchestrator puts each spawned subagent/teammate in a labelled herdr pane. Outside herdr nothing changes.

## ACs
Skill
- AC-1. New Claude-Code-only skill `herdr`, listed in tools/claude-only-skills.json (absent from the Copilot plugin). Our own text, not vendored; cites herdr.dev.
- AC-2. Skill covers detecting herdr (HERDR_ENV=1 and `herdr` on PATH) and create/label/focus/run/send-text/read/wait/close of panes (tabs/workspaces where needed), using only commands confirmed against herdr's CLI reference or `herdr api schema --json`; names the HERDR_* env vars used. Unverified commands are not documented.
- AC-3. States herdr is installed separately by the user; the plugin neither installs nor requires it.
Activation
- AC-4. herdr behaviour is active only when HERDR_ENV=1 and `herdr` on PATH; otherwise behaviour is exactly as before: no herdr command attempted, no error/warning.
- AC-5. A setting chooses `watch` or `run-in-pane`, default `watch`. Storage/name is a design decision (Assumption: follows the plugin's other settings); documented in the skill.
Watch mode (default)
- AC-6. Agents still spawn via Agent tool / agent team as today; additionally the orchestrator opens one labelled pane per subagent/teammate (label = agent + step) showing its progress.
- AC-7. Subagent pane closes when it has handed back; teammate pane closes when the teammate is shut down.
- AC-8. A teammate idle while waiting for a teammate's handoff/reply keeps its pane; a pane is never closed merely because its agent is idle.
- AC-9. Failure to create/label/close a pane never blocks, delays or fails agent work or the run.
Run-in-pane mode
- AC-10. Each agent runs as its own `claude --agent ai-dlc:<id>` process in a herdr pane, driven with pane run/wait/read; the orchestrator gets the result from the pane.
- AC-11. Handoff record, verbatim hand-back, and `handoff <file>: passed|failed` line 1 flow works unchanged; an unrecoverable result is a failed hand-back, never success.
- AC-12. If the mode cannot be honoured (herdr missing/unreachable mid-run), fall back to a normal Agent-tool spawn and say so.
Wiring
- AC-13. orchestrator, agent-invocation and request-routing (Mode 5) reference the skill and setting where agents are spawned/shut down; generic agents/skills stay stack-agnostic and do not require herdr.
- AC-14. Plugin rules followed: built via agent-manager; `node tools/build-copilot.mjs` and `--check` pass; `node tools/validate.mjs` passes; tests added/passing for any script (`node --test "tests/**/*.test.mjs"`); any hook stays under hooks/.
- AC-15. Works on Windows native, checked against herdr's documented Windows behaviour (no `terminal attach`; named-pipe socket); parity gaps documented, not guessed.
