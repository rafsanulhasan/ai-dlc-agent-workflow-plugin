# 1.2.l3.1 orchestrator → AAWP team: lay out herdr watch panes so every pane stays readable

## Goal
The human (2026-11-13): "yes add it as a followup for agent manager and the AAWP team in the run where we added the herdr skill", after this problem: `herdr.mjs open` splits every new pane **down from the newest live pane**, in one column. With five panes opened at once, the last ones got one row each and could not be read; the human had to ask for a third column, which the lead built by hand with `herdr pane move` across tabs.

Clarified intent (run state `run.v2.md`, *Joined requests*): `open` lays out watch panes so every pane stays readable — e.g. start a new column when the current one would make a pane too small — and keeps a team's panes together, instead of always splitting the newest pane down. Run-in-pane panes (`run`) follow the same placement.

## Facts found 2026-11-13 (herdr 0.9.5, Windows) — re-check live before you rely on them
- `herdr pane layout` returns every pane's rect and the split tree.
- `herdr pane move <id> --tab <tab> --split right|down --target-pane <id>` works only across tabs (same tab: `changed:false`, `reason:same_tab`); pane ids survive a move.
- `herdr pane split <pane>|--current --direction right|down --no-focus --cwd <root>` is what `open` uses today.
- The skill documents only herdr commands it uses (SKILL.md, *Commands the script calls*, each with its source and whether it was checked live). Any new command (e.g. `pane layout`) gets a row there, checked live, never guessed.
