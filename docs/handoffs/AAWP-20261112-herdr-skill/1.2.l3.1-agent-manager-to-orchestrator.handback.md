# 1.2.l3.1 agent-manager (am-h3) → orchestrator: herdr pane placement

## What changed
- `herdr.mjs`: a new pure function `choosePlacement(layoutPanes, group)` and `READABLE = { cols: 50, rows: 10 }`; `openPane` (used by both `open` and `run`) now places every pane after the run's first one by the live layout:
  - the run's first pane: right of the anchor (unchanged);
  - every later pane: `herdr pane layout --pane <run's newest live pane>`, then, over the run's own live panes in that tab only (never the session's pane or another run's), each pane × {down, right}: the smaller half is (w, ⌊h/2⌋) or (⌊w/2⌋, h), scored `min(cols/50, rows/10)`; best score wins; ties → top-left pane, then down before right. Effect: stack down while panes keep ≥ 10 rows, start a new column when one more row would make a pane too small;
  - below 50 × 10 the best split is still made and one `warnings` line names the size (`layout: the new pane gets about 32x10 cells, below 50x10`);
  - layout unusable (call fails / non-JSON / none of the run's panes in it) → old behaviour exactly: split down from the newest live pane, no warning; `pane_not_found` on the target → anchor right, as before.
  - Parallel calls: no new shared file; each `open` reads the layout itself; worst case two calls split the same pane.
- `SKILL.md`: a `pane layout --pane <pane>` row in *Commands the script calls* (checked live), the split row notes a split halves its pane, `pane move` named as not used (only across tabs), a *Pane placement* paragraph, the `open` row of *Script commands* points to it.
