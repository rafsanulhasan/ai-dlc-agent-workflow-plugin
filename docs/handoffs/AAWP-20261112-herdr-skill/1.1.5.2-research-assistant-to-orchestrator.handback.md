Q4 permissions in a -p child
- Since v2.1.302, -p starts in Manual mode when nothing sets a mode (S1, Auto-approve tools). In Manual mode a call that needs approval is denied unless a PermissionRequest hook or --permission-prompt-tool approves it (S1).
- --allowedTools "Bash,Read,Edit" lets those run. Unlisted tools run if they need no approval. Rule syntax such as `Bash(git diff *)` works (S1).
- --permission-mode accepts auto, dontAsk or acceptEdits (S1). dontAsk denies every call that would prompt (S1).
- --permission-prompts none (v2.1.259+) denies prompting calls and tells Claude not to retry (S1, S2). With --output-format stream-json, denials appear as permission_denied system messages and in the result's permission_denials (S1).
- Without --bare, -p runs hooks from project .claude/settings.json and connects .mcp.json, with no workspace trust dialog (S1). Whether project permissions.allow rules apply to -p: not verified, since the permissions page was not fetched. Unknown.
- A plugin subagent's frontmatter permissionMode is ignored. A subagent without one inherits the main conversation's mode (S4).

Q5 Windows install and spawning
- Native installer: `irm https://claude.ai/install.ps1 | iex` in PowerShell, or a curl-based .cmd in CMD. No Administrator needed (S7, Install and Set up on native Windows). Binary: %USERPROFILE%\.local\bin\claude.exe, versions in %USERPROFILE%\.local\share\claude (S7, Uninstall).
- npm: `npm install -g @anthropic-ai/claude-code`, needs Node 22+. The package pulls the native binary via a per-platform optional dependency and a postinstall step links it. "The installed claude binary does not itself invoke Node." win32-x64 and win32-arm64 are supported (S7, Install with npm).
- Whether npm leaves a .cmd or .ps1 shim: not stated. Unknown.
- Git Bash is recommended on native Windows for the Bash tool. CLAUDE_CODE_GIT_BASH_PATH sets its path. Without it, the PowerShell tool is used (S7).
- Spawn advice (inference, not in docs): the target is a native .exe in both installs, so a Node script can spawn it directly with child_process spawn or execFile, no shell. Resolve the path at run time (for example `where.exe claude`). Use `cmd /c` only if the resolved file is a .cmd shim. Medium.
