New findings
- plugins/claude/ai-dlc/skills/herdr/scripts/herdr.mjs:711-715 — Warning — this is a regression from the W2 fix. The child is now `detached`, so it leaves the pane's process group. `onSignal` handles only SIGINT and SIGTERM. When herdr closes the pane (a human closes it, or the pane closes mid-run), the shell and node most likely get SIGHUP. Node dies on SIGHUP by default and the detached `claude` keeps running, orphaned with no result written. Before the fix it shared the group and received the hangup. I did not verify that herdr sends SIGHUP on pane close. Fix: also register `process.on("SIGHUP", onSignal)` and remove it with the others. If someone can confirm herdr does not send SIGHUP, document that instead. No Blocker, since the user can still stop the run.
- plugins/claude/ai-dlc/skills/herdr/scripts/herdr.mjs:636 and tests/herdr/herdr-run-fallback.test.mjs:626 — Suggestion — the 5 s SIGKILL timer is not `unref`'d, so it holds the event loop open after the child has gone (harmless, 5 s). The only test that exercises the real group kill is skipped on Windows, so this host has no running evidence for the POSIX path. Fix: call `.unref()` on the timer, and make sure CI runs the POSIX test on Linux or macOS.
