## 3. `skills/herdr/scripts/herdr.mjs`

One file, Node 22+, no dependencies, ES module, `#!/usr/bin/env node`. It exports its pure helpers and runs `main()` only when executed (the pattern of `auto-handoff.mjs`, so tests import it).

### 3.1 Output and exit codes

- Orchestrator-facing commands (`detect`, `open`, `close`, `run`): **exactly one JSON line** on stdout, nothing on stderr, **exit 0 for every outcome**, including `ok:false`. Exit 2 only for a usage error (unknown command, missing or malformed argument), with one line `usage: ...` on stdout (JSON `{"ok":false,"reason":"usage: ..."}` too, so a caller that parses always can).
- Pane-side commands (`watch`, `child`): print to the pane (stdout is the pane); always exit 0.
- Settings commands (`show`, `merge`, `set`, `validate`): the format and exit codes of `auto-handoff.mjs` (human text; `show --json`; `validate` exits 1 on an error; `set` with no assignment exits 2). They are for people and the skill's Show/Edit modes, not for the orchestrator's run loop.
- Every `herdr` call: `spawnSync(exe, args, {timeout: callTimeoutMs, encoding:"utf8", windowsHide:true})`, `callTimeoutMs` = 5000, overridable by `AI_DLC_HERDR_CALL_TIMEOUT_MS` (an internal test hook, not a setting). A timeout, a signal, an `ENOENT`, an empty or non-JSON stdout where JSON is needed: `{ok:false}` with a reason, never a throw. `main()` wraps everything in `try/catch` that turns an exception into `{"ok":false,"reason":"internal: <message>"}` and exit 0.

### 3.2 Shared helpers (all exported)

| Helper | Contract |
|---|---|
| `resolveExe(name, env=process.env)` | Scans `env.PATH` (and `PATHEXT` on win32: `.EXE;.CMD;.BAT` in that order; bare name last) and returns `{file, shell}` where `shell` is true only for `.cmd`/`.bat`; `undefined` when absent |
| `runExe(name, args, {timeoutMs, input?, env?})` | `resolveExe` then `spawnSync`; for a shell target, args are checked by `safeArg` (below) and the call becomes `{ok:false,reason:"unsafe argument"}` if any fails; returns `{ok, status, stdout, stderr, reason?}` |
| `safeArg(s)` | `/^[A-Za-z0-9._:\/\\ -]+$/` and no `..`-only element; used only for the shell path (`claude.cmd`). Pane ids (`w1:p1`), labels and agent ids pass; `"`, `$`, `` ` ``, `;`, `&`, `|`, `<`, `>`, `%`, newline do not |
| `herdrJson(args)` | `runExe("herdr", args)`; parses stdout (else stderr) as JSON; returns `{ok, json?, errorCode?, reason?}`; `errorCode` is `json.error.code` when present |
| `paneIdFrom(json)` | `json?.result?.pane?.pane_id ?? json?.result?.pane_id`, else `undefined` (U3) |
| `parseStatusServer(text)` | `/^\s*status:\s*running\s*$/m` → true; anything else false (U: exit 0 when not running) |
| `readSettings(root, env)` | section 4; returns `{mode, runTimeoutMinutes, sources, warnings}` |
| `jobPath`, `paneFile`, `resultPaths` | the path builders of 3.6 |
| `atomicWrite(file, text)` | write `file + ".tmp"`, then `renameSync`; the only way the script writes a result or state file |
| `openPane(opts)` | steps 2-7 of `open` for one pair; **the only place that closes a pane after a failure** (3.3 `open` step 7) |
| `childCommand(job)` | validates every job field (3.4 step 0) and returns `{file, args, shell}` or `{ok:false, field}`; pure |
| `killTree(child)` | 3.4 step 4: `taskkill /t /f` on win32, `-pid` SIGTERM then SIGKILL on POSIX; never throws |
| `encodePaneCopy(text, nonce)` / `decodePaneCopy(paneText, nonce)` | the pane copy format of 3.8.3; pure |
| `retrieveResult(job, exitInfo, deps)` | 3.8.2: main, then fallback; returns `{ok, source, text?}` or `{ok:false, reason}`; `deps.readPane(pane)` is the only herdr call it makes |

### 3.3 Commands

Common arguments: `--root <dir>` (default: git root, else cwd), `--run <dir>` (the run folder; required by `open`, `close`, `run`, optional for `detect`), `--step <code>` (`/^[0-9]+(\.[0-9a-z]+)*$/`), `--agent <id>` (`/^[a-z0-9][a-z0-9-]*$/`). A value failing its pattern is a usage error (exit 2). No value ever reaches a shell unvalidated.

**`detect [--explain] [--run <dir>]`**

Order matters: the cheap, silent checks come first, and no `herdr` call is made before step 2.

1. `s = readSettings`. `s.mode === "off"` → `{"ok":true,"active":false,"mode":"off","reason":"mode is off"}`.
2. `herdr --version` fails (not on PATH) → `{active:false, reason:"herdr is not on PATH"}`. Otherwise keep the version text.
3. `herdr status server`: not `parseStatusServer(stdout)` → `{active:false, reason:"herdr server is not running"}` (the exit code is ignored: it is 0 when the server is down).
4. **Anchor and source.**
   - **A. `HERDR_ENV === "1"`** (set by herdr, or by the user in `env` of `.claude/settings.local.json`): `source:"env"`; anchor = `env.HERDR_PANE_ID` when set, else the `pane-match` result of B when it is unique, else `null` (a later `open` then splits with `--current`, which herdr resolves from its own environment; the focused pane is never used as a guess).
   - **B. `HERDR_ENV` missing or not `1`: pane match.** If `--run <dir>` is given and `<run-id>/anchor.json` names a pane that `pane list` still shows with `agent:"claude"`, use it (`source:"cached"`; the match is made once per run, so later calls are not confused by panes of our own). Else `herdrJson(["pane","list"])` (a failure or a missing `result.panes` array → inactive, reason `"pane list unavailable"`) and the candidate set is the panes with **all** of:
     1. `agent === "claude"`;
     2. `agent_status === "working"` (this session is running a tool right now; an idle claude pane in the same folder is another session);
     3. `cwd` equals, after `normPath` (lowercase on win32, backslash to slash, no trailing slash), the git root or `process.cwd()`;
     4. its `pane_id` is not in any `*.pane.json` under `<root>/.scratch/herdr/*/` (a pane we opened for a `claude -p` child).
     Exactly one candidate → `source:"pane-match"`, anchor = its `pane_id`. Zero → inactive, reason `"no pane matches this session"`. Two or more → inactive, reason `"ambiguous: <n> panes match this session"`. **Never pick one**: the evidence herdr gives (no pid, no tty) cannot tell two working claude panes in one folder apart, and a wrong pane would put the panes beside another session.
5. Active: `{"ok":true,"active":true,"source":"env|pane-match|cached","anchor":"w1:p1"|null,"mode":"watch|run-in-pane","modeSource":"<source>","runTimeoutMinutes":n,"version":"0.9.5"}`.

Silent in the sense of AC-4 (as changed, section 9): no stderr, exit 0; the reason is data for the run state, never a warning. Outside herdr (herdr not installed) nothing is called past step 2; with herdr installed but the session elsewhere, the read-only calls `--version`, `status server` and `pane list` run and nothing is created. `--explain` adds `candidates:[pane_id...]` for troubleshooting only.

**`open --run <dir> --step <c> --agent <id> [--record <path>]`** (repeatable `--step/--agent` pair for a fan-out: arguments are read left to right, each `--agent` closes the pair opened by the preceding `--step`; a `--record` applies to the pair before it)

For each pair, independently (one pair failing does not stop the others):

1. `detect` logic inline, with `--run` (so the cached anchor and own-pane exclusion apply); not active → that pair `{ok:true,skipped:true,reason}`; `open` never errors outside herdr. Computed once per call.
2. Anchor: the `anchor` of step 1 (`env.HERDR_PANE_ID`, the pane match, or the run's cached `anchor.json`); stored in `.scratch/herdr/<run-id>/anchor.json` as `{pane, source, at}` on the first pair. A `null` anchor splits with `--current` instead of a pane id. The old `pane current` fallback is gone: it returns the focused pane, which is not necessarily this session's.
3. Target = id of the newest `<step>-<agent>.pane.json` of this run whose pane still exists, else the anchor. First pane of the run: direction `right`; every later pane: `down`.
4. `herdrJson(["pane","split",target,"--direction",dir,"--no-focus","--cwd",root])`; on `errorCode === "pane_not_found"` retry once with the anchor. `paneIdFrom` the result; absent → `{ok:false,reason}`.
5. `herdr pane rename <id> "<agent> <step>"` (the label; exit code only; a failure leaves the pane, unlabelled, and is reported in `warnings`).
6. Write the job file (3.6) and `<step>-<agent>.pane.json` `{pane, mode:"watch", step, agent, opened}` (atomic).
7. `herdr pane run <id> "node \"<abs herdr.mjs>\" watch \"<abs job.json>\""`; non-zero exit → `{ok:false}`. **The pane is closed in exactly one place: `openPane` (the function steps 4-7 live in) closes it on any failure after the split and returns `{ok:false}`; its callers (`open`, `run`) never close it again** (review 1.4.1: the pane was closed twice).

Output: `{"ok":true,"opened":[{"step":"1.2","agent":"agent-manager","pane":"w1:p2"}],"skipped":[],"warnings":[]}`; or `{"ok":false,"opened":[...partial],"failed":[{"step":..,"agent":..,"reason":..}]}`. Any failed pair makes `ok:false` and nothing else changes: the orchestrator notes one line and goes on (AC-9).

**`close --run <dir> --step <c> --agent <id>`** (repeatable pair)

Reads `<step>-<agent>.pane.json`; none → `{"ok":true,"closed":[],"reason":"no pane"}`. Else `herdr pane close <id>`: exit 0 or `errorCode === "pane_not_found"` → remove the file, `ok:true`; any other failure → `ok:false` and the file stays. It never closes a pane for any reason but the call: no idle logic exists (AC-8). A pane whose agent is done but whose `close` was missed is closed by its own `watch`, which exits (3.5); the pane file is then stale and `close` removes it.

**`run --run <dir> --step <c> --agent <id> --record <path> --out <path> [--worktree <name>] [--timeout <minutes>]`**

Blocking; the orchestrator always calls it with `run_in_background` (3.7). Steps:

1. Mode must be `run-in-pane` and `detect` active, else `{"ok":false,"stage":"launch","reason":...}`.
2. Validate: `--record` and `--out` must be repository-relative paths matching `/^[A-Za-z0-9._/-]+$/` (no spaces, quotes, `$`, `..` segments), the record must exist, `--agent` `/^[a-z0-9][a-z0-9-]*$/`, `--worktree` `/^[A-Za-z0-9._-]+$/`. Violation → `stage:"launch"`, reason `unsafe or missing path`. (Run folders are slugs: `docs/handoffs/<LIFECYCLE>-<date>-<slug>/`; a slug with a space is therefore a fallback to the Agent tool, not a failure.)
3. Open a pane with `openPane` (as `open` steps 2-5, one close point, see `open` step 7), then delete any old `<out>` and `<out>.exit`; generate the **nonce** (`crypto.randomBytes(6).toString("hex")`); write the job file with `{kind:"child", agent, record, out, worktree?, timeoutMinutes, root, nonce}` (the nonce is in the job file only, never on the command line); `pane run <id> "node \"<herdr.mjs>\" child \"<job>\""`. Any failure before this point is `stage:"launch"` (the agent never started; the pane was closed by `openPane`).
4. Wait: poll every `AI_DLC_HERDR_POLL_MS` (1000) until `<out>.exit` exists or `timeout + 15 s` passes. Every 10th poll, `herdr pane list`: when the call succeeds and the pane id is gone and no `.exit` exists, **re-check `.exit` once more** (a child that finished just before the pane was closed), then stop with `stage:"run", reason:"pane closed before the agent finished"`; a failing call is ignored.
5. **Retrieve the result** (section 3.8): the main path, then the fallback. The outcome is one of `{source:"file"}`, `{source:"pane"}` or none.
6. A result was retrieved: close the pane, remove the pane file and return `{"ok":true,"result":"<out>","source":"file|pane","exit":0,"line1":"<first line, at most 200 characters>","handoffLine":true|false,"permissionDenials":n,"sessionId":"..","costUsd":x}`. **`ok:true` means "the agent's final text was copied to `<out>`", nothing more** (review 1.4.2 W1, 1.3 gap 1). `handoffLine` is true iff the first line matches `/^handoff S+: (passed|failed) — /`; it is information for the orchestrator, never a reason for the script to fail, because verifying a hand-back is the orchestrator's job (D4). When the fallback supplied the text and the main path had written a file, `source:"pane"` is also written to `<out>.exit` as `resultSource`.
7. Otherwise `{"ok":false,"stage":"run","reason":"<.exit.reason, or the retrieval reason, or timeout>","exit":n,"pane":"<id>"}`; the pane is left open (D5) and the pane file stays so the human can see it and `close` can remove it later.

**`watch <job.json>`** and **`child <job.json>`**: run inside the pane; read the job file path as their only argument.

**`show | merge | set | validate`**: section 4.

### 3.4 `child` (the run-in-pane wrapper)

Job: `{"kind":"child","agent","record","out","worktree?","timeoutMinutes","root","nonce"}`.

0. **`childCommand(job)` validates every field** before anything is spawned (review 1.4.1): `agent` `/^[a-z0-9][a-z0-9-]*$/`, `worktree` (when set) `/^[A-Za-z0-9._-]+$/`, `record` and `out` `/^[A-Za-z0-9._\/-]+$/` without a `..` segment, `root` an existing directory, `nonce` `/^[0-9a-f]{12}$/`, `timeoutMinutes` a positive number. A failure is a `finish()` with `usable:false, reason:"invalid job: <field>"` (the `.exit` file is still written, so the parent does not wait). The `safeArg` check of 3.2 stays as the second guard on the `.cmd` path.
1. `cwd = root`. Build the arguments, all from validated parts:
   `["-p", "<prompt>", "--agent", "ai-dlc:<agent>", "--output-format", "stream-json", "--verbose", "--permission-prompts", "none"]` plus `["--worktree", name]` if set. `<prompt>` is the fixed text `Handoff record (read first; it is your brief): <record>. Do the work it asks and end with your report: its line 1 is "handoff <file>: passed|failed — <why>".` The record path passed `/^[A-Za-z0-9._\/-]+$/` in `run`, so the prompt is a single argument with no shell metacharacter; on the shell path (`claude.cmd`) it is wrapped in double quotes, which needs no escaping because the text contains none.
   `--permission-prompts none` is verified accepted (1.1.6 probe). It turns a call that would need approval into a denial that the agent reports, which is what a non-interactive child can do; it is **not** `bypassPermissions`.
2. Async `spawn` (stdio `["ignore","pipe","pipe"]`, `shell` from `resolveExe`, `windowsHide:false`), env = the parent's plus `AI_DLC_HERDR_MODE=off` and `HERDR_ENV` removed from the child (a child never opens panes). **On POSIX the child is spawned `detached: true`**, so it leads its own process group and `killTree` can signal the whole group (review 1.4.1 W2).
3. Read stdout by line. Each line is `JSON.parse`d in a `try`; a line that is not JSON is printed raw. Rendering to the pane, one line each, nothing wrapped: `init` → `[start] <model>`; `assistant` text block → `<first 160 chars>`; `tool_use` block → `> <name> <first 100 chars of the main input>`; `result` → `[done] <subtype> <num_turns> turns $<cost>`; anything else ignored. The last parsed `type:"result"` object is kept.
4. A timer calls `killTree(child)` at `timeoutMinutes` and records `reason:"timed out after N min"`. `killTree`: **Windows** `taskkill /pid <pid> /t /f` through `execFileSync`; **POSIX** `process.kill(-pid, "SIGTERM")`, then `process.kill(-pid, "SIGKILL")` after 5 s, each in a `try` (an already-gone group is not an error). The same function runs when the script itself gets SIGINT or SIGTERM.
5. On close, compute `usable`: `exit === 0` **and** a `result` object **and** `result.is_error !== true` **and** `result.subtype === "success"` **and** `typeof result.result === "string"` with a non-blank trim. (From the probe: `is_error:false`, `subtype:"success"`. Missing `is_error` counts as not an error; a different `subtype` such as `error_max_turns` is not usable.)
6. `finish(...)` (one function; every exit path of `child`, including step 0 and a crash, goes through it). It never throws: each of its three writes is in its own `try`.
   a. If usable: `atomicWrite(out, result.result)` **first** (main channel). A failure is recorded as `writeError` and does **not** stop b and c.
   b. If usable and `Buffer.byteLength(result.result) <= PANE_COPY_MAX_BYTES` (16384): print the **pane copy** (3.8.3) as the last output of the pane. Larger: print `[no pane copy: result larger than 16 KiB]` instead, and the `.exit` file says `paneCopy:false`.
   c. Always: `atomicWrite(out + ".exit", JSON.stringify({usable, exit, subtype, isError, terminalReason, permissionDenials: result.permission_denials?.length ?? 0, sessionId, costUsd, bytes, sha256, paneCopy, nonce, reason?, writeError?}))`. `bytes` and `sha256` are those of the result text (UTF-8) whenever one exists. If this last write also fails, the child prints `[could not write .exit: <message>]` and exits 0; the parent then ends at its own timeout and tries the fallback (3.8.2), which needs no file. (Review 1.4.1: `finish()` used to be able to throw and leave no `.exit`.)
   `.exit` is written last, so its presence means `<out>` is final (or was not writable, see `writeError`).
7. Print `[result written: <out>]` or `[no usable result: <reason>]` before the pane copy, then exit 0. The pane stays at its shell; the orchestrator closes it.

The orchestrator never reads the pane; it reads `<out>` (copied verbatim into the hand-back file, AC-11) and `.exit`. `run` itself reads the pane only in the fallback (3.8.2).

### 3.5 `watch` (the progress view, read only)

Job: `{"kind":"watch","run","step","agent","record","opened"}`.

Loop every 2 s, redrawing the pane (clear + print, `\x1b[2J\x1b[H`), until exit:

1. Header: `<agent> <step>`, elapsed (`mm:ss`), the record file name, and the record's first 6 lines after `## Your task` (read each time; a missing file prints `(record not readable)`).
2. Layer 1: run-folder events: files in `--run` matching `*-<agent>-to-*` or `*-to-<agent>.*` with mtime >= `opened`; one line `HH:MM:SS <file name>`; newest 12.
3. Layer 2 (optional, U2): the transcript root is `$AI_DLC_HERDR_TRANSCRIPT_ROOT` else `($CLAUDE_CONFIG_DIR or ~/.claude)/projects`. Take the 20 newest `*/*/subagents/agent-*.jsonl` by mtime (depth fixed at project/session/subagents), keep those whose first 8 KB contain the record's file name (the brief's first item); of the match, print the last 8 assistant text / tool_use lines (`JSON.parse` each, tolerant). Not found, unreadable or no match: print nothing, no error.
4. Exit (print `[<agent> <step> finished]`, exit 0) when a file matching `<step>-<agent>-to-*.handback.md` exists in `--run`. It never writes.

### 3.6 State and job files

Under `<root>/.scratch/herdr/<run-id>/` (`<run-id>` = the run folder's basename; gitignored by `/.scratch/`): `anchor.json` `{pane, at}`; `<step>-<agent>.pane.json` `{pane, mode, step, agent, opened}`; `<step>-<agent>.job.json`; `<step>-<agent>.result.md` and `.result.md.exit` (run-in-pane; the job file of a `run` carries the `nonce` of 3.8). One file per pane, never one shared file, so parallel `run` calls do not race. Every write goes through `atomicWrite`.

### 3.7 Parallel fan-out and the Bash timeout (settles the design's open choice)

`open` and `close` take several pairs in one call. `run` takes one pair: for a fan-out the orchestrator issues one `Bash` call per agent with `run_in_background: true` and is notified as each exits (the Bash foreground limit is 10 minutes, shorter than `runTimeoutMinutes`). It then reads each result with the file tools, never through the pane.

### 3.8 Result retrieval: main path and fallback (round 1.1.6.l2; amends AC-10, section 9 item 5)

AC-10 says the orchestrator gets the result "from the pane" (pane run, wait, read). Human decision 1.1.6.l2: build **one main path and one fallback**, and choose the main by evidence.

#### 3.8.2 Decision

| Criterion | **Main: result file** (`child` writes `<out>`, then `<out>.exit`) | **Fallback: pane copy** (`pane read` of a base64 block) |
|---|---|---|
| Verbatim fidelity | exact bytes | exact **only** because the text is base64 (P8); plain text is lossy (P4, P5) |
| Size | none | 16 KiB raw (P9) |
| Pane closed mid-run | works if the child had finished | gone (P10) |
| Windows | no terminal dependency; atomic rename | needs herdr, a live pane and its scrollback; verified on herdr 0.9.5 / Windows only |
| Failure modes | disk unwritable, `.exit` unparsable, antivirus lock | scrolled out, too large, pane gone, herdr down |
| Proof of integrity | `.exit` is written after `<out>`; `sha256` in `.exit` | sha256 and byte count in the markers |

**Main: the result file.** It is exact, unbounded, independent of herdr's terminal handling and survives the pane. **Fallback: the pane copy**, used only where the file channel did not deliver a result the child produced, and never to override the child's own verdict.

**When the fallback runs** (`run` step 5):

1. Main first: `.exit` parses, `.exit.usable === true`, `<out>` exists and is non-empty, and the sha256 of `<out>` equals `.exit.sha256` → `source:"file"`.
2. The fallback is tried only when the child may have produced a result the parent could not read: **(a)** `.exit.usable === true` but `<out>` is missing, empty or its sha256 differs; **(b)** `.exit.writeError` is set; **(c)** `.exit` is missing or unparsable after `timeout + 15 s` (the child died or could not write `.exit`) and the pane still exists. It is **not** tried when `.exit.usable === false`: the child judged the run failed (non-zero exit, `is_error`, a wrong `subtype`, blank text, a timeout), and the pane copy is printed only for a usable result.
3. Steps: `herdr pane read <pane> --source recent-unwrapped --lines 100000` (stdout is plain text; a closed pane is exit 1 with `pane_not_found` on stderr, so no fallback and the reason is kept). Find, from the end, the last `<<<HERDR-RESULT-END-<nonce> sha256=<hex>>>>` and the last `<<<HERDR-RESULT-BEGIN-<nonce> encoding=base64 bytes=<n>>>>` before it (the nonce is the one in the job file; markers with another nonce, for example an earlier run's in the same pane, are ignored). Remove all whitespace between them, decode base64, require the byte count to equal `bytes` **and** the sha256 to equal the END marker's. A marker missing, a count or hash mismatch or invalid base64 → no result: `stage:"run"`, `reason:"pane copy unusable: <markers missing | size mismatch | hash mismatch | invalid base64>"`.
4. A verified copy gets the same non-blank check as the main result, is written with `atomicWrite(<out>, text)` and returned with `source:"pane"`.

`wait-output` is probed and works (P1, P2) but is **not used**: the script already waits on the `.exit` file, `wait-output` reports a truncated tail (P1), and a file check needs no herdr call. The skill names it as available, not instructed (AC-2).

**AC-11 holds on both paths.** A result is returned only when it is non-blank text of a run the child judged usable and, on the pane path, only when byte count and sha256 match; everything else is `ok:false, stage:"run"`, which the orchestrator turns into a failed hand-back (section 5). A **verified** result that is not a hand-back (no `handoff <file>:` line 1, for example after a Stop-hook rewrite of the child's final text) is `ok:true` with `handoffLine:false`; the orchestrator, not the script, fails that hand-back.

#### 3.8.3 The pane copy (printed by `child`)

After `[result written: ...]` the child prints, as the last output of the pane and nothing else between the markers:

```
[result copy for the orchestrator follows: <n> bytes, base64]
<<<HERDR-RESULT-BEGIN-<nonce> encoding=base64 bytes=<n>>>>
<base64 of the UTF-8 result, 76 characters per line, LF line ends>
<<<HERDR-RESULT-END-<nonce> sha256=<hex of the same bytes>>>>
```

Constants: `PANE_COPY_MAX_BYTES = 16384`, `PANE_COPY_WIDTH = 76`. The nonce (12 hex characters, `crypto.randomBytes(6)`) is made by `run` and appears only in the job file, the `.exit` file and the markers, never in the pane's echoed command line. Two exported pure functions carry the format, so tests need no herdr: `encodePaneCopy(text, nonce)` returns the block; `decodePaneCopy(paneText, nonce)` returns `{ok:true, text}` or `{ok:false, reason}`. It tolerates CRLF, trailing spaces, a wrapped line (all whitespace is removed before decoding) and the PowerShell prompt after the END marker.

## 9. Revisions to `1.1.4-design.md` (none changes a decision)

1. 3.1 table: `show` / `set <key> <value>` / `validate` become `show | merge | set <key>=<value>... | validate` in the text format of `auto-handoff.mjs` (they are for people, so the "one JSON line" rule applies to `detect`, `open`, `close`, `run` only).
2. D7 and section 5 of the design: `mode` accepts `off` (human decision O1, 2026-11-12), and the design's text "No `off` value" is superseded.
3. `run` runs in the background, one call per agent (3.7); the design left the choice to the system engineer.
4. **AC-4 changed (round 1.1.6.l1, human decision 2026-11-12) for the architect's record.** Old: herdr behaviour is active only when `HERDR_ENV=1` and `herdr` is on PATH; otherwise no herdr command is attempted. New: active when the herdr server is running and `herdr` is on PATH, and either `HERDR_ENV=1` or exactly one `pane list` entry is this session's pane by `agent`, `cwd` and `agent_status` (3.3, step 4B); a missing or ambiguous match is inactive, never a guess; mode `off` wins. Consequences: with herdr installed, an inactive session still runs three read-only, silent calls (`--version`, `status server`, `pane list`); the claim "no herdr command is attempted" holds only when `herdr` is not on PATH. D8 (activation) is amended accordingly; ADR-0010's decision (the orchestrator drives panes through one script) is untouched.

5. **AC-10 amended (round 1.1.6.l2, human decision 2026-11-12), for the architect's and the run state's record.** Old: "driven with pane run/wait/read; the orchestrator gets the result from the pane". New: the pane is started with `pane run`; the result comes from a result file written by the `child` wrapper (main, design D4), with a pane copy read by `pane read` as the fallback (3.8); `pane wait-output` is not used. D4 is unchanged in direction and gains the fallback; ADR-0010 is untouched. `ok:true` of `run` means the text was copied; the hand-back check stays with the orchestrator (AC-11).
6. `run`'s JSON gains `source`, `line1`, `handoffLine`; `.exit` gains `bytes`, `sha256`, `paneCopy`, `nonce`, `writeError`; the job file of `run` gains `nonce`; `child` gains POSIX process-group kill, field validation and a never-throwing `finish()`.

## 10. Escalations

None for the architecture: the AC-10 change of section 9 item 5 keeps D4 and ADR-0010; it is recorded for the architect, not asked. Remaining unknowns (U10: whether the scrollback depth is configurable, and whether other herdr versions keep as much as the 500 to 1000 rows observed) only affect the 16 KiB cap, a constant. Two points are for `agent-manager` to report back rather than decide: the Copilot-output check of orchestrator text (section 6, last paragraph), and, for the architect's record, the AC-4/D8 change of section 9 item 4. U1 is decided by the human (fallback detection), not left open.
