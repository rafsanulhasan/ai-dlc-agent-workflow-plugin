Findings (syntax, stable 0.9.5 page unless noted):
- Tag v0.9.5 exists on github.com/herdrdev/herdr (tags page, dated 2026-10-14, marked immutable). [github.com/herdrdev/herdr/tags]
- pane split: `herdr pane split [<pane_id>|--pane ID|--current] --direction right|down [--ratio FLOAT] [--cwd PATH] [--env KEY=VALUE] [--right-click herdr|pane] [--focus] [--no-focus]`. Target is any pane_id given, so a pane in another tab is accepted as an id argument; the page does not say explicitly that cross-tab targeting works. New pane id at `.result.pane.pane_id`. [herdr.dev/tui/docs/cli-reference/; same syntax on preview page]
- pane rename: `herdr pane rename <pane_id> <label>|--clear`. No JSON shape documented. [stable cli-reference]
- pane run: `herdr pane run <pane_id> <command>`. Honors bracketed paste and submits text plus Enter atomically. No JSON shape documented. [stable cli-reference]
- pane close: `herdr pane close <pane_id>`. No JSON shape documented. [stable cli-reference]
- tab create: `herdr tab create [--workspace <workspace_id>] [--cwd PATH] [--label TEXT] [--env KEY=VALUE] [--focus] [--no-focus]`. JSON: `.result.tab.tab_id` and `.result.root_pane.pane_id`. [stable cli-reference; preview page agrees]
- pane read: `herdr pane read <pane_id> [--source visible|recent|recent-unwrapped|detection] [--lines N] [--format text|ansi] [--ansi] [--raw]`. Prints UTF-8 text, not JSON; ANSI stripped by default. [stable cli-reference]
- pane wait-output: `herdr pane wait-output <pane_id> (--match <text> | --regex <pattern>) [--source ...] [--lines N] [--timeout MS] [--raw]`. Success JSON, per one secondary fetch: `.result.pane_id`, `.result.matched_line`, `.result.read`. Not confirmed on the primary page, which gives no success shape. Errors: JSON on stderr, exit 1; usage errors exit 2. [stable cli-reference]
- Liveness: no dedicated ping. Closest are `herdr status`, `herdr status server`, `herdr status client`; output not described. `pane current [--pane ID|--current]` exists but no output shape. [stable cli-reference]
- `api snapshot` appears only in a list of routed commands on the preview page, with no syntax. Not usable as documented. [preview cli-reference]
- No-server behaviour: not documented. The only documented server-error behaviour is "CLI commands print a JSON error to stderr and exit with status 1" (stable docs, timeout/server error). The exit code and message for the no-server case are unknown. [stable cli-reference]
- Windows: README says Windows is supported and calls it "endpoint-protected Windows", with a separate windows-beta doc and a PowerShell installer (`irm https://herdr.dev/install.ps1 | iex`). [github.com/herdrdev/herdr README via WebFetch]
- Windows transport (named pipe, ConPTY): not stated in any fetched page. Unknown. The stable docs mention only a Windows-only setting for elevated-server access and no pipe or ConPTY detail. [stable cli-reference]
- pane run shell on Windows: a secondary llms-full.txt fetch says the default shell is `pwsh.exe` when on PATH, else `powershell.exe` (`terminal.default_shell`). Not on the stable CLI page, and not corroborated by a second independent source. Confidence Low. Whether a wrapper `node script.mjs ...` can run through `pane run` under that shell is not verified.
