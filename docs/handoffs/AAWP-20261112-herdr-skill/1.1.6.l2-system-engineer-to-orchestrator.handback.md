**Decision**
- **Main path: the result file.** `child` writes `<out>`, then `<out>.exit`. It gives exact bytes with no size limit, does not depend on herdr's terminal handling, and survives the pane being closed.
- **Fallback: a pane copy.** `child` always prints the result as a base64 block between per-run nonce markers, with a byte count and sha256, capped at 16 KiB raw. `run` reads it with `herdr pane read <id> --source recent-unwrapped --lines 100000`.
- **When the fallback runs:** only when the file channel failed to deliver a result the child had produced:
  - `.exit` says usable but `<out>` is missing, empty or its sha256 differs;
  - `.exit.writeError` is set;
  - `.exit` is absent or unparsable at timeout while the pane still exists.
- **When it does not run:** never when `.exit.usable === false`. The child's own verdict is not overridden.
- **AC-11 holds on both paths.** A pane result is accepted only if the byte count and sha256 both match. Otherwise the run returns `ok:false, stage:"run"` and the orchestrator stores a failed hand-back.
- **Why base64.** Plain text through `pane read` loses data (P4, P5, P7 below). Base64 survives it byte for byte (P8).
- **`wait-output` is not used.** It works, but it returns only a truncated tail, and the script already waits on the `.exit` file.
