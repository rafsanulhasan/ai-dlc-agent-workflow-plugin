**Decisions:**
- **D1. Who acts (ADR-0010):** the orchestrator drives every pane with one `Bash` call per action to `skills/herdr/scripts/herdr.mjs` (`detect`, `open`, `close`, `run`, `show`, `set`, `validate`). A hook can't do it: hook events don't carry the step code the pane label needs, and a hook can't replace a spawn. Every failure exits 0 with `ok:false`, so a pane never blocks the run (AC-9).
- **D2. Watch mode:** `open` before the spawn; `close` after the hand-back (subagent) or after shutdown (teammate). Nothing closes a pane because its agent is idle, so AC-7 and AC-8 hold by construction.
- **D3. Progress in a watch pane:** layer 1 reads the run folder (the brief, then each record to or from that agent, and elapsed time), so it works for subagents and teammates. Layer 2 tails the agent's transcript, found because the brief's record path is in its first message. Layer 2 is optional and depends on Q2.
- **D4. Run-in-pane mode:** a wrapper in the pane runs `claude -p --agent ai-dlc:<id> --output-format stream-json --verbose` (plus `--worktree` when the brief asks for isolation). It shows progress in the pane and writes the final result to a file atomically. The orchestrator copies that file verbatim as the hand-back, so the AC-11 flow is unchanged. Pane text is used only for diagnostics.
- **D5. Fallback:** if herdr can't be used before launch, the orchestrator spawns with the `Agent` tool and says so. If the run started but gave no usable result or timed out, a failed hand-back is stored, then the same step is spawned with the `Agent` tool (AC-11, AC-12).
- **D6. Agent teams (Mode 5):** a team stage always uses watch, whatever the setting, and the Routing Plan says so. Teammates can't be external `claude` processes.
- **D7. Setting:** `.ai-dlc/herdr.json` with `mode` (`watch`, the default, or `run-in-pane`) and `runTimeoutMinutes` (default 60), with variables `AI_DLC_HERDR_MODE` and `AI_DLC_HERDR_RUN_TIMEOUT_MINUTES`. It uses the same five precedence levels as auto-handoff. There is no workspace-trust gate (reason in design §5) and no separate configure skill.
- **D8. Activation:** `HERDR_ENV=1`, then `herdr` on PATH, then a check that the herdr server answers. Any miss means a silent no-op (AC-4).
- **D9. Scope:** only the orchestrator's own spawns get panes; nested spawns don't.
- **Files to change:** listed in design §6, each marked code or docs.
  - Code: new `skills/herdr/` (`SKILL.md`, `scripts/herdr.mjs`, `templates/herdr.schema.json`), `tools/claude-only-skills.json`, `tests/herdr/herdr-cli.test.mjs`.

**Known limits (in the design):** run-in-pane children can't answer permission prompts, have a cold prompt cache, and on Windows `claude` may be a `.cmd` shim, which changes how the wrapper starts it.
