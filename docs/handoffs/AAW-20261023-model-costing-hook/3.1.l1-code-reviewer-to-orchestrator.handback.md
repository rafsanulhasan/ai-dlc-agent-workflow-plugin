### New findings
- `update-model-metadata.mjs:476,485-488`: Warning. The Models API cap is 10 pages. If `has_more` is still true after page 10, the loop ends and the partial Map is returned as a complete answer. Because a non-null `apiLimits` makes `buildMetadata` ignore the old file (:366), every model past the cut loses its previous API figures and gets null, and the file flips. Fix: return null when the loop ends with `has_more` still true, which fits the all-or-nothing rule used for a failure on page 2. The test at `round4.test.mjs:184` asserts "keeps what it read" and must change to expect null.
- `update-model-metadata.mjs:476-478` with `settings.json:57,91`: Minor. The worst case is 10 pages at a 10 s timeout each, 100 s in the API call alone, against a 60 s hook `timeout`. The hook would be killed mid-write of the stamp or file. The tmp+rename write keeps the file safe, but no failure stamp is written. Fix: use one overall deadline (for example a single `AbortSignal.timeout` shared by all pages, 20 s or less), or lower the page cap.
- `update-model-metadata.mjs:478`: Minor. The `x-api-key` header is sent with default `redirect: "follow"`. I did not verify whether Node's fetch strips `x-api-key` on a cross-origin redirect (it strips `authorization`). The risk is a redirect from api.anthropic.com to another host. Fix: set `redirect: "error"` on this call.
- `update-model-metadata.mjs:62-63,537`: Minor. The back-off stamp has a predictable name in the shared OS temp directory. On Linux and macOS `writeFileSync` follows a symlink planted there by another local user and truncates the target, and a pre-created stamp can also silence refreshes. Fix: put the stamp in a per-user directory (for example under `os.homedir()` or `$XDG_CACHE_HOME`), or open it with `flag: "wx"` after an `lstat` check.
- `update-model-metadata.mjs:397-399`: Minor. `API_FIELDS` and `API_FIELDS_ORDER` hold the same three names in two constants, declared below `buildMetadata`, which uses one of them. Keep a single ordered list and use `includes` for validation. The doc comment at :467 is also one very long line.
- `update-model-metadata.mjs:477`: Question. Is `limit=1000` accepted by `GET /v1/models`? I did not check it against the API docs. If the maximum is lower, the API returns 400 and the fill is silently off (the :479 `!res.ok` path). Have `research-assistant` confirm the maximum, or lower the value to a documented one.
