## Models API (endpoint and fields, with sources)
- **Request:** `GET https://api.anthropic.com/v1/models?limit=1000`, following `has_more` / `last_id` → `&after_id=` for up to 10 pages. Headers are `x-api-key` and `anthropic-version: 2023-06-01`, with a 10 s timeout.
- **Fields used:** `id`, `max_input_tokens` and `max_tokens`, each "number or null"; there is no `context_window` field.
- **Sources:** https://platform.claude.com/docs/en/api/models/list and /api/models/retrieve; the claude-api skill's `shared/models.md`; and https://platform.claude.com/docs/en/api/errors (an invalid key returns 401 `authentication_error`).
- **Open conflict:** the docs' curl examples show `Authorization: Bearer` and `anthropic-version: 2026-10-21`. The skill and the errors page use `x-api-key` and `2023-06-01`. I used the second pair; it is not verified live.
- **What gets filled:** a field is filled only while it is null, never over a docs figure.
  - `maxInputTokens` ← `max_input_tokens`
  - `contextWindow` ← `max_input_tokens`, when no page states one
  - `maxOutputTokens` ← `max_tokens`, when no page states it
  - A model is matched by `id` or any alias. A value that is not a positive integer counts as null; the docs' example responses show 0 as a placeholder.
- **Recording:** each model now has `sources.modelsApi`, the list of fields filled from the API (`[]` when none).
- **Key handling:** with no key, no call is made. With a failed call (401, 500, throw, malformed body), the fields stay null and the refresh succeeds. The key goes only into the `x-api-key` header and appears in no message and no file.
- **Consumer rule:** "Do not show a null limit" is in SKILL.md "Reading the file", in the schema descriptions and in the init Phase 3 report.
