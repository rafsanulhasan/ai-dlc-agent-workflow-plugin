## Addendum (long-context threshold), one line per change
- **Field choice:** I kept it inside the rates object, as `longContextPricing.thresholdTokens`.
- **Schema:** `thresholdTokens` is now `tokenCount` (an integer or `null`), described as "`null` when the page names a long-context price but no threshold".
- **Parser:** a long-context row that states no number ("(for long prompts)" or "(long context)") gives `thresholdTokens: null`. A stated number is unchanged (Haiku 5.5: 100000).
- **Validator:** accepts a `null` threshold and rejects a missing threshold or 0.
- **Env override:** `AI_DLC_MODEL_METADATA_LONG_CONTEXT_THRESHOLD_TOKENS=<n>` sets one number for all models. The hook only records it, as the required top-level `longContextThresholdTokensOverride` (a positive integer, otherwise `null`; parsed by the new exported `thresholdOverride()`). A change reaches the file at the next refresh, or at once with `--force`.
- **Consumer rule,** written in the schema description and the skill's new **Long prompts** paragraph:
  - The rule applies to models whose `longContextPricing` is not null.
  - threshold = `longContextThresholdTokensOverride` ?? `longContextPricing.thresholdTokens`.
  - A request whose prompt (all input tokens, cache reads and writes included) is over the threshold pays `longContextPricing` for all its tokens; any other request pays `pricing`.
  - When both are null the cost is shown as unknown, never guessed.
  - The override has no effect on a model whose `longContextPricing` is null.
  - The "all its tokens" reading follows the pricing page's "Long context pricing" section.
- **Tests:** validator cases; `modelName` with no threshold; `thresholdOverride` parsing; `run` records the override and clears it to null; the hook passes the env through and ignores an invalid value. Both hook test helpers now clear the variable.
- **Memory:** one bullet in `project_model-metadata-hook.md`.
